# 知识文章写作

读取 [实施规范](../../知识库/00_知识库说明/知识库实施规范.md)。涉及句式、过渡或全文改写时读取 [技术中文写作规范](../../知识库/00_知识库说明/技术中文写作规范.md)，其中保留用户指定来源的短句正例。

先写一句主问题，再沿输入、现象、原因、机制、实现、失效和代价组织文章。用具体对象作主语，跟踪数据如何变化。段落增加信息，过渡指出尚未解决的问题。公式交代变量与单位，代码解释前提、执行和错误观察。

H2表达技术模型的大部分或方案家族，H3表达其中方法与子问题，H4表达必要实现细节。保留同题方案的比较。主归属已有完整解释时引用它，并写应用约束。

分别输出 `boundary_action`、`content_actions` 与 `title_review`；边界KEEP同样复读语言和审查标题。标题按实施规范表达核心概念或主问题，使用读者习惯的术语。按范围、结构、深度、实现、证据、写作、标题、信息架构、视觉逐项记录状态与依据。扫描候选需原文判断，工程运行状态按实际执行填写。

已认可的文风标杆见 [描边](../../知识库/11_NPR与风格化渲染/描边.md)。学习问题推进、因果解释、轻重与过渡，结合样例上下文、图注和验证表达；按当前问题设计自己的章节。跨主题文风与结构验证见 [Render Graph](../../知识库/13_引擎架构与资源系统/Render Graph.md)，编译器内部实现仍待深度补足，目标引擎运行状态另列。

重点问题展开推理，普通输入条件集中交代，补充限制在对应问题出现时说明。句段精修保留已通过的层级与代码，已有自然段落按实际问题微调。复读时检查信息量、解释轻重与语气，连接词表达真实因果。

交付正文、相关链接、证据状态和验收记录。尊重当前试点/迁移批准范围，必要引用同步不扩大成全库改写。
