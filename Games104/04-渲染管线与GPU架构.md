# 游戏引擎中的渲染实践：从光栅化到现代 GPU 架构

本笔记整理自 Games104《游戏引擎中的渲染实践》课程，聚焦现代游戏引擎渲染实践的全貌：从经典投影光栅化管线，到 GPU 并行架构、Mesh Shader 等现代硬件特性，再到引擎编辑器的工程实践。

---

## 一、 核心知识点与原理剖析

### 1. 渲染管线的演进与硬件驱动
*   **演进动力**：渲染技术随着硬件与游戏产业环境的变化快速优化迭代，现代引擎渲染实践高度依赖 GPU 架构。
*   **学习心态**：内容专业，听不懂不必慌张，逐步建立概念即可。

### 2. 经典渲染流程：投影与光栅化
*   **投影（Projection）**：从相机位置出发，将 3D 场景投影到屏幕空间，分为**正交投影**与**透视投影**。
*   **光栅化（Rasterization）**：将屏幕空间中的三角形转换为一个个像素，中间进行大量加减乘除运算。
*   **贴图采样**：计算时从 2D 贴图中取出对应位置的颜色，与其他结果合成最终画面。

### 3. GPU 并行架构（Graphics Processing Unit）
*   **职责**：GPU 承担大量并行图形计算，是渲染实践的算力核心。
*   **并行单元**：N 卡（NVIDIA）GPU 内部由大量小核（CUDA Core）组成，用于执行海量并行运算；GPU 每秒可完成几十上百个运算，远超 CPU。
*   **缓存（Cache）优化**：GPU 架构为 Cache 做了大量设计——如果每次计算的数据恰好都在缓存上，性能将大幅提升；数据缺失则需访问显存，成为性能瓶颈。
*   **性能分析术语**：现代图形优化中常用 "**ALu Bound**"（受算力单元限制）等黑话描述瓶颈，例如 `ALU Bound` 即计算单元满载、等待数据或指令。

### 4. 场景对象与渲染数据组织
*   **Mesh（网格）与材质**：每个物体由 Mesh 组成，每个 Mesh 上可挂多种材质（如布料、金属），材质决定表面的视觉属性。
*   **顶点数据（Vertex Data）**：Mesh 由大量顶点构成，顶点上携带位置、法线、UV 等数据，顶点数据的定义方式是引擎开发的基础。
*   **PBR（Physically Based Rendering）**：基于物理的渲染材质模型，将在后续课程详细讲解。
*   **纹理（Texture）**：通过纹理贴图表达表面的细节与材质外观。

### 5. 场景管理：坐标系、可见性与碰撞
*   **坐标变换**：物体在自身局部坐标系中制作，再变换到世界坐标系参与渲染。
*   **渲染数据去重**：同一份 Mesh/Shader 只需存储一份，按材质切换渲染状态即可复用。
*   **可见性剔除（Culling）**：通过空间划分（如房间结构、凸包 CONVEX HULL）提前判断哪些物体可见，避免把大量不可见物体都绘制出来——"把那么多房间的东西都画了"是巨大的浪费。
*   **碰撞体**：物理系统中常用凸包（Convex Hull）作为碰撞近似形状。

### 6. 现代 GPU 特性：Mesh Shader
*   **背景**：传统管线只能按物体（Object）做裁剪，粒度较粗。
*   **Mesh Shader / Amplification Shader**：现代硬件提供的更细粒度处理能力，可以对单个物体内部（如一只手的一部分三角形）做裁剪剔除，在相机条件下直接丢弃不需要绘制的部分，效率极高。

### 7. 引擎编辑器实践
*   **编辑器与游戏模式**：编辑器有编辑界面与游戏模式之分。编辑模式下可操作场景对象（如 MOTO 移动物体）；进入游戏模式后相机才起作用。
*   **模式切换**：按 Alt 等快捷键可回到编辑模式，释放鼠标。
*   **工程组织**：Shader 通常单独放在一个工程中管理；现代引擎工程（如示例项目）将 ECS 等核心机制先行实现，再逐步扩展粒子系统、植被（草）等要素。
*   **管线学习**：经典 Pipeline 仍需学习理解——即便使用现代可编程管线，理解经典流程有助于掌握数值变化与原理。

## 二、 重点术语与概念解析

### 1. 投影（Projection）
*   **定义**：将 3D 坐标映射到 2D 屏幕空间的过程，分正交投影与透视投影。

### 2. 光栅化（Rasterization）
*   **定义**：将几何图元（三角形）转换为像素的过程，是实时渲染的核心步骤。

### 3. GPU / CUDA Core
*   **定义**：图形处理器；NVIDIA GPU 内部的小型并行计算核心，负责海量并行运算。

### 4. Cache（缓存）
*   **定义**：位于 CPU/GPU 与主存之间的高速存储，缓存命中与否直接影响计算性能。

### 5. Mesh / Vertex / Texture
*   **定义**：网格（几何体）、顶点（网格的基本数据点）、纹理（表面贴图）。

### 6. PBR（Physically Based Rendering）
*   **定义**：基于物理的渲染，用能量守恒等物理规律模拟材质与光的交互。

### 7. 凸包（Convex Hull）
*   **定义**：包含几何体所有点的最小凸多面体，常用于碰撞检测与可见性判断。

### 8. Mesh Shader / Amplification Shader
*   **定义**：新一代 GPU 可编程着色阶段，支持在物体内部进行细粒度几何处理与剔除。

## 三、 工程经验与避坑指南

### 1. 缓存友好的数据处理
*   **经验**：让每次计算所需数据尽量命中缓存（Cache），是图形性能优化的核心原则。

### 2. 减少无效绘制
*   **经验**：利用空间划分与剔除技术，避免绘制大量不可见物体；现代硬件下可借助 Mesh Shader 做细粒度裁剪，显著提升大场景渲染效率。

### 3. 顶点数据与资源复用
*   **经验**：合理定义顶点数据结构，重复资源（Mesh/Shader）只存一份，按材质切换渲染状态，减少显存与带宽压力。

### 4. 编辑器工作流
*   **经验**：熟练掌握编辑模式/游戏模式切换，理解编辑器作为引擎工具层的价值——它让美术、策划直接参与场景搭建，是引擎工程化的重要一环。
