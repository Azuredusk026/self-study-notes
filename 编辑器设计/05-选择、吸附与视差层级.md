# 地图选择、吸附、视差层级与编辑器阶段总结

## 一、核心知识点与原理剖析

### 1. 模型选择的课堂更新

课堂开头评价了当时新发布的 Kimi 模型，并与 Claude、GPT、Grok 等比较：

- 老师的个人实测认为新模型代码质量和长上下文表现很强，并具备原生多模态。
- 缺点是价格对学生不低、输出速度慢；同一任务可能比其他模型耗时更长。
- 不建议购买长期包年，因为模型迭代速度快；先按月验证更稳妥。
- 课堂继续使用已有工具，避免为了新模型中断项目。

这些结论只代表课堂当时版本和个人工作负载，实际选择应重新测试。

### 2. 地图对象选择逻辑修正

原实现按 Collider 判断选中，导致图片很大但 Collider 较小时，点击图片边缘无法选中。

正确做法是区分：

- **渲染边界**：SpriteRenderer、MeshRenderer 或实际图形包围盒。
- **选择边界**：通常以渲染边界为基础，可增加少量扩展系数。
- **物理边界**：Collider，仅用于玩法碰撞。

选择应优先按实际 Sprite/Renderer 包围盒，而不是 Collider。因为在《空洞骑士》等游戏中，Collider 只需保证玩法手感，常与美术轮廓不同。

### 3. 拖拽吸附设计

课堂计划增加吸附开关，但第一次把“边缘吸附”误实现成了“网格吸附”。这说明需求必须明确。

#### 3.1 网格吸附

- 位置量化到固定格子。
- 适合 Tilemap 或体素编辑。
- 本项目为自由摆放 Sprite，不应默认强制网格化。

#### 3.2 边缘吸附

- 拖动物体靠近其他对象边缘时，对齐左、右、上、下边界或中心线。
- 应设置最大吸附距离。
- 工具栏提供开关，用户可以临时关闭。
- 视觉上可显示参考线或高亮被吸附边缘。

让 AI 自行选择吸附定义导致了错误方案，最终必须由人明确决策。

### 4. 框选与多选移动

- 编辑器需要空白区域拖拽框选多个对象。
- 框选结果进入一个选择集合。
- 拖动任一已选对象时，整个集合保持相对位置一起移动。
- 多对象移动应形成一个 Transaction，Undo 时整体回到原位。
- 框选不能与视口平移、单对象拉伸和 UI 点击冲突。

### 5. 拆解类银河城场景的视觉层次

课堂通过实际游戏画面分析横版场景：

- 后景并非单张背景，可能包含多个远近层。
- 世界/地块层承载玩家、碰撞和主要建筑。
- 前景覆盖在玩家前面，也可有多个层。
- 不同层随相机移动速度不同，产生视差。
- 某些层还需要模糊、雾化、颜色等滤镜。

概念结构：

```text
前景层 N（最靠近镜头）
...
前景层 1
世界 / 地块层（玩家真实交互，Parallax = 1）
后景层 1
...
后景层 N（最远）
```

### 6. 视差滚动原理

视差通过让各层相对相机以不同系数移动实现。简化公式：

```text
layerOffset = cameraPosition × parallaxFactor
```

- 世界层系数通常为 1，和实际世界同步。
- 远景系数较小，看起来移动慢、距离远。
- 前景可使用更大的相对运动或与相机接近的系数，营造近物快速掠过。
- 系数的具体方向和基准取决于实现是移动层还是修改采样坐标，必须用运行画面验证。

### 7. 世界层级数据与 UI 设计

每张地图拥有完整层级数据：

- 前景大类，可添加多个子层。
- 世界层。
- 地块层；课堂后续倾向把世界与地块视为主要交互平面。
- 后景大类，可添加多个子层。

每个前/后景子层包含：

- 名称和排序。
- Parallax Factor。
- Filter 类型与参数，如 Blur、Fog、Color Tint。
- 该层对象列表。

UI 设计：

- 左侧显示层级列表，上下顺序对应前后绘制关系。
- 通过加号添加前景或后景子层。
- 选中层后，右侧 Inspector 编辑视差系数和滤镜。
- 工具按钮切换当前编辑层。
- 非当前层应变暗且不能被选中，防止误编辑。
- 每张地图保存自己的完整层级配置。
- 旧地图数据迁移时，所有对象默认放入地块/世界交互层。

### 8. 移除重复的对象父子层级

- 前一课新增过对象父子层级视图。
- 引入世界层级后，继续保留父子层级会让左侧 UI 和概念过于复杂。
- 对当前自由 Sprite 地图，课程判断父子关系不是核心需求，于是移除对象层级和对应视图，只保留世界层级。
- 这属于主动删功能：降低用户理解成本，也减少 Transform、保存和撤销复杂度。

### 9. 四类资源配置隔离

前景、后景、世界和地块并不应该共享完全相同的可用资源。课堂补充：

- 四个大层级各自使用独立的 ScriptableObject 配置。
- 资源面板随当前层切换，只显示该层允许的 Prefab/地图单元。
- 例如前景只显示雾、藤蔓、遮挡物；后景显示远山、建筑；地块显示平台；世界层显示 NPC、机关等。
- 这样能避免把玩家碰撞平台误放到纯背景层。

### 10. 层级功能的运行验收

课堂发现并修复/记录：

- Fog 滤镜结果不正确，Blur 尚可。
- Parallax 参数一开始看似不可编辑，后确认交互位置。
- 切换层后仍能选中其他层对象，应限制选择。
- Player 排序错误，显示在后景之后。
- 前景跟随相机过强，视觉不自然。
- 地图较小时相机几乎不移动，视差效果不明显；需要扩大地图或手动移动相机验证。
- 非当前层应变暗，当前层需要清晰选中反馈。
- 部分 AI 生成素材存在紫边、抠图不干净和层次不匹配，只能作为占位资源。

### 11. 2D 跳跃手感优化

课堂同时调整了 Player 跳跃：

- 纯物理冲量的跳跃不易得到目标手感。
- 需要变量控制：最大上升时间、上升速度/曲线、松键后的快速下落、最大高度和落地状态。
- 预期是按住时继续上升，提前松开时更快下降，形成可变跳高。
- 初版出现只能跳很低、必须连续按键、松键不快速下降等 Bug，经过多次修改默认值与逻辑后才达到可接受效果。
- 运行时体验必须实际操作验收，单元测试很难完全替代手感测试。

### 12. 编辑器后续可扩展系统

当前主框架完成后，还可继续：

- 移动平台和动态机关。
- NPC 与对话。
- 支线任务与任务编辑器。
- 道具获取条件。
- 序列帧、粒子和动态背景。
- 更多滤镜、光源和多层素材。
- 更完整的数据校验、错误提示与运行预览。

这些都可以继续沿用统一序列化、Drawer、Transaction、层级和编辑运行桥接。

## 二、重点术语与概念解析

- **Hit Test（命中测试）**：判断鼠标点击命中了哪个可编辑对象。
- **Renderer Bounds**：渲染器覆盖的世界空间包围盒，可作为选择范围。
- **Grid Snapping（网格吸附）**：把位置限制到固定网格点。
- **Edge Snapping（边缘吸附）**：把对象边缘或中心自动对齐到附近对象。
- **Marquee Selection（框选）**：拖出矩形，一次选择区域内多个对象。
- **Parallax（视差）**：不同深度层随相机以不同速度移动产生的空间感。
- **Foreground / Background**：位于玩家前方的前景与玩家后方的后景。
- **Filter（滤镜）**：对某层应用模糊、雾化、染色等统一视觉处理。
- **ScriptableObject**：Unity 中存储共享配置和资源引用的资产类型。
- **Data Migration（数据迁移）**：数据结构升级后把旧存档转换为新格式。

## 三、工程经验与避坑指南

### 1. 需求词语必须消除歧义

- “吸附”可以指网格、边缘、中心、角点或磁性范围。
- 不明确时，AI 会做一个合理但错误的决策。关键交互不能完全让模型自主选择。
- 计划中的每个用户体验决策都应确认。

### 2. 选择、渲染和物理要解耦

- 选择范围服务编辑体验。
- Renderer 服务视觉。
- Collider 服务玩法。
- 三者完全共用会导致图片点不到、碰撞太精细或选择范围怪异。

### 3. 当前层之外应禁止交互

- 仅改变颜色不够，非当前层必须在命中测试中过滤。
- 否则前景遮住地块时无法选中目标，编辑体验会迅速崩坏。

### 4. 数据结构升级要兼容旧地图

- 从单层升级为多层时必须定义旧对象归属。
- 默认迁移到地块/世界层最安全，因为它保留原来的交互和碰撞语义。
- 版本号、迁移日志和失败回滚应在正式项目中补充。

### 5. 主动删除重复功能

- 对象父子层级与世界视觉层级同时存在会让非专业用户混淆。
- 若父子关系没有明确玩法或编辑需求，删除比保留“以后可能有用”更好。

### 6. AI Coding 的长期维护

- 编辑器代码从 Demo 扩大时，早期架构不足会快速放大混乱和 Bug。
- 应主动让 AI 输出模块图和程序集依赖图，由人类审查后重构。
- Assembly Definition 是限制依赖的天然框架边界，必须保持单向、清晰。
- 归档项目需求、设计和用户体验原则，让新会话预热后立即知道项目目标。

### 7. 阶段结论

- 程序实现大量交给 AI 后，课程最重要的能力仍是**编辑体验设计**：用户如何选中、拖拽、连接、切层、撤销和运行。
- 当前编辑器的主框架已较完整，但素材、美术、滤镜、错误处理和商用品质仍需长期打磨。
- 后续功能迭代应由学生沿用本课程的工作流独立完成。
