# 游戏引擎架构分层：资源层、功能层与工具层

本笔记整理自 Games104《游戏引擎架构分层》课程，聚焦现代游戏引擎的层次化架构设计思想：资源层、功能层、工具层的职责划分，以及"分层思考优先于算法实现"的核心方法论。

---

## 一、 核心知识点与原理剖析

### 1. 游戏引擎的三大层次
*   **资源层（Resource Layer）**：负责游戏资产的加载、存储与管理。类比记忆朋友的住址——引擎需要高效地存取网格、贴图、音频等资源。
*   **功能层（Functional Layer）**：提供具体的引擎功能模块，如渲染、物理、动画、逻辑模拟等。
*   **工具层（Tool Layer）**：面向开发者的编辑工具，如场景编辑器、材质编辑器、资源浏览器，使美术与策划能直接参与游戏制作。

### 2. Tick 机制：游戏世界的"永动机"
*   **定义**：游戏引擎每隔一个固定时间间隔，把整个游戏世界往前推进一小格，这一过程称为 **Tick**。
*   **类比**：Tick 机制就像一个永动机——逻辑层在每个 Tick 中完成输入处理、物理更新、逻辑更新、渲染提交等步骤，形成稳定的游戏循环。
*   **意义**：Tick 是逻辑层（对世界的模拟）的核心节拍，决定了游戏逻辑的更新频率。

### 3. 核心层的数学与数据结构基础
*   **数学库**：向量、矩阵运算是核心层的基础（如 SIMD 指令直接扩展 CPU 的向量并行运算能力）。
*   **数据结构的取舍**：核心层不止于数学，还需要链表、数组等基础数据结构。例如一开始分配 100 个元素后，如何高效管理内存、避免频繁扩容，是引擎效率的关键。
*   **内存管理**：内存管理是操作系统最重要的工具之一，引擎层在管理数据时需要遵循简单而高效的规则（如内存池、缓存友好布局）。

### 4. 引擎的两大组成块
*   **对世界的模拟**：包括逻辑、物理、动画等所有让世界"活起来"的模块。
*   **工具链（Tool Chain）**：支撑内容生产的编辑器与工具。
*   **核心工程思想**：当面对任何需求时，首先要想清楚"我做的事情应该属于哪一层"，而不是急于实现算法——这是游戏引擎架构中最重要的分层思维。

### 5. ECS 架构示例（Pilot 项目）
*   **案例**：Pilot 项目将全套 ECS（Entity-Component-System，实体-组件-系统）架构融入引擎，用庖丁解牛的方式把 ECS 拆解为清晰的结构。
*   **价值**：ECS 作为现代游戏引擎（尤其是数据驱动引擎）的核心架构模式，是理解引擎数据组织的关键入口。

## 二、 重点术语与概念解析

### 1. Tick
*   **定义**：引擎的固定频率逻辑更新步进，每次 Tick 将世界状态推进一个时间片。

### 2. SIMD（Single Instruction Multiple Data）
*   **定义**：单指令多数据流，CPU 的一条指令同时对多个数据进行运算，用于加速向量/矩阵等数学运算。
*   **应用**：引擎数学库通过 SIMD 指令实现高效的并行向量运算。

### 3. ECS（Entity-Component-System）
*   **定义**：实体-组件-系统架构，一种以数据为中心的游戏对象组织方式，将对象拆分为实体（ID）、组件（数据）与系统（逻辑）。

### 4. 资源层 / 功能层 / 工具层
*   **定义**：引擎的三大横向分层，分别负责资源管理、功能实现与开发工具，层间单向依赖、高内聚低耦合。

## 三、 工程经验与避坑指南

### 1. 分层思维优先于算法实现
*   **经验**：做任何引擎需求时，先判断该功能属于哪一层，再考虑具体算法。急急忙忙写算法而忽略分层，会导致架构混乱、难以维护。
*   **目标**：掌握分层思想后，"基本够你混到初级架构师"。

### 2. 学习路径建议
*   **循序渐进**：引擎开发应从核心层（数学、数据结构、内存管理）出发，从上到下逐步构建，最终封装成完整的引擎框架。
*   **参考课程**：闫令琪老师的 GAMES101/104 课程对向量、矩阵、投影等概念讲解清晰，是学习引擎数学的优质资源。

### 3. 项目实践
*   **动手验证**：用 3D 建模软件（如 3ds Max）制作小角色并导入引擎，亲手体验资源层到功能层的流转，是理解引擎架构最直观的方式。
