# 动画压缩

同一段动作删掉一半关键帧，躯干可能看不出变化，手指却离开了握持点。局部旋转的微小误差会沿骨骼层级放大，所以动画压缩先定义哪些部位容许多大误差，再决定删轨道、删关键帧还是降低位宽。包体之外，解码速度和随机访问也决定它能否用于运行时。

## 动画数据为什么大

假设 100 个 Joint，每个 Joint 每帧保存 Translation、Quaternion 和 Scale 共 10 个 Float，30 FPS、10 秒动画的原始数据约为：

$$
100\times 300\times 10\times 4\text{ bytes}\approx 1.2\text{ MB}
$$

单个 Clip 看似不大，但角色、武器、表情、过场和多语言口型叠加后会迅速增长。运行时还关心解压后的内存访问和 Cache，不只是包体。

## Track 与 Key Reduction

第一步是删除恒定 Track：

- 没有变化的 Scale 不必逐帧保存；
- 固定 Translation 可只存一个值；
- 完全不动的 Joint 可以使用 Reference Pose。

Key Reduction 会尝试删除中间 Key，再用相邻 Key 插值。若重建结果在容许误差内，就保留较少 Key。

一种贪心关键帧抽取从保留的关键帧向前尝试扩大插值区间，在重建误差超过阈值前删除中间 Key。误差第一次超限时，保留前一个安全位置，再从新 Key 继续。它得到非均匀 Key Time，变化平缓处稀疏，快速动作处密集。

误差不能只看单个 Joint 的局部角度。手指根部很小的旋转，在长层级末端可能产生明显位置误差。更可靠的压缩器会评估 End Effector 或整条 Skeleton 的 Object Space 误差。

## Quantization

动画值可映射到有限位宽。Translation 在 Clip 或 Segment 的 Min/Max 范围内量化；Quaternion 可省略最大绝对值分量，用其余三个分量和符号重建。

分段量化比整段 Clip 使用一个范围更精确，但每段需要额外 Header。压缩是在精度、随机访问、解码速度和元数据之间取舍。

Quaternion 还要统一半球。$q$ 与 $-q$ 表示同一旋转，但直接插值会走长路径。编码前应保证相邻 Key 的 Dot Product 非负，必要时翻转符号。

## Sample Rate 与 Variable Rate

固定帧率采样访问简单，也便于 SIMD 解码。Variable Key Time 能删除更多冗余帧，却需要查找相邻 Key。

动作快慢不同，不应全库使用相同压缩误差。手部交互、武器轨迹和面部口型通常比远景 NPC Idle 更敏感。压缩配置应按动画类型、角色 LOD 和目标平台分级。

## 流送与运行时解压

长过场或大量动作不一定全部常驻。Clip 可按 Segment 流送，只保留当前和即将播放区间。

运行时关注：

- 解压是否产生临时分配；
- Joint 数据是否按遍历顺序连续；
- 多角色是否重复解压相同 Clip 时间；
- Job/Task 粒度是否足够大；
- 动画 LOD 是否降低更新频率、骨骼数和面部通道。

降更新频率后可以在渲染帧间插值 Pose，但快速动作和 Root Motion 不能简单跳帧。

## 平移轨道解码

轨道将每个分量编码为 16 位归一化整数，输入是轨道范围与量化值，输出使用与原轨道相同的长度单位。

```cpp
Vec3 DecodeTranslation(U16Vec3 quantized, Vec3 minimum, Vec3 maximum)
{
    Vec3 normalized = Vec3(quantized) / 65535.0f;
    Vec3 extent = maximum - minimum;
    return minimum + normalized * extent;
}
```

常量轨道单独编码。一个轴的最大舍入误差约为范围除以 `2 * 65535`，但骨骼层级会放大旋转误差，因此运行验收仍需看末端位置和根运动。分段量化缩小范围，也增加元数据和解码寻址成本。

## 验证方法

- 比较压缩前后的手脚末端、根运动和关节旋转误差。
- 分别测量解码 CPU 时间、临时分配、Clip 包体和运行内存。
- 固定帧率与变帧率路径用同一播放时刻对比。
