# 动画压缩、面部、布料与毛发

角色动画的成本不只在蒙皮。Clip 数据量、解压访问、面部通道、布料和毛发的二级运动都会影响内存、CPU、GPU 与制作流程。

## 动画数据为什么大

假设 100 个 Joint，每个 Joint 每帧保存 Translation、Quaternion 和 Scale 共 10 个 Float，30 FPS、10 秒动画的原始数据约为：

$$
100\times 300\times 10\times 4\text{ bytes}\approx 1.2\text{ MB}
$$

单个 Clip 看似不大，但角色、武器、表情、过场和多语言口型叠加后会迅速增长。运行时还关心解压后的内存访问和 Cache，不只是包体。

## Track 与 Key Reduction

第一步是删除恒定 Track：

- 没有变化的 Scale 不必逐帧保存；
- 固定 Translation 可只存一个值；
- 完全不动的 Joint 可以使用 Reference Pose。

Key Reduction 会尝试删除中间 Key，再用相邻 Key 插值。若重建结果在容许误差内，就保留较少 Key。

Merlin 类关键帧抽取从保留的关键帧向前尝试扩大插值区间，在重建误差超过阈值前删除中间 Key。误差第一次超限时，保留前一个安全位置，再从新 Key 继续。它得到非均匀 Key Time，变化平缓处稀疏，快速动作处密集。

误差不能只看单个 Joint 的局部角度。手指根部很小的旋转，在长层级末端可能产生明显位置误差。更可靠的压缩器会评估 End Effector 或整条 Skeleton 的 Object Space 误差。

## Quantization

动画值可映射到有限位宽。Translation 在 Clip 或 Segment 的 Min/Max 范围内量化；Quaternion 可省略最大绝对值分量，用其余三个分量和符号重建。

分段量化比整段 Clip 使用一个范围更精确，但每段需要额外 Header。压缩是在精度、随机访问、解码速度和元数据之间取舍。

Quaternion 还要统一半球。$q$ 与 $-q$ 表示同一旋转，但直接插值会走长路径。编码前应保证相邻 Key 的 Dot Product 非负，必要时翻转符号。

## Sample Rate 与 Variable Rate

固定帧率采样访问简单，也便于 SIMD 解码。Variable Key Time 能删除更多冗余帧，却需要查找相邻 Key。

动作快慢不同，不应全库使用相同压缩误差。手部交互、武器轨迹和面部口型通常比远景 NPC Idle 更敏感。压缩配置应按动画类型、角色 LOD 和目标平台分级。

## 流送与运行时解压

长过场或大量动作不一定全部常驻。Clip 可按 Segment 流送，只保留当前和即将播放区间。

运行时关注：

- 解压是否产生临时分配；
- Joint 数据是否按遍历顺序连续；
- 多角色是否重复解压相同 Clip 时间；
- Job/Task 粒度是否足够大；
- 动画 LOD 是否降低更新频率、骨骼数和面部通道。

降更新频率后可以在渲染帧间插值 Pose，但快速动作和 Root Motion 不能简单跳帧。

## Blendshape 与 Morph Target

Blendshape 保存顶点相对基础 Mesh 的 Position/Normal/Tangent Delta。运行时按权重累加：

$$
\mathbf{p}'=\mathbf{p}_0+\sum_i w_i\Delta\mathbf{p}_i
$$

它适合面部表情、口型和肌肉修形。目标数多时，逐目标读取完整稀疏 Delta 很浪费。可只保存受影响顶点、限制同时激活目标数，或在 Compute 中预合并结果。

Blendshape 强依赖顶点拓扑和顺序。重新拓扑、合并 Mesh 或改变导出设置后，旧目标通常无法直接复用。

## 面部 Rig

面部常组合使用：

- Joint 驱动眼球、下颌、眉毛和较大区域；
- Blendshape 驱动唇形、皱褶和非线性修形；
- Corrective Shape 修复多个动作组合后的塌陷；
- Wrinkle/Flow Map 根据表情权重改变皮肤细节；
- Look-at、眨眼和微表情由程序层控制。

FACS 可作为表情动作单元的共同语言，但项目仍需要自己的命名、范围和组合约束。直接让几十个控制器自由相加会出现穿插和不自然极值。

音素到 Viseme 的映射只给出嘴形基础。自然口型还依赖协同发音、语速、情绪、下颌和面颊联动。自动生成结果需要可编辑曲线和人工修正入口。

Live2D 用分层二维纹理网格、参数变形和遮罩组织角色表情与姿态。运行时根据角度、眼睛、嘴形等参数插值顶点变形，并按层级和裁剪关系合成。它保留二维原画风格，但仍需要统一参数命名、变形范围、绘制顺序和移动端纹理预算。

## 布料的表示层级

布料可以按成本分为：

1. 烘焙在 Clip 中的辅助骨骼；
2. Spring/Dynamic Bone；
3. 低模 Physical Mesh 的实时 Cloth；
4. 高质量离线模拟或缓存播放。

渲染网格通常太密，不能直接作为模拟网格。Physical Mesh 用更少粒子求解，再通过 Skin/Wrap 映射驱动渲染网格。

## 从质点弹簧到 PBD

质点弹簧模型对粒子施加重力、风、阻尼和弹簧力。显式积分在刚性高、步长大时容易爆炸，需要小 Time Step。

Position Based Dynamics（PBD）直接迭代修正位置，使距离、弯曲、碰撞等约束接近满足。其稳定、可控，适合实时布料。典型帧流程：

1. 外力预测位置；
2. 构建碰撞约束；
3. 多次迭代 Stretch/Bend/Collision；
4. 由位置变化更新速度；
5. 把模拟网格结果映射到渲染网格。

更多 Substep 和 Iteration 通常更稳定，但成本线性增长。普通 PBD 的刚度还会随迭代数和步长变化；XPBD 用 Compliance 改善参数与步长的依赖。

## 碰撞与穿插

角色碰撞常用 Capsule/Sphere 近似身体。碰撞体过小会露皮肤，过大则让衣服悬空。

Self Collision 成本高，尤其多层衣物。常见工程手段包括：

- 降低模拟网格密度；
- 增加 Substep 并限制最大速度；
- 使用层级、厚度和碰撞组；
- 对身体使用 SDF；
- 在不重要区域关闭自碰撞；
- 用 Animation/Corrective Shape 掩盖极端姿势。

Teleport、低帧率和角色瞬移必须重置或重新初始化模拟，否则历史速度会把布料甩飞。

## 毛发：Cards、Strands 与 Guides

Hair Cards 用少量带 Alpha 的面片表示发束。主要成本在 Overdraw、排序、阴影和各向异性材质。二级运动可用少量 Joint 或 Spring Chain。

Strand/Groom 直接表示大量发丝，通常先模拟少量 Guide Hair，再插值 Follower。还需要分 Cluster 做剔除、LOD 和渲染。

毛发模拟要处理长度、弯曲、碰撞和阻尼约束。近景可保留更多 Guide 与发丝，远景逐步降低密度，最终切到 Cards 或体积近似。几何 LOD、阴影 LOD 和材质 LOD需要一起变化。

## 验证方法

- 对压缩前后计算 Joint Rotation、End Effector Position 和 Root Motion 误差。
- 在不同角色 LOD 记录 Clip 内存、解压时间、Bone Count 和 Skinning 时间。
- 对面部检查极值、组合表情、口型同步和拓扑版本。
- 用低帧率、暂停恢复、Teleport 和碰撞极限测试布料。
- 分开统计 Cloth Simulation、Skinning、Hair Simulation、Hair Rendering 和 Shadow 成本。
