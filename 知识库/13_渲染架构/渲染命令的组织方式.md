# 渲染命令的组织方式

渲染任务需要把资源访问和绘制操作转换为可提交的 GPU 命令。采用 Render Graph 时，图负责从依赖编译执行计划；Render Pass 表达附件使用范围，Command Buffer 承载操作记录。这些概念各自处理不同层次的组织问题。

## 阅读路线

从单次绘制入手时，先理解 Command Buffer 的记录与提交，再读附件及同步。理解跨效果调度时，进入 Render Graph，把逻辑资源、依赖和实际执行连接起来。

资源回收需要参考 GPU 完成状态，不能由 CPU 已结束记录直接推出。生命周期专篇负责这一判断；图编译和命令录制分别说明它们保存哪些依赖信息。

例如一个阴影通道写深度D、主光照通道读D并写颜色C，图先保存D的生产消费关系；编译后将阴影排在光照前，给D生成写后读依赖，并决定它的物理存储寿命。各通道在Render Pass中声明附件的加载、存储和布局，随后记录为Command Buffer，由协调者按依赖提交。最后一次读D的命令已经录完时，GPU可能尚未执行它，因此物理资源回收仍等完成值。依次查看逻辑版本、附件状态、命令记录与完成条件，能将漏声明、错误清理、提交逆序和过早回收四类问题分开。
