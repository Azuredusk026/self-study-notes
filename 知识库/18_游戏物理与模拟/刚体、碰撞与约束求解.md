# 刚体、碰撞与约束求解

实时物理不是逐帧“算出真实世界”。它在固定时间步内完成积分、碰撞检测和约束求解，并接受可控误差。稳定性、可重复性和玩法手感通常比绝对物理精度更重要。

## 刚体状态与积分

刚体至少保存位置、旋转、线速度、角速度、质量和惯性。力改变速度，速度再改变位置。半隐式欧拉先更新速度再更新位置：

$$
v_{t+1}=v_t+a\Delta t,\qquad x_{t+1}=x_t+v_{t+1}\Delta t
$$

它比显式欧拉更适合常见实时系统，但时间步过大仍会增加能量误差。固定 Delta Time 能让求解行为更稳定。渲染帧与物理帧不同步时，表现层可以对前后两个物理状态插值。

### 为什么半隐式比显式稳定

显式欧拉用当前速度推进位置，在弹簧等回复力系统中每步都向系统注入能量，振荡幅度越来越大直到发散。半隐式欧拉先用力更新速度、再用新速度更新位置，这个次序差异让它成为辛积分器——能量误差有界震荡而不累积，长时间模拟不会自发爆炸。

这不是精度更高的近似，而是误差的**性质**不同：半隐式的误差表现为相位漂移（周期略有偏差），显式的误差表现为能量增长（振幅失控）。游戏物理对前者宽容得多。

### 固定时间步与累加器

渲染帧率波动时，物理时间步必须固定，否则同样的输入在不同帧率下产生不同结果。标准做法是累加器模式：把渲染帧的真实耗时存入累加器，每次循环按固定步长消费，余量留给插值：

```csharp
accumulator += deltaTime;
while (accumulator >= fixedStep)
{
    PhysicsStep(fixedStep);
    accumulator -= fixedStep;
}
// 渲染时按 accumulator / fixedStep 在两个物理状态间插值
```

要防“死亡螺旋”：物理耗时超过固定步长时，累加器持续增长、每帧要跑的物理步越来越多、帧时间进一步恶化。做法是设单帧最大物理步数，超出部分丢弃（表现为游戏变慢而不是卡死）。

Dynamic 刚体由力和约束驱动；Kinematic 刚体由游戏逻辑给出目标运动，但仍可参与接触；Static 几何不移动。直接修改 Dynamic 物体 Transform 会绕过速度和连续碰撞语义，应明确使用 Teleport 还是物理驱动。

## 碰撞检测

Broad Phase 用 AABB、Sweep and Prune、Grid 或 BVH 快速找出可能相交的物体对。Narrow Phase 再对球、盒、胶囊、凸包或三角网格求准确接触。

离散检测只比较两个时间点，快速小物体可能穿过薄墙。连续碰撞检测会计算 Swept Volume 或碰撞时间 TOI，但成本更高，也不能自动解决所有高速旋转和复杂网格问题。常见策略是只给关键高速物体启用 CCD，并限制最大速度和时间步。

### Narrow Phase 的两类主力算法

凸体相交检测有两个常用框架。**分离轴测试**（SAT）枚举候选分离轴——两个凸体的面法线与边方向叉积——只要找到一条轴上两投影不重叠，两体必不相交。它概念直接，适合盒、胶囊等简单形状，轴数量随形状复杂度增长。

**GJK** 用闵可夫斯基差把“两凸体是否相交”变成“原点是否在差集内”，通过支撑函数迭代逼近，不需要枚举特征。距离不为零时还能给出最近点对；已穿透时需要 EPA 等后续算法求穿透深度与方向。实践中两者常配合：GJK 判相交，SAT 或 EPA 求接触信息。

接触流形通常包含法线、穿透深度和若干接触点。点太少会不稳定，点太多会增加求解成本。持久化接触可以复用上一帧的冲量作为 Warm Start，让堆叠更快收敛。

### 2D 圆与 AABB

圆心到 AABB 的最近点可以通过逐轴 Clamp 求出。输入位置处于同一个二维世界空间，AABB 用中心与半尺寸表示：

```cpp
Collision HitCircleAabb(Vec2 center, float radius,
                        Vec2 boxCenter, Vec2 halfExtent)
{
    Vec2 closest = boxCenter + Clamp(center - boxCenter,
                                    -halfExtent, halfExtent);
    Vec2 delta = center - closest;
    float distance2 = Dot(delta, delta);
    if (distance2 > radius * radius) return {};

    float distance = Sqrt(Max(distance2, 1e-12f));
    Vec2 normal = distance2 > 1e-12f
        ? delta / distance
        : NearestExitAxis(center, boxCenter, halfExtent);
    return { true, normal, radius - distance, closest };
}
```

返回的法线从盒子指向圆，穿透深度用于位置修正。圆心位于盒内时，最近点等于圆心，`delta` 无法提供方向，因此要选择离最近边界最短的轴。位置修正后只移除速度沿法线且指向障碍物的分量；直接把整个速度反向会破坏切向运动。可用四个边、四个角和圆心完全位于盒内的测试验证方向与穿透值。

## 冲量与约束

碰撞法线方向的相对速度决定是否需要冲量。恢复系数控制反弹，摩擦约束限制切向相对运动。约束可以统一写成 Jacobian 对速度的限制，再通过迭代求解 Lagrange Multiplier。

顺序冲量求解器会逐条修正约束并重复多轮。迭代次数越高通常越稳定，但不是线性换取精度。质量差异过大、很长的关节链和不合理的穿透修正都可能让系统抖动。

位置误差不能一次强行清零，否则会注入额外能量。Baumgarte Stabilization、Split Impulse 或位置级求解会把修正分散到多轮。Sleep 可以停止几乎静止的刚体，减少成本；唤醒规则必须覆盖接触、外力和父级运动。

### 穿透修正的三种取向

**Baumgarte 稳定化**把穿透误差折成一个微小的速度偏差，让物体在几帧内“弹回”正确位置。实现最简单，但修正速度会与真实速度耦合，参数过大时物体表现出不自然的弹性。

**Split Impulse** 把修正分成两个速度通道：位置修正用单独的伪速度推进，不进入真实动量，因此不注入能量。代价是每个约束要求解两轮。

**位置级直接投影**（PBD 一系）直接在位置层面解除穿透，完全不经过速度。它最稳定、最容易做不可穿透的硬保证，但代价是与动量守恒脱钩——堆叠物体的能量行为不物理，布料、毛发这类“视觉正确优先”的系统用它最多。

三者没有普适最优。刚体堆叠、关节链倾向 Split Impulse；角色控制器与布料倾向位置投影；Baumgarte 作为遗留方案仍在不少引擎中出现。

## 查询、层与事件

Raycast、Shape Cast 和 Overlap 是 Gameplay 常用的场景查询。Collision Layer 和 Mask 应表达清楚的交互矩阵，避免每个脚本自行过滤。物理回调通常发生在求解阶段，回调里立即创建或销毁物体容易造成重入，适合把结果排队给后续逻辑阶段处理。

## 确定性与验证

浮点运算顺序、多线程调度、平台数学库和接触排序都会影响结果。需要确定性时，应固定时间步、输入顺序、随机种子、数据布局和求解顺序，并用状态 Hash 检测分歧。仅设置相同 Delta Time 不足以保证跨平台确定。

测试可从斜面静止、箱体堆叠、质量悬殊、快速弹丸、关节链和暂停恢复开始。记录最大穿透、能量变化、活跃刚体数和求解耗时，比只看画面“差不多”可靠。
