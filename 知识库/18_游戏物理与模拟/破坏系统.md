# 破坏系统

一个物体碎开，不只是生成很多刚体。破坏系统先保存碎块连接和支撑，再让冲击改变连接，失去支撑的连通块进入动态模拟。碎片生命周期与权威事件决定它能否用于玩法。

## 预切分与连接图

破坏系统通常预先用 Voronoi 等方式切分碎块，并建立连接图。冲击先改变连接强度，失去支撑的连通块再转成动态刚体。这样比运行时任意布尔切割稳定，也便于美术控制断面。

碎片数量必须有预算。远处可只播放替代动画或粒子，小碎片可以快速休眠、合并碰撞或不参与玩法结算。破坏结果影响玩法时，要由权威逻辑决定，表现层只负责播放对应状态。

## 激活流程

模型伪代码输入断裂连接与预算，连通计算以当前连接图为准。

```text
remove failed bonds
components = ConnectedComponents(chunkGraph)
for component without support:
    activate dynamic representation within budget
    use explicit proxy for excess fragments
```

## 支撑传播与连通分量

把碎块表示成节点，仍有效的黏结表示成无向边。外力造成的伤害更新边的剩余强度，降到零的边被移除。支撑状态随后沿有效边传播：一个分量中只要有固定支撑节点，该分量就仍连接地基；没有任何支撑的分量转成动态簇。

例如链0—1—2与另一簇3—4中，0是地基，只有3、4需要激活。若再断开1—2，节点2也失去支撑。检测用遍历即可实现：从未访问节点出发，用栈收集全部可达邻居，再检查集合与支撑集合是否相交。一次全图重算的时间为 $O(V+E)$，局部更新可缩小范围，但要正确处理一条桥边断裂把分量一分为二。

```text
for each unvisited chunk:
    stack = [chunk]; component = {}
    while stack is not empty:
        v = pop stack
        if v already visited: continue
        mark v visited; add v to component
        push neighbors connected by intact bonds
    if component has no support: activate this component
```

这段伪代码展开了连通算法；[参考实现](../examples/revision_16_21/reference.py)中的 `unsupported` 可直接运行。支撑传播是假定黏结足以承载的简化模型，不计算应力和扭矩。要模拟渐进结构坍塌，还需由力学模型更新边的承载状态。

激活簇继承原物体的线速度与角速度。碎块质心偏移为r时，初始线速度用 `v + omega × r`，避免旋转物体破碎瞬间所有碎块速度相同。玩法障碍保留权威碰撞代理，超出预算的细碎表现可转粒子；预算不能悄悄改变已承诺的通路和伤害判定。

## 验证方法

固定断裂事件比较连接分量，检查小碎片预算、睡眠与回收。联网破坏由权威状态确定，VFX只表现结果；实际断面与碰撞由资产验证。
