# 向量、矩阵与空间变换

图形学中的数学问题，很多不是公式不会算，而是**数据所在的空间不清楚**。同一组三个浮点数可以表示位置、方向、法线或颜色。数值一样，不代表语义一样。

## 点和向量

点表示一个位置。向量表示方向和长度，也可以表示两个点之间的位移。

- 点减点得到向量。
- 点加向量得到新点。
- 两个点直接相加通常没有清楚的几何意义。

使用齐次坐标时，位置常写成 $(x,y,z,1)$，方向写成 $(x,y,z,0)$。因此平移矩阵会影响点，不会影响方向。

## 长度和归一化

向量 $mathbf v$ 的长度是：

$$
\lVert \mathbf v \rVert = \sqrt{v_x^2+v_y^2+v_z^2}
$$

归一化得到长度为 1 的方向：

$$
\hat{\mathbf v}=\frac{\mathbf v}{\lVert \mathbf v \rVert}
$$

归一化会丢掉原长度。距离、速度等数据不能随便归一化。零向量也不能直接除以长度，代码中需要处理接近零的情况。

## 点积（Dot Product）

$$
\mathbf a\cdot\mathbf b=a_xb_x+a_yb_y+a_zb_z
$$

另一种写法是：

$$
\mathbf a\cdot\mathbf b=\lVert\mathbf a\rVert\lVert\mathbf b\rVert\cos\theta
$$

当两个输入都是单位向量时，点积直接表示夹角余弦：

- 接近 1：方向相近；
- 接近 0：接近垂直；
- 接近 -1：方向相反。

Lambert 光照中的 $\max(0,\mathbf N\cdot\mathbf L)$ 就是在问表面朝向光源的程度。

向量 $mathbf a$ 投影到单位方向 $\hat{\mathbf b}$ 上的标量长度是 $\mathbf a\cdot\hat{\mathbf b}$。对应的投影向量是：

$$
\operatorname{proj}_{\mathbf b}(\mathbf a)
=(\mathbf a\cdot\hat{\mathbf b})\hat{\mathbf b}
$$

> [!warning] 易错点
> 未归一化的点积同时包含角度和长度。不同坐标空间中的方向也不能直接点积。

## 叉积（Cross Product）

$\mathbf a\times\mathbf b$ 得到一个垂直于两者所在平面的向量。长度是：

$$
\lVert\mathbf a\times\mathbf b\rVert
=\lVert\mathbf a\rVert\lVert\mathbf b\rVert\sin\theta
$$

它可以用来：

- 根据三角形边构造法线；
- 构造相机或切线空间基底；
- 判断二维转向；
- 计算平行四边形面积。

叉积不满足交换律：$\mathbf a\times\mathbf b=-(\mathbf b\times\mathbf a)$。输入顺序和坐标系手性都会改变结果方向。

## 矩阵表示变换

4x4 矩阵可以统一表示缩放、旋转和平移。组合变换时，矩阵乘法不满足交换律。代码中的实际顺序还受行向量/列向量约定影响，不能只看“行主序或列主序”猜乘法方向。

通常会看到这些变换：

```text
Local/Object Space
  -- Model Matrix --> World Space
  -- View Matrix  --> View Space
  -- Projection   --> Clip Space
  -- Perspective Divide --> NDC
  -- Viewport Transform  --> Screen Space
```

### Model Matrix

把模型局部坐标变到世界坐标。它通常由平移、旋转和缩放组合。

### View Matrix

把世界变到相机空间。可以理解为相机世界变换的逆，而不是把相机本身继续往前移动。

### Projection Matrix

把视空间的可见体映射到裁剪空间。透视投影会让距离影响屏幕大小，正交投影不会。

## Clip Space、NDC 和透视除法

顶点乘投影矩阵后得到齐次裁剪坐标 $(x_c,y_c,z_c,w_c)$。GPU 在裁剪后做透视除法：

$$
(x_{ndc},y_{ndc},z_{ndc})=
\left(\frac{x_c}{w_c},\frac{y_c}{w_c},\frac{z_c}{w_c}\right)
$$

这一步才得到 NDC。Clip Space 和 NDC 不是同一个空间。

不同 API 的 NDC 深度范围和屏幕 Y 方向可能不同。写跨平台 Shader 时应使用引擎提供的变换函数，或者明确当前 API 约定。

### 顶点阶段的 MVP

下面的 HLSL 顶点阶段采用列向量约定，把对象空间位置依次变换到世界、观察和裁剪空间。分开保存中间量有助于检查矩阵顺序和空间归属：

```hlsl
VSOutput VSMain(VSInput input)
{
    VSOutput output;
    float4 positionWS = mul(Model, float4(input.positionOS, 1.0));
    float4 positionVS = mul(View, positionWS);
    output.positionCS = mul(Projection, positionVS);
    output.positionWS = positionWS.xyz;
    return output;
}
```

矩阵放在左侧还是右侧取决于向量约定和编译设置。代码、CPU 数学库和上传转置必须使用同一套规则，不能只凭表达式外观判断。

## 法线为什么不能当普通方向变换

法线表示一个平面的垂直约束。非均匀缩放会改变平面的形状。如果直接用模型矩阵变换法线，变换后的法线可能不再垂直于表面切线。

法线应使用模型矩阵线性部分的**逆转置矩阵**：

$$
\mathbf n'=(M^{-1})^T\mathbf n
$$

只有纯旋转或统一缩放时，普通方向变换与逆转置结果才可能等价。

## 如何验证空间问题

- 在场景中画出位置、法线、切线和光照方向的 Gizmo。
- 把方向映射到 RGB，检查轴向是否符合预期。
- 暂时把模型设置为非均匀缩放，观察法线变换是否仍正确。
- 在 RenderDoc 中检查 Vertex Shader 输入、输出和常量矩阵。
- 明确矩阵是在 CPU 端转置，还是 Shader 编译器按布局解释。
