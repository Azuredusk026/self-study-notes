# 输入、动作状态与框架分层

动作游戏框架要把设备输入、玩家意图、动作规则、移动和表现拆开。直接在 Update 中读取按键并播放动画，短期很快，加入 AI、回放、网络和连招后会立刻失控。

## 从设备到命令

Input Device 只负责读取键盘、手柄或触摸的原始值。Input Mapping 把它转换为 Jump、Attack、Move 等语义动作。Input Buffer 保存带时间戳的按下、释放和方向信息，为连招、Coyote Time 和网络重放提供依据。

输入采样与逻辑消费可能处于不同频率。一次短按必须被缓存到至少一个逻辑 Tick，而不是依赖两个 Update 恰好碰上。模拟摇杆需要 Dead Zone、归一化和响应曲线；方向相对相机时，应把输入向量投影到水平面的相机基向量。

AI、玩家和网络回放都可以产生同一类 Command。这样动作层只处理意图，不关心来源。

搓招识别把最近一段 Input Buffer 与有序模式匹配。模式可包含方向、按键、按住/松开、最大帧间隔和可接受的简化输入；匹配通常从最新输入向前回溯，优先选择更长、更具体的指令。识别结果应生成语义 Command，再由请求层判断当前资源、状态和 Cancel Window，不能在输入层直接发动技能。

## 请求层与行为层

请求层检查“想做什么”，例如请求攻击、闪避或切换武器。行为层决定“当前能否做、开始后如何推进”。请求可以被接受、排队、拒绝或替换，并记录原因。

状态机保存 Idle、Move、Attack、Hit 等互斥状态。层次状态机可以让 Grounded 和 Airborne 共享上层规则。多个可并行维度不必硬塞进一张状态图，例如移动、上半身动作和装备可以使用独立层，再通过明确约束协调。

Cancel Window 是动作数据，不应散落在动画事件回调中。动作定义可以包含前摇、有效帧、后摇、可取消目标、资源消耗和 Root Motion 策略。动画事件适合通知表现时刻，权威命中与资源扣除仍由 Gameplay 状态控制。

## 移动与状态解耦

Movement 模块处理加速度、转向、重力、地面和平台。动作状态给出移动约束或目标速度，而不是自己改 Transform。Root Motion 需要明确是权威位移、建议位移还是纯表现。

角色跳跃、落地、坡面和碰撞通常运行在固定时间步。相机和动画可在渲染帧插值。把同一速度在 Update 与 Fixed Update 重复积分是常见错误。

## 分层框架

一种实用分层是：

1. 信息层保存可查询的世界与角色状态；
2. 输入层产生语义命令；
3. 请求层做规则入口和优先级；
4. 行为层推进状态与动作；
5. 表现层驱动动画、音频、VFX 和相机。

分层不等于每层都需要抽象基类。稳定的数据契约和单向依赖更重要。跨层共享临时布尔值会让状态重新耦合。

## 2D Sprite 的变换与投影

屏幕空间 2D 场景常使用正交投影，把左上或左下角坐标直接映射到裁剪空间。一个 Sprite 的对象矩阵通常按“平移到目标位置、移动到枢轴、旋转、缩放单位 Quad、移回枢轴”的顺序构造：

```cpp
Mat4 model = Translate(position)
           * Translate(pivot * size)
           * RotateZ(rotationRadians)
           * Translate(-pivot * size)
           * Scale(size);
Mat4 clipFromObject = Orthographic(0, width, height, 0, -1, 1) * model;
```

这里的单位 Quad 位于 $[0,1]^2$，`position`、`size`、正交投影边界都使用像素单位，`pivot` 位于 $[0,1]^2$。矩阵乘法顺序需要按数学库约定调整。批处理时每个 Sprite 只上传变换、UV Rect、颜色和层级，所有实例共享 Quad 顶点和材质。验证可使用非正方形图片、中心与角落枢轴、90 度旋转和窗口缩放；Y 轴约定错误会表现为上下翻转，枢轴顺序错误会表现为绕世界原点旋转。

## 最小游戏循环

一个 2D 小游戏也需要区分输入采样、固定步长模拟和显示帧。下面的 C++ 伪代码把真实帧时间累积起来，模拟阶段只消费固定步长：

```cpp
double accumulator = 0.0;

while (!window.ShouldClose()) {
    double frameTime = Clamp(clock.Tick(), 0.0, maxFrameTime);
    accumulator += frameTime;
    input.Poll(window);

    while (accumulator >= fixedDelta) {
        CommandFrame commands = input.ConsumeForTick();
        game.FixedUpdate(commands, fixedDelta);
        accumulator -= fixedDelta;
    }

    renderer.Draw(game, accumulator / fixedDelta);
    window.Present();
}
```

`Clamp` 防止断点或窗口拖动产生一次超长模拟。`ConsumeForTick` 要保留短按，避免渲染帧和逻辑帧频率不同造成输入丢失。最后的比例用于表现插值，不参与权威状态更新。关卡加载、碰撞、粒子、音频和 UI 都应从明确的游戏状态读取结果，而不是各自维护另一份胜负状态。

## 数据驱动与调试

动作参数适合资产化，并通过 Validator 检查时间范围、引用、取消图和资源消耗。运行时应能显示最近输入、请求处理结果、当前状态、剩余时间和状态跳转原因。

回放一段 Command 流可以复现大部分框架错误。加入随机帧率、暂停、切换控制者和场景重载测试，能暴露时序与生命周期问题。
