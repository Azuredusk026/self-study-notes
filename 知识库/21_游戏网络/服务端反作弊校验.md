# 服务端反作弊校验

客户端请求可能带合法身份，却仍给出不可能位移或伤害。服务端校验先用权威Tick和能力约束解释请求，再记录偏差与上下文。协议认证、行为统计和处罚规则分别承担职责。

## 反作弊分层

第一层是权威服务器：客户端提交输入和请求，服务端验证速度、碰撞、冷却、资源与伤害。第二层是协议与客户端完整性，包括会话认证、签名、调试器与篡改检测，但客户端机器永远不完全可信。第三层是数据检测，通过不可能事件、行为统计和关联证据发现异常。

检测应保留可审计证据，并控制误报。网络抖动、辅助功能和高水平玩家可能看起来异常。敏感检测规则不应完整下发客户端。封禁、回滚经济损失和申诉流程也属于系统设计。

服务端速度校验的容差写法：允许位移 = 标称速度 × 服务端模拟时长 × (1 + 容差) + 已确认特殊位移量。容差按项目量化误差、离散步长和合法运动模型校准。网络抖动改变命令到达时刻，不应直接增加权威模拟时长。统计上区分单次超速与持续超速：单次记日志，持续超速才进入处罚流程——单次偏差可能来自网络、合法位移技能或异常请求，不能只凭一次超阈值处罚。回放时用服务端 Tick 和已确认运动能力核对，并把容差当作项目规则验证。

## 位移校验

机制伪代码使用服务端模拟时间与已确认特殊位移，单位统一为长度。

```text
allowed = speedLimit * serverElapsed * (1+tolerance) + approvedSpecialDisplacement
if measuredDistance > allowed:
    record anomaly with tick, inputs and ability state
    apply project-defined correction and review policy
```

## 输入时长与运动能力

服务器按已接纳的Tick消费输入，每个Tick最多接受协议允许的命令。客户端即使在同一帧发来十条“前进0.1秒”，也不能因此获得1秒运动预算；真实模拟时长由服务器调度决定。位移、冷却和资源校验因而共享同一时间基准。

路径长度限制只是筛选。例如角色在墙外与墙内的位置相距很短，距离公式可以通过，扫掠碰撞仍会拒绝。平台搬运、击退和传送由服务器授予独立能力记录，包含开始Tick、持续时间和最大效果，再纳入合法运动。客户端自行填写“特殊位移量”会直接绕过约束。设权威步长0.05秒、速度上限6米/秒、容差10%，普通预算只有0.33米。客户端把同一步输入重复十次，预算仍是0.33米；服务器若确认该步有2米冲刺，筛选上限才变成2.33米。即使2米终点满足长度限制，冲刺是否允许穿墙仍由该能力的碰撞规则决定。

告警记录原始输入序号、权威起终状态、能力记录和拒绝原因。离线回放用同版本规则复算，区分模拟不同步、合法技能边界和持续异常。统计信号只能提供调查证据，不能替代单次权威规则。

## 验证方法

回放正常抖动与已知技能，统计误报；注入超速和非法资源请求检查拒绝原因。单次异常不自动证明作弊，容差按玩法测试，不把客户端时间当权威。
