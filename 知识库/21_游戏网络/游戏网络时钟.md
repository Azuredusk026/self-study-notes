# 游戏网络时钟

两端时钟的起点不同。客户端在本地第10秒收到“服务器第35秒”的快照，单看两个数字无法判断快照在网络上走了多久。网络时钟先估计两个时间轴的偏移，再把服务器时间换成模拟 Tick；测量的误差决定这份估计能用于多精细的判定。

## 四个时间戳

一次探测记录客户端发送时刻 $t_0$、服务器接收时刻 $t_1$、服务器发送时刻 $t_2$、客户端接收时刻 $t_3$。每一端在自己的单调时间轴上计时，单位都是秒。服务器处理耗时是 $t_2-t_1$，从整个往返时间里减掉它，才能估计链路往返延迟：

$$d=(t_3-t_0)-(t_2-t_1),\qquad
\theta=\frac{(t_1-t_0)+(t_2-t_3)}{2}$$

在链路对称且短窗口内时钟速率相同的近似下，服务器时间约为客户端时间加 $\theta$。这两式对应 RFC 5905 第8节的时间戳关系；本页只使用其测量关系，不实现完整 NTP。

例如客户端在0秒发送、0.4秒收到，服务器在5.1秒收到、5.3秒回复。服务器处理花了0.2秒，链路往返也是0.2秒，偏移估计为5秒。只用一个服务器时间戳会把处理等待混入偏移。

```python
def clock_sample(t0, t1, t2, t3):
    offset = ((t1 - t0) + (t2 - t3)) / 2
    network_rtt = (t3 - t0) - (t2 - t1)
    return offset, network_rtt
```

这是 Python 数值片段，输入来自同一次握手。协议层先检查探测ID、顺序、有限数值及会话身份，再接纳样本。它不能由四个时间戳分辨真实偏移与固定链路不对称：上行150毫秒、下行50毫秒时，偏移会高估50毫秒。

## 平滑偏移与模拟步长

连续样本会带队列抖动。可以在短窗口里优先使用低延迟样本，并限制每次偏移调整量；低延迟能减少排队影响，却不能消除固有路径不对称。长时间运行还会出现频率偏差，此时以 $S(l)=a l+b$ 表示服务器时间估计，缓慢调整斜率 $a$ 和偏移 $b$，避免一个噪声样本突然改变事件年龄。

服务器发送纪元ID、基准 Tick、对应服务器时间和固定步长。客户端用这份锚点计算当前估计 Tick，重连或重启改变纪元时清空旧样本。偏移修正用于显示时间和调度估计；物理仍消费约定的固定步长。调时直接改变一次物理步长，会同时改变碰撞与输入积分。

## 偏移更新与Tick换算

一种明确的教学过滤器保存最近8个有效探测，取其中网络RTT最小的样本偏移作为目标。每次更新把当前偏移向目标移动，幅度限制为本地经过时间乘允许的最大校正速率；例如上次偏移5.000秒，目标5.020秒，经过0.1秒、校正速率0.01秒/秒，本次只移到5.001秒。频率斜率a暂取1，长期漂移会不断产生新误差，需由目标工程另设频率拟合；这个简化过滤器没有实现完整NTP。

给定服务器锚点时间S0=10秒、Tick0=600、固定步长1/60秒，服务器时间估计10.05秒对应Tick603。代码用floor((S−S0)/dt)+Tick0，并保留分数供显示插值；浮点边界采用协议统一的整数时间单位或容差规则，避免两端在恰好一步处相差一Tick。新纪元的Tick600不能与旧纪元600比较，先换纪元并清空历史，才能接受新的时间轴。大幅错误锚点超过允许恢复窗口时重建会话同步，不通过一次超大物理步长追回。

## 验证方法

分别注入对称延迟、非对称延迟、服务器处理等待和丢失探测。比较估计偏移、链路RTT和样本接纳原因。墙钟跳变不应改变单调计时；大幅校正采用重新建锚点的策略，并明确暂停、追帧或显示平滑的行为。
