# 游戏网络时钟

两端墙钟不同，收到时间戳不能直接判断事件年龄。游戏网络时钟用往返样本估计偏移与漂移，再映射到共同Tick。链路不对称使估计带误差，所以校时不能直接改变物理步长。

## RTT 与时钟偏移

Round-Trip Time 是请求发出到响应返回的总时间。只用一次采样会受抖动影响，通常维护平滑 RTT 与偏差。若本地在 $t_0$ 发出，服务端时间为 $t_s$，本地在 $t_1$ 收到，并假设上下行大致对称，可粗略估计：

$$offset\approx t_s-\frac{t_0+t_1}{2}$$

上下行并不总对称，因此这是估计，不是绝对时间。游戏通常更关心共同 Tick、事件年龄和插值时间线。系统墙钟可能跳变，测量间隔应使用 Monotonic Clock。

这与 NTP 的基本偏移估计相同：利用双向时间戳同时估算往返延迟和本地时钟偏移，再从多次采样中选择低延迟样本并平滑漂移。服务器权威 Tick 仍应独立于墙钟，避免系统校时直接改变模拟步长。

## 偏移样本

机制伪代码使用单调本地时间，服务时间戳语义由协议定义。对称链路近似仅给偏移估计。

```text
rtt = receiveLocal - sendLocal
offsetSample = serverTimestamp - (sendLocal+receiveLocal)/2
update filtered offset using bounded adjustment
estimatedServerNow = localNow + filteredOffset
```

## 验证方法

注入上下行不对称、抖动和墙钟跳变，比较估计误差及调整速度。低RTT样本和长窗口平滑分别记录，Tick序号与日历时间保持独立。
