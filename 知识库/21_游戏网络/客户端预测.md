# 客户端预测

本地玩家等待往返确认才移动，会直接感到延迟。客户端预测先执行输入，服务器确认后恢复权威状态并重放剩余命令。逻辑修正立即生效，显示偏移再平滑，不能只线性插值权威碰撞位置。

## 客户端预测与校正

本地玩家若等待服务器确认才移动，响应时间会包含往返、服务器排队与显示等待。客户端预测立即用本地输入模拟，同时把带序号的输入发给服务端并保存在输入缓冲。

服务端返回权威状态和最后处理的输入序号后，客户端执行校正：回到权威状态，丢弃已确认输入，再重放剩余输入。预测代码和服务端规则应共享或保持严格一致。视觉层可缓慢消化小误差，而碰撞和玩法状态立即以权威值为准。

直接对权威位置做线性插值会把问题藏起来，也可能永远追不上。应先重放得到正确预测结果，再单独做显示偏移平滑。

## 权威边界

客户端可以预测表现，不能决定伤害、掉落、库存和最终位置。服务端验证输入频率、移动能力、碰撞、资源和技能前提。完全拒绝所有偏差会误伤网络抖动玩家，完全信任客户端则给作弊留下入口，规则需要带容差且可审计。

## 校正循环

伪代码要求确认序号单调且按回绕规则比较，Simulate与服务端使用相同固定步长及玩法规则。

```text
predicted = authoritativeAtAck
erase inputs through ack
for input after ack in tick order:
    predicted = Simulate(predicted,input)
visualOffset = previousRenderedPosition - predicted.position
```

## 重放中的碰撞与序号

权威状态必须与确认序号成对使用。假设服务器确认到65535号输入时角色位于8米，客户端还保存0号向前5米和1号向后1米的命令，前方10米处有墙。重放0号先在墙前停到10米，再重放1号得到9米。把未确认位移直接求和会得到12米，因此重放必须执行同一移动与碰撞规则。

16位序号在65535后回到0。只要活动窗口始终小于半个序号空间，可用模差判断新旧：

```python
def newer(a, b):
    return 0 < ((a - b) & 65535) < 32768
```

输入确认序号与权威快照Tick分别比较。相同输入确认号只表示没有新输入被消费，服务器仍可能因外力或平台运动产生较新的权威状态；应接受较新快照，再重放尚未确认输入。快照Tick过旧或确认号倒退的包才拒绝，完全重复的状态不再处理。两序号恰好相差32768时无法判断方向，协议必须保证不会积累到这个跨度，或重新同步会话。待重放队列按本地生成顺序保存，不能对回绕后的整数直接排序。

预测还需要对应时间的外部条件。角色站在移动平台上时，仅有自己的坐标不足以复现碰撞；保存或重建平台变换，才能让重放使用相同接触条件。缺少这些条件时允许校正，但要记录误差来源，不能用显示平滑掩盖持续的规则偏差。

校正后的逻辑位置立即供下一 Tick 使用。显示层保存“旧显示位置减新预测位置”的偏移，并按固定半衰期衰减；指数形式 `offset *= exp(-ln(2)*renderDt/halfLife)` 使不同显示帧率具有一致衰减时间。传送等大幅不连续变化直接重置偏移。

## 重放事件的身份

位置可以反复重算，声音和粒子不能每次校正都创建一次。为可预测事件保存(会话纪元,输入序号,事件槽)作为身份；首次模拟输入17的开火槽0时播放枪口效果，重放同一输入再次产生该ID，只更新其状态。服务器确认接受时把它转为已确认；服务器拒绝该动作时取消可撤销表现，扣弹和伤害始终由权威结果决定。

输入队列还必须有上限。断线后积累超过可重放历史窗口时，旧外部碰撞条件已不存在，客户端停止按旧输入追赶，申请完整权威状态并建立新纪元。继续重放任意长队列会把重连耗时和错误碰撞一起放大。此时显示层可淡入或直接跳转，但逻辑状态必须从新锚点开始。

## 验证方法

记录校正距离与重放Tick，模拟延迟、重复确认和序号回绕。碰撞、平台、传送与技能打断分别测试，事件重放去重并不等于复制旧显示状态。
