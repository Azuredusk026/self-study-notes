# 延迟补偿命中

射手看到目标还在门外，服务器收到射击时，目标已经走进门里。两端看到的是不同时间的目标。延迟补偿让服务器在有限历史窗口内查询射手所见的碰撞状态，再把命中结果应用到当前权威状态。

## 射击与显示时间

客户端预测本地角色，远端角色却在历史快照间插值。因此射击请求至少要关联输入序号、射击朝向和该帧使用的远端显示时间。客户端记录开火帧实际采用的远端播放时刻r及服务器纪元，服务器用时钟映射估计射击生成时刻，核对画面年龄与许可插值窗口。稳定播放时可写成下面的关系，目标查询使用通过校验的实际r：

$$t_q=r_{fire},\qquad d_{actual}=t_{fire,server}-r_{fire}$$

例如服务器当前10.000秒，估计请求在9.920秒生成，远端插值延迟为0.100秒，实际r为9.820秒时查询该时刻的目标碰撞体。这里的80毫秒已经体现在射击生成时刻里，不能再次减去一次单程延迟。

服务器核对序号、开火间隔、弹药、枪口位置和朝向变化，再检查查询时间是否落在允许窗口及实际历史范围。客户端时间戳是请求数据；服务端按会话样本、最大补偿窗口和配置允许的插值延迟限制它。过旧请求可明确拒绝，不能悄悄把任意旧时间夹到最早一帧并声称重建了原画面。

快照页的播放时间r有独立速率控制，缓冲恢复期间未必等于估计服务器时间减去目标延迟。因而不能只重新计算`t_fire-Dtarget`代替开火帧真正显示的r。请求记录`(输入会话,输入号,显示纪元,r)`，服务器限制`d_actual`在该会话协商的画面年龄范围内，并在连续呈现段内检查相邻射击r的推进符合许可播放速率；缓冲重建切换呈现段时，先按会话规则登记重同步标记、重新检查允许画面年龄，再建立新的r推进锚点，不能沿用旧段速率比较。超窗、纪元不符或缺少历史时明确拒绝。客户端声明只提供候选视图，不获得任意查询历史的权限。

射手枪口与远端目标采用不同边界。按 [[21_游戏网络/客户端预测]] 的输入协议，服务器在实际消费开火输入的Tick先执行本步移动，再从该步权威角色姿态计算枪口并判射击；朝向也来自该输入并受变化速率与动作状态校验。客户端采样时刻的映射用于年龄和反重放检查，不把射手退回那个墙钟时刻。目标和可回溯遮挡物查询实际`t_q`，对应射手当时所见的远端插值画面。若输入在服务端队列多等了一步，枪口仍使用该输入实际消费步，而不是误取早一步的射手历史。此双边界规则不把本地预测射手和远端插值目标强行放在同一个历史时刻。

## 历史碰撞体

每个服务器 Tick 保存可受击实体的稳定ID与代数、碰撞体位置、旋转、尺寸和有效状态。查询时间落在两帧之间时，连续运动可插值；传送、生成和销毁把历史分段，跨段时按玩法规则处理，不能在不存在的位置生成中间碰撞体。

历史查询可使用独立碰撞场景，也可暂时替换实时碰撞体后在作用域退出时恢复。独立场景避免查询期间触发实时物理回调，代价是额外存储和索引。历史长度为 $W$ 秒、频率为 $f$、实体数为 $N$、每实体记录 $B$ 字节时，原始存储约为 $WfNB$，还要计入索引和分配成本。

动态门和平台也会改变遮挡。把角色退回过去、门却留在现在，是一套混合时间规则。本文选择角色、可移动门与平台全部在`t_q`查询，静态场景用固定几何。门开关等离散变化保存事件时间，查询时取不晚于`t_q`的最近状态；角色传送也按事件切段。服务器接纳输入时记录采用的补偿时间和策略版本，这样重试不会因为后来增加历史而改变判定。

## 最小射线查询

用球形受击体可以先验证时间插值与命中算法。设单位射线方向为 $d$，起点为 $o$，历史球心为 $c$，半径为 $r$。代入 $|o+td-c|^2=r^2$，令 $m=o-c$，则 $b=m\cdot d$、$q=m\cdot m-r^2$，判别式为 $b^2-q$。

```python
disc = b*b - q
if disc < 0:
    return None
enter = -b - sqrt(disc)
leave = -b + sqrt(disc)
if leave < 0:
    return None
return max(0, enter)
```

这是求交机制片段，输出射线前方距离，所有位置与半径使用米；起点在球内时输出0。完整参考函数见下方。测试球心(5,0,0)、半径1、射线沿正X，命中距离应为4；球心在(-5,0,0)时不应命中。真实角色需要胶囊或骨骼碰撞体，并比较所有有效遮挡的最近命中。

## 历史遮挡与实时状态隔离

设目标球心在9.80秒为(5,0,0)、9.84秒为(5,2,0)，查询9.82秒得到(5,1,0)。射线沿X轴、半径0.5米时不命中；若误用9.80秒记录就会命中。门在9.81秒关闭时，门的历史状态也必须在9.82秒参与最近交点比较，否则角色虽然回溯正确，遮挡规则仍混用了时间。

临时替换实时碰撞体的实现必须覆盖所有退出路径：进入查询前保存每个被改对象的变换和启用状态，在禁止实时物理步进与回调的查询范围内安装历史状态，执行查询后用作用域清理恢复，异常和提前返回也走恢复。记录对象代数，避免把已经销毁重建的新对象恢复成旧对象位置。独立历史场景则将查询数据与实时世界隔离，后续只把命中ID和距离交回权威逻辑。

## 命中提交与验证

查询只回答历史上击中了谁。对所有有效历史受击体与遮挡体求正向最近交点，再选距离最小者；遮挡更近便阻断，距离相同按预先规定的遮挡优先与稳定ID次序处理，避免容器遍历顺序决定命中。查询结果返回目标ID、实例代数、距离和使用的历史时间，不直接改实时物理状态。

当前权威逻辑再验证目标代数、当前存活规则和射击ID。本文规则允许命中过去位置，但伤害只应用到同一实例当前仍存活的目标；已经死亡或销毁的实例返回无伤害结果，不把旧命中转给重生角色。开火请求的身份采用输入会话、序号和动作槽，首次处理时在对局单一模拟事务中保存弹药变化、伤害、结果与事件ID；重复请求读取该结果，不再次查询后改判。若弹药不足，保存拒绝结果而不是等待状态变化后再让同一请求成功。

对局崩溃恢复还需将这次输入和提交结果纳入耐久日志或状态快照，顺序见 [[21_游戏网络/对局服务器架构]]；内存去重只能覆盖进程仍在运行的时间。音效按事件ID消费，客户端预测表现与权威伤害分开确认，不能在每次重试历史查询时重复执行。先用目标横穿射线的录制轨迹验证时间选择，再测试掩体、传送、销毁、重复请求及超出窗口的拒绝原因。
