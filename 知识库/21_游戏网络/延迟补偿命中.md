# 延迟补偿命中

射手看到目标还在门外，服务器收到射击时，目标已经走进门里。两端看到的是不同时间的目标。延迟补偿让服务器在有限历史窗口内查询射手所见的碰撞状态，再把命中结果应用到当前权威状态。

## 射击与显示时间

客户端预测本地角色，远端角色却在历史快照间插值。因此射击请求至少要关联输入序号、射击朝向和该帧使用的远端显示时间。服务器利用已建立的时钟映射估计射击生成时刻，再减去协议允许的插值延迟，得到目标查询时刻：

$$t_q=t_{fire,server}-d_{interp}$$

例如服务器当前10.000秒，估计请求在9.920秒生成，远端插值延迟为0.100秒，则查询目标9.820秒的碰撞体。这里的80毫秒已经体现在射击生成时刻里，不能再次减去一次单程延迟。

服务器核对序号、开火间隔、弹药、枪口位置和朝向变化，再检查查询时间是否落在允许窗口及实际历史范围。客户端时间戳是请求数据；服务端按会话样本、最大补偿窗口和配置允许的插值延迟限制它。过旧请求可明确拒绝，不能悄悄把任意旧时间夹到最早一帧并声称重建了原画面。

## 历史碰撞体

每个服务器 Tick 保存可受击实体的稳定ID与代数、碰撞体位置、旋转、尺寸和有效状态。查询时间落在两帧之间时，连续运动可插值；传送、生成和销毁把历史分段，跨段时按玩法规则处理，不能在不存在的位置生成中间碰撞体。

历史查询可使用独立碰撞场景，也可暂时替换实时碰撞体后在作用域退出时恢复。独立场景避免查询期间触发实时物理回调，代价是额外存储和索引。历史长度为 $W$ 秒、频率为 $f$、实体数为 $N$、每实体记录 $B$ 字节时，原始存储约为 $WfNB$，还要计入索引和分配成本。

动态门和平台也会改变遮挡。把角色退回过去、门却留在现在，是一套混合时间规则。项目应明确哪些遮挡体参与历史查询，并用门关闭前后两种射击记录验收。

## 最小射线查询

用球形受击体可以先验证时间插值与命中算法。设单位射线方向为 $d$，起点为 $o$，历史球心为 $c$，半径为 $r$。代入 $|o+td-c|^2=r^2$，令 $m=o-c$，则 $b=m\cdot d$、$q=m\cdot m-r^2$，判别式为 $b^2-q$。

```python
disc = b*b - q
if disc < 0:
    return None
enter = -b - sqrt(disc)
leave = -b + sqrt(disc)
if leave < 0:
    return None
return max(0, enter)
```

这是求交机制片段，输出射线前方距离，所有位置与半径使用米；起点在球内时输出0。完整参考函数见下方。测试球心(5,0,0)、半径1、射线沿正X，命中距离应为4；球心在(-5,0,0)时不应命中。真实角色需要胶囊或骨骼碰撞体，并比较所有有效遮挡的最近命中。

## 命中提交与验证

查询只回答历史上击中了谁。当前权威逻辑再验证目标代数、当前存活规则和射击ID，提交一次伤害。音效和扣弹不能在每次重试历史查询时重复执行。先用目标横穿射线的录制轨迹验证时间选择，再测试掩体、传送、销毁、重复请求及超出窗口的拒绝原因。
