# 世界分区与AOI

玩家只需要附近和玩法相关对象，完整世界复制会耗尽带宽。AOI用空间与关系筛选，跨服务器移动再交接状态和路由。复制范围与权威迁移是两个层次，边界切换都需要稳定身份。

## AOI 与世界分区

Area of Interest 只把相关实体复制给玩家。可按网格、四叉树、动态区域或玩法关系筛选，再按距离和重要性分配带宽。进入和离开 AOI 要有稳定的生成与移除语义，边界抖动可加迟滞。

大型世界可按 Zone、Shard 或实例划分。跨区对象需要 Ghost/Proxy 表示相邻区域状态。玩家跨服务器时，源服冻结可迁移状态，目标服确认接管，再切换路由。这个过程很难做到任意物理对象和战斗交互完全无缝，因此边界通常放在门、传送或低交互区域。

跨服迁移按三阶段执行：源服冻结玩家状态并生成带版本号与所有权 epoch 的迁移包；目标服加载、校验后回执；路由层切换完成，源服才释放资源。超时后先核实所有权提交状态，再决定继续、重试或撤销准备。迁移期间到达的该玩家输入要排队，切换完成后按序补发，否则技能请求会在交接缝隙里丢失。

跨区事务应有唯一 ID、幂等处理和补偿流程。分布式系统里网络超时不能说明对方一定没执行，盲目重试会复制物品或重复扣费。

## 基于网格的 AOI 查询

实体按二维世界位置进入固定尺寸格子。查询只遍历观察者周围覆盖视距的格子，再做精确距离判断：

```cpp
CellKey ToCell(Vec2 p) { return Floor(p / cellSize); }

void QueryAoi(Vec2 center, float radius, Vector<EntityId>& out)
{
    CellKey minCell = ToCell(center - Vec2(radius));
    CellKey maxCell = ToCell(center + Vec2(radius));
    for (int y = minCell.y; y <= maxCell.y; ++y)
        for (int x = minCell.x; x <= maxCell.x; ++x)
            for (EntityId id : cells[{x, y}])
                if (DistanceSquared(position[id], center) <= radius * radius)
                    out.push_back(id);
}
```

该片段把实体作为单点且每个ID只存一个桶，cellSize为正，radius非负；调用方先清空输出。单线程更新阶段内，实体跨格子时先维护旧桶与新桶的一致性；并发查询使用锁或快照保证一致视图，断线或迁移时也要清理成员。格子太小会增加桶遍历和迁移，太大又会增加精确过滤。验证时统计每次查询访问的格子、候选数、最终实体数和跨区迁移次数。

## 复制迟滞与权威交接

进入半径取R，退出半径取R+h，其中h是正的迟滞宽度。实体首次进入R时发送完整生成状态，随后增量更新；已经在集合中的实体只有超过R+h才离开。客户端按实体ID与代数处理生成和销毁，这样边界附近的小幅移动不会反复创建对象。维护已有集合时，候选查询需覆盖R+h，或另行逐个检查已有成员；若只查R就把未返回者删除，迟滞会失效。空间查询只提供候选，队伍、任务和观战关系还会加入非空间相关实体。

权威迁移需要一个能仲裁所有权的记录 `(entityId,epoch,owner)`。源服冻结后，目标服先处于准备状态；只有所有权记录通过条件更新切到新epoch，目标服才接受输入。存储或下游服务同时拒绝旧epoch写入，才能阻止迟到的旧服务器继续修改状态。

如果目标已经取得新epoch而回执丢失，源服不能因超时自行恢复。它先查询仲裁记录：所有权仍归源服才可恢复，已归目标则继续路由到目标，仲裁不可达时保持冻结或执行明确的故障策略。用暂时不可用换取单一权威，避免超时形成双主。

## 验证方法

全量遍历与网格查询比较集合，测试负坐标、边界与迁移清理。跨服每个故障点检查epoch和唯一权威，迁移输入按序缓冲，超时不能直接让两端同时继续。
