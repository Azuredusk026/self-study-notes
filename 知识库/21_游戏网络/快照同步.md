# 快照同步

远端输入尚未到达，本地通常只能显示已收到的状态。快照同步保留一段历史，在两个确定快照之间插值；压缩只相对接收端已确认基线，丢失时用完整状态恢复。

## 压缩与基线

位置、旋转和速度可按玩法允许误差 Quantize。Delta Compression 只发送相对已确认 Baseline 的变化，因此必须知道接收方拥有哪个基线。周期性 Keyframe 可在丢包或加入中途时恢复完整状态。

复制优先级通常由距离、可见性、变化幅度和玩法重要性决定。AOI 先筛选相关实体，再按带宽预算安排字段。省略更新不等于删除实体，生命周期消息要有独立可靠语义。

## 远端实体插值

其他玩家通常不预测输入，而是把显示时间故意放在估计的当前服务器时间之前一小段 Interpolation Delay，在两个快照之间插值。缓冲越大越平滑，但画面越旧。

短暂缺包时可按速度 Extrapolation 或 Dead Reckoning，时间过长则冻结或切安全状态，避免无限漂移。位置和旋转的插值要与传送、死亡等离散事件区分，事件不能被当成普通连续值穿过去。

### 插值缓冲的取时刻

插值的具体取法：维护渲染时刻 `renderTime = serverTime - interpDelay`，`interpDelay` 以 1~2 个快照间隔起步。渲染时在缓冲里找到夹住 `renderTime` 的两个快照，参数 $t=(renderTime-t_0)/(t_1-t_0)$，位置 Lerp、旋转 Slerp。快照到达节奏抖动时缓冲会耗尽或溢出：耗尽就钳制在最新快照并暂停推进 `renderTime`，溢出就丢弃最旧快照并让 `renderTime` 前跳半个间隔，而不是瞬间对齐到最新。缓冲长度随实测抖动自适应：统计最近窗口的到达间隔 P99，`interpDelay` 跟随它收放，但每秒最多调整一次以免振荡。

## 快照插值

伪代码中serverNow是估计的服务器时间，delay为正，快照t0<t1。

```text
renderTime = serverNow - delay
a,b = FindSnapshotsBracketing(renderTime)
alpha = clamp((renderTime-a.time)/(b.time-a.time),0,1)
renderPosition = lerp(a.position,b.position,alpha)
```

## 验证方法

丢包、乱序与到达抖动记录缓冲耗尽率和外推时长。传送、生成销毁不按连续位置插值，Delta基线缺失时请求完整快照。
