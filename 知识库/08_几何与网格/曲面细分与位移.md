# 曲面细分与位移

曲面细分让 GPU 在光栅化之前按需生成新顶点。它解决的问题是：美术无法为每个观察距离准备一套网格密度，而静态高模在远处浪费顶点、在近处仍可能不足。把细分决策交给运行时，几何密度就能跟随距离、屏幕投影尺寸或曲率变化。

曲面细分是可选管线阶段。启用后，Input Assembler 提交的不再是三角形，而是控制点构成的 Patch。

## 管线位置

固定管线插入三个阶段，位于 Vertex Shader 与 Geometry Shader 之间：

1. **Hull Shader**（OpenGL 称 Tessellation Control Shader）：输出细分因子和控制点；
2. **Tessellator**：固定功能硬件，按细分因子在参数域内生成拓扑；
3. **Domain Shader**（OpenGL 称 Tessellation Evaluation Shader）：对每个新顶点求最终位置与属性。

Tessellator 本身不可编程。它只知道参数域坐标，不知道模型形状。所有几何含义都由 Hull 和 Domain 两个可编程阶段赋予。

## 控制点与 Patch

启用细分后，Vertex Shader 的职责变成处理控制点。它不再做 Object Space 到 Clip Space 的变换——那件事推迟到 Domain Shader，因为顶点位置在细分之后才最终确定。

Patch 的控制点数量由 API 声明。三角形是三控制点 Patch，四边形是四控制点。控制点数量可以更多，用于表达 Bezier 曲面等高阶曲面：控制点越多，可表达的自由度越高。

Hull Shader 的输出控制点数量不必等于输入数量，允许在此阶段新增或丢弃控制点。

## 细分因子

Hull Shader 分为两部分。Patch Constant Function 每个 Patch 执行一次，输出边细分因子与内部细分因子；Control Point Function 每个输出控制点执行一次。

因子语义随 Domain 类型变化：

| Domain | `SV_TessFactor` | `SV_InsideTessFactor` |
|---|---|---|
| `quad` | 长度 4，四条边各分几段 | 长度 2，内部横向与纵向各分几段 |
| `tri` | 长度 3，三条边各分几段 | 长度 1，控制内部环数 |
| `isoline` | 长度 2，线段数量与每段细分数 | 忽略 |

`tri` 内部点的生成方式是对每个顶点分割邻边，在分割点作垂线求交点。理解这一点才能解释为什么三角形内部细分呈同心环状，而不是均匀网格。

Direct3D 11 与 OpenGL Core 规定最大细分因子至少为 64。`maxtessfactor` 属性把 Shader 实际使用的上限告知驱动，硬件可能据此优化。

## 分割模式

`partitioning` 决定细分因子的小数部分如何处理：

- `integer`：因子向上取整。因子跨越整数边界时，新顶点整排突然出现，产生可见跳变（Popping）；
- `fractional_odd`：保持奇数段数，小数部分体现为新边从零宽度平滑生长；
- `fractional_even`：同理但保持偶数段数。

连续 LOD 必须使用 fractional 模式。用 `integer` 做距离驱动细分会在相机推进时出现几何抖动。

相邻 Patch 的共享边必须计算出完全相同的边细分因子，否则会出现裂缝（Crack）。因子应当由共享边的两个端点唯一决定，例如取两端点世界位置的中点计算屏幕尺寸，而不能使用 Patch 中心或面法线——后者在两侧 Patch 上取值不同。

## 参数域坐标

Tessellator 把新顶点以参数坐标交给 Domain Shader，形式随 Domain 类型变化：

- `quad` 与 `isoline`：二维 UV 坐标；
- `tri`：三维重心坐标 $(u,v,w)$，满足 $u+v+w=1$。

Domain Shader 对每个新顶点执行一次，用这些参数坐标在控制点之间插值。这里通常是细分管线中计算量最大的部分：所有顶点属性都要重新求值，并完成到 Clip Space 的变换。

### Domain Shader 的插值与位移

下面是 `tri` Domain 的最小实现。输入是 Hull Shader 输出的三个控制点与重心坐标，输出 Clip Space 位置。高度图采样必须使用 `SampleLevel` 指定 mip，因为顶点阶段没有屏幕导数：

```hlsl
[domain("tri")]
DomainOut DS(PatchTess patchTess,
             float3 bary : SV_DomainLocation,
             const OutputPatch<HullOut, 3> tri)
{
    float3 posL = tri[0].PosL * bary.x
                + tri[1].PosL * bary.y
                + tri[2].PosL * bary.z;
    float3 nrmL = normalize(tri[0].NrmL * bary.x
                          + tri[1].NrmL * bary.y
                          + tri[2].NrmL * bary.z);
    float2 uv   = tri[0].UV * bary.x
                + tri[1].UV * bary.y
                + tri[2].UV * bary.z;

    float h = gHeight.SampleLevel(gSampler, uv, 0).r;
    posL += nrmL * (h * gDisplaceScale - gDisplaceBias);

    DomainOut dout;
    dout.PosH = mul(mul(float4(posL, 1.0), gWorld), gViewProj);
    return dout;
}
```

去掉位移那一行，输出结果与不做细分完全一致——细分本身只增加顶点，不改变形状。形状变化来自 Domain Shader 对位置的修改，或来自 Bezier 等高阶曲面求值。

位移方向用插值法线时，法线必须在插值后重新归一化。`gDisplaceBias` 决定高度图的零位面：不减去偏置，整个表面会沿法线整体外扩。验证方法是把 `gDisplaceScale` 设为 0，画面应当与细分关闭时完全一致；若有差异，说明插值或偏置有误。

## Unity URP 中的写法

URP 用 `#pragma` 声明各阶段入口，最低 Shader Target 为 4.6：

```hlsl
#pragma target 4.6
#pragma vertex   TessVert
#pragma hull     Hull
#pragma domain   Domain
#pragma fragment Frag
```

控制点结构中的位置语义必须写成 `INTERNALTESSPOS` 而非 `POSITION`，否则编译器报位置语义重用错误。这是 Unity 侧的约定，不是硬件限制。

> [!warning] 待补充
> 细分在 Unity 中的平台支持随图形 API 变化。Metal 不支持 `isoline` Domain，部分移动 GPU 对细分的硬件支持有限或性能极差。目标平台清单需按项目实测确认，不能假设桌面端结论成立。

## 成本转移到哪里

细分把成本从内存与带宽转移到 GPU 几何阶段：

- 顶点着色工作量按细分因子平方增长，`tri` 与 `quad` 皆然；
- Domain Shader 中的纹理采样发生在顶点频率，没有 Quad 导数，必须显式指定 mip；
- 细分产生的大量小三角形会降低光栅化效率。小于一个像素的三角形仍按 2x2 Quad 着色，利用率降到四分之一；
- 硬件细分单元在部分 GPU 上是独立的有限吞吐单元，可能成为新瓶颈。

因此细分因子应当由屏幕空间尺寸驱动，目标是让每个输出三角形落在若干像素的范围内，而不是无条件取满 64。

## 与其他 LOD 方案的关系

离散 LOD 切换整套网格，切换瞬间有跳变但运行时成本可预测。细分提供连续过渡，代价是每帧几何阶段开销。Nanite 等虚拟化几何方案则在 Cluster 层级做选择，绕开了固定细分单元。

位移贴图与视差映射解决相似的视觉问题。视差只改变采样 UV，不产生真实几何，轮廓和自阴影仍是平的；位移改变真实顶点位置，轮廓正确，但成本高得多。

## 验证方法

- 线框模式下拉近拉远相机，观察细分因子是否连续变化，`integer` 模式应能看到整排新顶点突现。
- 检查相邻 Patch 边界是否出现裂缝，这几乎总是边因子计算不一致导致。
- 在帧捕获中查看 Domain Shader 调用次数与输出图元数，确认与预期细分因子相符。
- 把位移强度归零，画面应与关闭细分一致。
- 统计输出三角形的平均屏幕面积，小于一个像素说明细分过度。
