# 游戏AI决策模型

守卫正在追击敌人，敌人突然消失，下一帧又收到受伤事件。决策系统既要决定继续搜寻还是撤退，也要让旧移动真正停止，再把移动器交给新动作。只选对行为名称，还不能保证角色执行的是这次决定。

感知层提供带时间和来源的事实，决策层选择意图，执行层操作移动、动画和技能。下面先把三者的交接固定下来，再分别展开状态机、行为树、效用选择和目标规划。它们使用同一套动作实例与资源规则，组合时才能解释哪一个请求正在控制角色。

## 决策输入与动作交接

### 黑板快照

黑板键保存类型、值、来源、更新时间和版本。感知更新先形成一份只读快照，决策在这份快照上完成本轮判断。遍历途中到达的普通事件进入下一轮；紧急事件通过调度入口中止当前动作。如此树的前半段不会读旧目标，后半段却突然使用另一份目标。

短期可见状态和长期记忆分开保存。敌人离开视野时，当前可见标记变假，但最后位置可以保留到记忆时限。信念—愿望—意图模型（BDI）正是对这几类信息的区分：最后位置是信念，追击和自保是愿望，当前已经接受的撤退计划是意图。项目仍需规定何时放弃承诺；本页允许失效目标和紧急危险触发重新选择。

### 动作实例与独占资源

决策输出候选动作、目标和所依据的快照版本。执行器在接纳入口重新检查目标、冷却和资源，再生成动作实例ID；接纳失败返回原因。行为名称相同的两次追击也拥有不同ID，完成消息必须回到对应实例。规划中的预期效果只有在执行成功并读取实际结果后才写入事实。

移动器、武器或动画通道等独占资源保存所有者ID与代次。切换动作时先向旧实例发出幂等取消，执行器停止后续副作用、释放预约，再返回取消完成。新动作在冲突资源释放后才接纳；决策可以提前准备候选，但不能提前声明它已经运行。

旧移动取消期间收到迟到成功，只能结清旧实例。释放资源也比较所有者ID，旧清理不能清空新请求的槽。取消超时则保持占用并报告故障，候选可改用其他资源上的安全行为。已经射出的子弹属于世界事件，取消只阻止继续发射。动作ID解决消息归属，取消完成解决资源交接，两者都需要。

## 状态机与层次切换

### 状态进入、更新与退出

有限状态机（FSM）用活动状态和转移条件表达待机、巡逻、追击或攻击。一次进入创建该状态的动作，更新只观察同一实例，退出负责终止它。规则脚本也可沿这条接口执行：按明确优先级选择首个满足条件的规则，再交给动作账本，避免多条规则同时覆盖移动请求。

层次状态机（HFSM）把共享行为放在父状态。以下树中，战斗父状态负责目标跟踪，追击和攻击各自负责移动或武器：

```text
根
├─ 平静
│  ├─ 巡逻
│  └─ 安全待机
└─ 战斗
   ├─ 追击
   ├─ 攻击
   └─ 搜寻
```

从战斗/追击到战斗/攻击，最近公共祖先是战斗。先让追击取消移动，等待资源释放，再完成追击退出；战斗保持活动，最后进入攻击。等待期间HFSM保存目标路径并处于转移中，旧叶不再发新请求，新叶尚未活动。紧急事件可以修改待进入目标，退出已经开始的叶仍须完成清理。

### 进入失败与恢复路径

从平静/巡逻转到战斗/攻击，公共祖先是根。退出顺序为巡逻、平静，进入顺序为战斗、攻击。每个成功进入的状态记入本次清单；Enter失败的状态先撤销自身已取得的部分资源，异步撤销完成以前保持转移中。只有成功进入的状态才调用配对Exit，失败Enter使用自己的失败清理，避免同一资源释放两次。

假设战斗进入成功，攻击因目标销毁而失败。先完成攻击的部分初始化清理，再退出本次成功进入的战斗，回到仍活动的根。若指定的失败目标是平静/安全待机，就依次进入平静和安全待机。原巡逻的移动已被取消，因此不能把旧巡逻标记重新设为活动来假装恢复原状。安全待机自身无外部预约，作为这条路径的确定终点；它也不可用时保留根的错误状态并报告配置问题。

同一父状态内失败时，清单更短：追击已退出，攻击进入失败，公共祖先战斗仍活动。失败策略选择战斗/搜寻，只需进入搜寻。清理只撤销本次进入部分，公共祖先是否退出由实际路径决定，不能一律退到根或保留已经退出的旧叶。

## 行为树与节点生命周期

### 组合语义

行为树把条件和动作放在叶节点，由组合节点决定遍历顺序。顺序节点需要所有子节点成功；遇失败即结束。选择节点按优先级尝试子节点，失败才尝试下一个，成功即结束。两者遇到运行中的子节点都保留该分支。装饰节点可以增加门禁、循环或冷却，但同样遵守子节点的进入和取消规则。

记忆型顺序节点在动作跨帧运行时保存索引；反应式顺序节点每轮从前面的条件重新检查。反应式检查若改变了活动路径，先中止原动作，再进入新的冲突分支。只把索引归零会让旧追击继续占用移动器，同时再次创建另一次追击。

### 叶节点的四种状态

节点生命周期和对父节点的结果分别保存。生命周期为Idle、Running、Cancelling、Finished；终态结果为Success、Failure或Cancelled。Running与Cancelling对外都表示尚未结束，父节点还要看自身是否正在中止，不能把“等待取消”当成继续执行原计划。

| 生命周期 | 接收普通更新 | 接收中止 | 进入下一状态 |
|---|---|---|---|
| Idle | 调用一次Enter，接纳动作后保存实例ID | 直接以Cancelled结束，无外部资源 | 接纳成功到Running；无残留预约的拒绝到Finished(Failure) |
| Running | 查询同一实例；终态时执行一次Exit | 发一次幂等取消，停止普通更新 | 正常完成到Finished；中止到Cancelling |
| Cancelling | 只处理取消、迟到完成与资源释放 | 合并重复请求，不重复创建动作 | 确认资源已释放后完成一次清理，到Finished，保存取消或进入失败结果 |
| Finished | 返回缓存终态，不再Enter或Exit | 保持已有终态 | 父节点消费终态后显式Reset到Idle |

Enter被拒绝时必须保证没有残留预约。若初始化已经部分取得资源，节点进入Cancelling并保存待结束结果Failure，沿同一执行账本撤销并等待释放；清理完成才进入Finished(Failure)，不能先报失败让父节点启动下一动作。失败Enter执行自身失败清理，成功Enter的实例才调用配对Exit；这与HFSM进入失败的规则相同。普通运行中止的待结束结果则是Cancelled。

动作在取消请求之前已经成功时，可以正常结清Success；父节点若已进入Cancelling，也不会据此启动下一动作。取消后到来的成功只说明底层已停止，由取消路径统一结清为Cancelled。事件处理在调度入口串行排序，这个先后关系才可重放。

### 顺序节点的父子推进

下面是记忆型顺序节点的机制伪代码。叶节点Tick执行上表，`Finish`缓存结果并执行本节点Exit一次；组合节点没有直接操作角色的能力。每个实例一次只运行一个孩子。

```text
TickSequence:
    if state == Finished: return savedResult
    if state == Idle:
        state = Running; index = 0
    if state == Cancelling:
        if active child exists:
            poll its cancellation until child is Finished
            if child is not Finished: return Running
        reset every Finished child to Idle
        index = 0
        return Finish(Cancelled)
    while index < childCount:
        result = child[index].Tick()
        if child[index] is not Finished: return Running
        if result != Success:
            reset every Finished child to Idle
            index = 0
            return Finish(Failure)
        index += 1
    reset every Finished child to Idle
    index = 0
    return Finish(Success)

AbortSequence:
    if state == Finished or state == Cancelling: return
    state = Cancelling
    request Abort on the active child, if any
```

组合节点中止先标记自己Cancelling，再向活动子节点传播。子节点内部若还是组合节点，就继续向下传播；结束则由叶到父逐层确认。父节点等待整个活动子树终止后才复位已结束孩子，自己变为Finished，最后由更上层消费并复位。未进入的Idle兄弟保持Idle，已成功的兄弟只复位而不重复Exit。选择节点沿同样生命周期推进，但在正常运行中遇Failure时递增索引，遇Success结束；Cancelled表示执行被打断，结束当前选择，不把它当成普通失败立刻启动下一孩子。

例如顺序为“目标有效、追击、攻击”。追击处于Running时目标失效，父节点先进入Cancelling；追击等待移动器取消完成，期间攻击始终Idle。完成后追击Exit、父节点复位已结束子节点并输出Cancelled。上层重新进入这条顺序时，目标条件才会重新求值，追击不会沿用上一次Finished结果。

### 条件观察与调度

每帧遍历能发现条件变化，代价随NPC数量和树规模增长。观察者可在相关黑板键变化时请求重评估，Running和Cancelling节点仍须收到执行结果。事件派发与本轮快照在固定边界交接，条件变化不会直接从任意线程重入树。

Unreal的Observer Aborts把中止范围分为Self、Lower Priority、Both和None，分别作用于自身分支、较低优先分支、两者或关闭观察中止；具体执行仍由引擎调度。这些选项说明要停哪条路径，动作实例和资源协议说明何时真正停完。[Epic装饰节点说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-behavior-tree-node-reference-decorators)可对照宿主语义。

## 效用评分与动作切换

### 必要条件与偏好

效用系统（Utility AI）比较此刻各行为的价值。先用布尔门禁判断目标、弹药、路径和冷却等必要条件，再给可行行为计算偏好分数。本页的偏好采用加权几何平均：

$$U=\exp\left(\frac{\sum_i w_i\log\max(s_i,\epsilon)}{\sum_i w_i}\right).$$

每个原始输入先按已配置区间归一化，曲线输出s在[0,1]，权重w为正，ε取10⁻⁶。越界有限值可按规则夹到区间；非有限值或无效配置产生诊断，并把该候选判为不可用。必要条件为假直接拒绝，不能让ε把“没有弹药”变成微小却合法的射击概率。

```text
ScoreAction(action, snapshot):
    if any necessary condition is false: return Ineligible
    if preferences is empty: return Eligible(1)
    logSum = 0; weightSum = 0
    for preference in preferences:
        require finite input, finite curve result, finite weight > 0
        s = clamp(curve(normalize(input)), 0, 1)
        logSum += weight * log(max(s, 0.000001))
        weightSum += weight
    return Eligible(exp(logSum / weightSum))
```

三个同权0.8偏好和一个0.8偏好都会得到0.8；直接连乘则是0.512与0.8，差异只来自条目数量。几何平均保留低分压低总体偏好的性质，但偏好零分经数值下限仍是很小的正数。确实需要否决行为的条件放在门禁里，不与偏好混用。空偏好列表在本页取常量1，适合只受门禁控制的明确动作；设计者须将这个常量与其他动作的评分一起审查。

### 迟滞与失效优先级

普通切换要求新动作分数严格高于当前分数0.1，且当前动作已持续0.3秒。两项门槛只在当前动作仍可行且正在运行时适用。每次重评估先检查当前门禁和执行终态：目标销毁、路径失败、弹药耗尽或动作已结束，都直接进入停止或重新选择流程，绕过分差与持续时间。紧急事件按预定事件优先级选择可行的应急动作，同样绕过两项门槛；紧急不能绕过动作自己的必要条件。

当前追击0.75，新搜寻0.82，普通变化保留追击；新撤退0.9且持续0.4秒才触发普通切换。若敌人已销毁，即使追击只运行0.05秒、搜寻只有0.2，也先取消失效追击，再选择搜寻。没有可行候选就进入无外部预约的待机，不保持已经失效的动作。

选择最高分时用稳定行为ID打破平分。停止旧动作后，候选还要经过资源释放与最新门禁检查；等待取消期间若候选也失效，重新选择即可，旧动作不会重新获得执行权。随机选择是另一种项目策略，需要保存分布、种子和随机消费顺序，本页具体路线采用确定性最高分。

## 目标规划与执行

### GOAP回归搜索

目标导向行动规划（GOAP）用有限事实描述状态，动作用前提、效果和非负成本描述转换。目标是“有弹药且在掩体”时，搜索可以找到先补弹再进入掩体的次序。连续距离等输入按任务需要离散成有限区间，成本的时间、风险与消耗先统一尺度，避免状态数量和成本单位失控。

#### 规划的反向搜索

```cpp
Plan GoapPlan(WorldState start, Goal goal, Action[] actions)
{
    bestCost[goal.facts] = 0; // 其他事实集的默认成本为无穷；动作成本非负
    open.Push({ goal.facts, {}, 0 });           // 待满足事实、已选动作、累计成本
    while (!open.IsEmpty()) {
        Node node = open.PopLowestCost();
        if (node.cost != bestCost[node.required]) continue;
        if (start.Satisfies(node.required))     // 当前世界已满足全部剩余前提
            return Reverse(node.actions);
        foreach (Action& action in actions) {
            if (!action.effects.Intersects(node.required)) continue;
            if (action.negativeEffects.Intersects(node.required)) continue;
            Facts remaining = node.required - action.effects + action.preconds;
            if (remaining.ContainsContradictoryValues()) continue;
            if (node.cost + action.cost >= bestCost[remaining]) continue;
            bestCost[remaining] = node.cost + action.cost;
            open.Push({ remaining, node.actions + action,
                        node.cost + action.cost });
        }
    }
    return null;
}
```

这是回归规划的算法轮廓。每步用动作效果满足部分目标，再把动作前提加入剩余需求。片段将正效果、负效果与前提表示成事实集合，负效果与目标冲突时拒绝，合并后同一键出现矛盾值时也拒绝。bestCost按规范化事实集合索引，默认无穷；完整实现还需搜索预算、稳定平局规则和具体状态编码，冲突例子见下文。当前状态尚未满足某项前提时，其他动作可能建立它，不能据此直接剪枝。布尔事实可用位掩码保存；多值状态需要显式的键值表示与冲突规则。

计划只是意图，不保证底层动作一定成功。执行器要报告完成、失败、取消和超时，规划器据此更新事实。调试时同时保存搜索过的状态、被拒绝的前提和最终成本。

回归时若把“冲出掩体捡弹药”直接作为最后动作，它的负效果删除了目标中的在掩体，应拒绝这个位置。先选择“进入掩体”作为最后动作，再回归到补弹，则可以形成合法的“补弹→进入掩体”。这说明负效果检查针对本次剩余目标，不能把会破坏某项事实的动作永久禁用。

搜索队列按成本、稳定动作ID排序，事实集合采用固定键序列作为去重键；到达预设的展开节点上限（例如每次5000个）返回预算耗尽，不把未完成搜索当成证明无计划。零成本循环只在改善某个事实集的最佳成本时重新入队。执行时逐步复查前提，失败报告实际世界事实并重规划。

### HTN分解与状态推进

层次任务网络（HTN）用领域方法将复合任务拆成子任务。守卫在安静状态选择[巡逻]，警报状态选择[前往报警点,搜寻,报告]。规划器的节点保存临时状态、待展开任务列表与原子计划；取首任务，原子动作满足前提时应用效果并追加计划，复合任务则按方法顺序把子任务插到列表头。

假设报警点在锁门之后，第一个方法要求直接前往，前提不满足，规划器恢复该方法展开前的临时状态，再尝试[取得钥匙,开门,前往报警点,搜寻,报告]。取得钥匙的效果先写入临时状态，开门才会通过；方法失败时连同这份临时效果一起丢弃。相同临时状态与待展开任务组合去重，并限制分解深度，防止递归方法无限展开。

临时推演只用于找计划。真实执行取得钥匙失败，世界里仍没有钥匙，执行器不会继续开门，也不会把规划快照写回场景。GOAP与HTN都把原子动作交给同一动作账本，只有宿主确认成功才推进计划；取消时按活动实例释放资源，未开始的计划后缀直接丢弃。

## 模型组合与验证

状态机表达局部模式，行为树表达执行次序和优先级，效用系统选择当前目标，GOAP或HTN生成达到目标的动作序列。项目可以让效用选择撤退目标、规划器生成路径与掩护计划、行为树执行原子动作，但每个独占资源只有一份执行账本。多个模型提出候选不等于它们各自拥有一套移动器。

调试记录本轮快照、候选门禁与评分、活动节点、动作ID、资源所有者、取消原因和终态。看到角色仍追旧敌人时，先检查决策是否产生取消，再检查执行器是否完成交接，最后检查新候选是否被接纳。这样可以区分选择错误、取消滞留和资源竞争，而不只观察最后的动画。

### 逐机制反例

- 确定性回放：固定种子与世界快照离线重放整局决策，逐帧比对每个 NPC 的当前节点与动作序列；任何分叉都要能定位到具体黑板键的变化。
- 中止测试集：为每类 Observer 中止构造“打断瞬间”用例，确认被打断动作的退出执行了、外部请求被取消、黑板残留状态被清理。
- 黑板审计：记录每个键的写入者与时间戳，检查是否有系统绕过受控接口直接改写，短期感知键是否按过期时间清理。
- Utility 回归：录制典型局势（残血、弹尽、被围），确认期望动作得分第一；每个评分因素的输入、曲线输出与总分写日志，分数异常时可回放归因。
- GOAP 计划校验：对生成的计划逐步骤检查前提在模拟中成立；动作执行失败时确认执行器上报失败并触发重规划，而不是原地干等。
- 预算检查：统计单帧决策耗时的 P99；大量 NPC 时确认事件驱动重评估生效，检查持续 Running 任务更新与条件重评估各占多少成本。事件驱动和逐帧 Tick 都可以成立，选择取决于实现语义与预算。

## 实现与证据

行为树、效用和GOAP正文为机制片段。[有限键值GOAP模型](../examples/revision_16_21/review_reference.py)通过3项回归检查：拒绝破坏目标的末动作、先破坏后重建事实、零成本循环终止；运行 `python 知识库/examples/revision_16_21/test_review_reference.py` 可复现。完整NPC框架、异步动作与行为树中止尚未接入运行。
