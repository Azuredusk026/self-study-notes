# 群体、学习与高级决策

高级 AI 不代表把单体决策换成更复杂的模型。群体、战术搜索和学习系统首先要解决信息规模与计算预算：谁能看见什么、多久思考一次、结果是否公平、能否在服务器或回放中复现。

## 群体与战术信息

群体移动可从 Separation、Alignment、Cohesion 三类局部规则开始。它们能形成自然队形，但不了解关卡目标与门口拥堵。实战通常把全局导航走廊、局部避障、队形槽位和通行优先级组合起来。

Influence Map 把危险、控制力、资源或视野写入 Grid/NavMesh 区域。AI 可查询安全路线、薄弱侧翼和集火区域。不同信号要有衰减和更新时间，不能把过期敌情当成实时真相。Tactical Point 则预先或运行时标记掩体、射击位和观察点，并按距离、暴露度、队友占用等评分。

Influence Map 的更新分源写入与扩散衰减两步：每个单位把影响力写入所在格子（威胁写正值、资源用另一层写正值），随后每层向邻居做若干轮扩散，每轮强度乘衰减系数 $\alpha<1$。衰减控制影响半径，扩散轮数控制传播速度，两者合起来决定地图的“记忆长度”。常见分层是即时威胁层高衰减快更新、战略控制层低衰减慢更新。查询时读查询点周围一个小邻域的积分而不是单点，否则单位沿格子边界移动时评分会跳变。

## 感知预算与信息抽象

每个 NPC 每帧扫描所有对象是典型的 $O(N^2)$ 陷阱。可先用空间索引筛选邻近对象，再按距离和重要性分层更新。视线检测可以分帧，远处单位降低频率，关键事件通过消息直接唤醒。

AI 应读取游戏允许它知道的信息，而不是直接遍历玩家组件。最后看见位置、声音方向和估计威胁都带不确定性与过期时间。这样既便于公平性控制，也便于调试“AI 为什么知道玩家在这里”。

## MCTS

Monte Carlo Tree Search 反复执行 Selection、Expansion、Simulation、Backpropagation。Selection 常用 UCT 平衡已知收益与探索：

$$UCT_i=\bar X_i+C\sqrt{\frac{\ln N}{n_i}}$$

$\bar X_i$ 是子节点平均收益，$N$ 是父节点访问次数，$n_i$ 是子节点访问次数。$C$ 越大越偏探索。Expansion 添加未尝试动作，Simulation 用简化策略推演，最后把结果沿路径回传。

UCT 是 UCB 思想在树搜索中的应用。PUCT 再引入策略网络给出的先验概率，让高先验动作更早得到探索，同时仍随访问次数调整探索奖励。先验只能引导搜索，最终质量仍取决于模拟、价值估计和访问预算。

MCTS 适合规则可模拟、分支较大且无法预先写出完整评估的决策。其质量依赖状态复制成本、模拟速度和奖励设计。实时游戏要限制迭代数或时间，使用固定随机种子时才能稳定重放。隐藏信息游戏还需避免在模拟中偷看真实状态。

先测量单次模拟耗时，再确定实时预算允许的迭代数。搜索质量随预算变化的曲线依赖游戏、模拟策略和局面，需要用固定测试集测量，不能预设统一的对数增长规律。

隐藏信息的一种近似是确定化采样：从当前信息允许的完整状态中采样，再分别搜索并汇总结果。它容易产生策略融合，例如把不同隐藏状态下各自可行的动作组合成实际无法执行的策略。应与信息集搜索对比，并检查是否使用了决策者无法观察的信息；偏差方向由具体游戏决定。

## MDP、Policy 与 Value

Markov Decision Process 用状态 $s$、动作 $a$、转移概率和奖励描述序列决策。Policy $\pi(a|s)$ 决定在状态下选什么动作。Value $V(s)$ 表示状态的期望累计回报，$Q(s,a)$ 表示执行某动作后的期望回报。未来奖励通常乘折扣 $\gamma$：

$$G_t=r_{t+1}+\gamma r_{t+2}+\gamma^2 r_{t+3}+\cdots$$

$\gamma$ 接近 0 更重眼前，接近 1 更看长期。真实游戏很少满足完整可观察和理想 Markov 假设，因此状态表示和记忆机制同样重要。

## 强化学习管线

训练前先定义 Observation、Action Space、Reward、Episode 终止条件和课程难度。Observation 不应包含上线时拿不到的信息；Action 最好接入已有角色控制接口，而不是让网络绕过物理与规则。

Reward Shaping 最容易制造“看起来在学习、实际钻规则漏洞”的结果。奖励应接近真正目标，并通过日志检查各分量。

经典反例能说明为什么必须逐分量检查：奖励“前进距离”可能学到原地翻滚刷位移，奖励“存活时间”可能学到站进角落不动，奖励“击杀”可能学到故意放残血对手逃跑再追。总回报曲线上升而目标分量（例如真实击杀数、占点时间）不动，就是在钻规则漏洞。每个分量单独画曲线、单独设上限，异常分量的权重变化要写进训练日志。训练、验证和压力场景要分开；模型版本、环境版本、随机种子和指标一起记录，才可能复现。

学习模型适合难以手写的连续控制或复杂策略，但它不是免费智能。推理成本、平台差异、量化误差、确定性和失败回退都要在部署前验证。竞技玩法尤其要确认模型不会获得玩家不可见的信息。

## 神经网络与学习方式

MLP 由全连接层组成，适合固定长度状态向量；CNN 通过局部卷积和共享权重处理图像或网格；RNN 把历史状态递归传递，LSTM 用门控缓解长序列中的梯度和记忆问题。网络结构应匹配输入的空间、时间结构，层数更多并不自动带来更好的游戏行为。

监督学习从带标签样本学习输入到目标输出；模仿学习从专家轨迹学习策略，但会受到分布偏移影响；强化学习通过与环境交互、累计奖励学习决策。三者可以组合，例如先模仿得到可用策略，再用强化学习微调。

AlphaGo 结合策略网络、价值网络与 MCTS；AlphaZero 用自我博弈替代人类棋谱；AlphaStar 面向部分可观察、长时序和巨大动作空间，使用联盟式训练与序列模型。这些案例说明模型、搜索、训练分布和环境接口需要共同设计，不能只抽取一个算法名称套用到实时游戏。

## 混合架构

可靠做法通常是规则系统守住边界，学习或搜索只处理有限选择。例如行为树控制战斗流程，Utility 选择战术目标，RL 只输出局部移动参数。权威游戏规则、伤害结算和资源消耗仍由确定性系统验证。

LLM 可用于离线生成候选对白、规划草案或把自然语言转成受限指令，但不应直接拥有场景任意操作权。输入先压缩成允许暴露的事实，输出经过 Schema、白名单和规则校验；超时或不可用时必须有传统逻辑回退。它是受约束的辅助层，不是权威决策者。

## 验证方法

评价 AI 不能只看胜率。还要记录单帧预算、决策延迟、行为分布、失败率、玩家感知公平性和不同硬件的一致性。自动比赛能发现统计问题，具体异常仍需可视化感知、候选动作、搜索树或模型输入输出。

上线内容最好支持固定种子回放和离线重算。若算法无法完全确定，就记录足够的决策结果用于复盘，并把非确定性限制在不影响权威结算的位置。

- 感知公平性审计：断言 AI 的一切查询都经过感知系统；抓取一局内 AI 实际使用的信息集合，确认不含玩家不可见信息（精确血量、视野外位置）。
- Influence Map 守恒检查：没有新源写入时，全图总影响力应随扩散轮数单调衰减；出现增长说明扩散算子不守恒，边界复制错误是最常见原因。
- MCTS 扩展性：固定局面下迭代数按十倍递增跑自博弈，确认胜率曲线存在拐点；固定种子重放同一局面必须输出同一动作。
- RL 部署前清单：真机实测推理耗时、量化前后行为对比、无效动作掩码生效、环境异常时规则回退接管。
- 群体压测三场景：对冲、过窄门、环形围堵，统计死锁次数、振荡频率与完成时间，作为避障与队形参数改动的回归基线。
- 可复现归档：模型版本、环境版本、种子与超参同日志一起保存，同一组合重跑应得到一致的指标分布。

### MCTS 的 UCT 选择

选择阶段从已展开子节点中平衡平均回报和探索。父节点访问次数必须大于零，未访问子节点优先展开：

```cpp
Node* SelectChildUct(Node& parent, float exploration)
{
    Node* best = nullptr;
    float bestScore = -Infinity;
    for (Node& child : parent.children) {
        if (child.visits == 0) return &child;
        float exploit = child.totalValue / child.visits;
        float explore = exploration
            * Sqrt(Log((float)parent.visits) / child.visits);
        if (exploit + explore > bestScore) {
            bestScore = exploit + explore;
            best = &child;
        }
    }
    return best;
}
```

回报视角必须统一：双人零和游戏在回传层级切换时常需要翻转符号。探索系数依赖回报量纲，不能跨项目直接照搬。用固定随机种子记录每次选择分数、访问次数和最终动作，能复现树搜索偏差。
