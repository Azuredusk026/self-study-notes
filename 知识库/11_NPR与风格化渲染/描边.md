# 描边

描边把物体轮廓、折角或指定结构画成线。输入可以是模型几何，也可以是屏幕上的深度、法线和对象遮罩。选方案时先决定要画哪种边，再看可用数据和线宽要求。

## 轮廓从哪里来

外轮廓把物体与背景分开，内部线描述折角、材质分界或手绘细节。立方体的可见外轮廓随相机转动，而棱线来自相邻面的方向差异。衣服缝线可能只存在于贴图或顶点数据中，几何和深度都无法直接推断它。

| 要画的线 | 可用信号 | 典型限制 |
|---|---|---|
| 外轮廓 | 扩张几何壳、对象遮罩边界、深度差 | 开放网格、遮挡和分辨率影响结果 |
| 折角 | 相邻面夹角、几何法线变化 | 平滑法线和法线贴图会改变检测结果 |
| 材质或对象分界 | 离散ID、材质遮罩 | 同ID接触面需要额外信息 |
| 艺术指定细节 | 手绘线、SDF、顶点权重 | 依赖资产制作与采样精度 |

一个材质可以同时使用几何壳画外轮廓，用贴图画衣服结构线，再用屏幕检测补场景接触边。各方法的输出应分别可视化，方便判断是哪种信号引入了错误线条。

## 几何壳描边

### 沿法线外扩，再绘制背面

额外画一次模型，把顶点向外移动并输出描边色。描边通道剔除正面，只画扩张壳的背面。对于闭合网格，背面大多处于原表面后方，深度测试挡住中间部分，露出的边缘形成轮廓。

最简单的对象空间外扩是：

$$\mathbf p'_{OS}=\mathbf p_{OS}+w_{OS}\hat{\mathbf n}_{OS}$$

`wOS`的单位与模型坐标相同。模型放大后轮廓也会变宽；透视相机中，远处模型的像素线宽会变细。这条路径适合先验证剔除、深度和轮廓方向。

最小状态为 `Cull Front`、`ZWrite Off`、`ZTest LEqual`，在不透明本体完成后绘制。深度关系仍受凹面、开放边界、自交和宽度影响。壳与别的物体接近时，先保持真实深度测试，再检查外扩是否越过了前方表面。

### 先解决硬边裂缝

硬边处会出现裂缝，因为同一个位置通常存在多个法线不同的顶点。沿各自法线外扩后，这些顶点会向不同方向移动，于是原本相连的轮廓被拉开。

给描边单独准备外扩方向，让同一轮廓接缝上的顶点共享方向，原着色法线仍负责光照。烘焙时在对象空间分组，分组条件同时考虑位置容差和拓扑所属；两块独立表面恰好相交时，位置相同也未必应焊接。

#### 权重累加完成后再归一化

同组方向采用加权和：

$$\mathbf n_{outline}=\operatorname{normalize}\left(\sum_i a_i\mathbf n_i\right)$$

面积权重能减少小三角形重复贡献，角度权重能减少局部重划分的影响。输入应来自所选面片的法线与权重；把已拆分顶点的法线直接累加，相当于选择了另一种权重，需要知道重复顶点如何产生。

下面是可运行Python参考函数，输入为同组方向和非负权重。累加后只归一化一次，交换遍历顺序得到相同结果。

```python
def smooth_group(normals, weights):
    total = tuple(sum(n[axis] * w for n, w in zip(normals, weights))
                  for axis in range(3))
    length = sum(value * value for value in total) ** 0.5
    if length < 1e-12:
        raise ValueError("无法确定外扩方向")
    return tuple(value / length for value in total)
```

完整参考实现检查输入长度和权重，见 [reference.py](../examples/outline/reference.py)。输入三个互相垂直的单位方向时，结果为归一化后的`(1,1,1)`。如果每次加一项就归一化，后加入的方向会改变前面累计量的权重，结果随顺序变化。

#### 数据通道与蒙皮

| 存储方式 | 前提 | 要检查的代价 |
|---|---|---|
| 顶点色 | 选择8位或浮点格式，确认原有遮罩用途 | 方向量化、顶点带宽、通道占用 |
| UV属性 | Unity `SetUVs`支持索引0–7与2/3/4分量 | 布局与精度；两分量可用八面体编码 |
| 切线 | 资产不使用该通道的法线贴图契约 | 与切线、手性和导入处理冲突 |
| 独立缓冲 | Shader能按顶点或实例索引读取 | 绑定、索引一致性和生命周期 |

量化后的方向要重新归一化。8位颜色能否满足线宽和精度需求，用近景斜边和高曲率网格验证，不能仅凭格式大小判断。

静态对象空间方向跟随对象变换。蒙皮角色需要让描边方向随骨骼姿态变形；把静态方向存在UV里并不会自动完成蒙皮。可保存切线空间方向，再用变形后的基底还原，或明确对该方向做蒙皮。非均匀缩放时，法线变换使用逆转置并归一化。

每级LOD分别烘焙，检查轮廓形状和属性布局。自动导入步骤记录算法、容差、权重和版本，资产重导入后能够复现同一外扩数据。

### 让宽度以像素计

裁剪坐标除以`clip.w`才得到NDC。想在屏幕上移动`k`个像素，就先将像素位移换成NDC，再乘回`clip.w`：

$$\Delta\mathbf p_{clip,xy}=\left(\frac{2k d_x}{W},\frac{2k d_y}{H}\right)p_{clip,w}$$

`(dx,dy)`是像素空间单位方向，`W,H`是当前渲染目标尺寸。宽度因此与目标像素关联；升采样后的显示像素还要按分辨率比例换算。

```hlsl
float4 OffsetOutlinePixels(float4 clipPosition, float2 pixelDirection,
                           float widthPixels, float2 renderSize)
{
    float lengthSquared = dot(pixelDirection, pixelDirection);
    if (lengthSquared < 1e-8)
        return clipPosition;
    float2 direction = pixelDirection * rsqrt(lengthSquared);
    clipPosition.xy += direction * (2.0 * widthPixels / renderSize)
                       * clipPosition.w;
    return clipPosition;
}
```

这是API中立HLSL片段，调用者先构造像素方向。例如把外扩方向变到视空间，使用投影矩阵的XY线性部分投影，再按目标宽高换算为像素方向。对普通无斜切的透视/正交矩阵，这能作为稳定的方向近似。法线朝向相机时，XY方向趋近零，函数直接跳过偏移；附近仍可能出现宽度不连续。

位移幅度在数值上可保持固定像素，但壳的几何覆盖不是严格的二维轮廓膨胀。模型角点、投影变形和遮挡仍需检查。需要严格屏幕形状时，改用遮罩膨胀。远景还可给宽度设置距离衰减与上下限，避免小物体被粗线覆盖。

### 深度与模板控制

#### 深度偏移改变可见性

把壳沿视方向推远，或者使用光栅深度偏移，能减少壳与本体的局部冲突。两种操作改变的数据不同：视空间位移改变投影深度；光栅偏移依据深度斜率和设备深度分辨率调整测试值。[Unity Offset](https://docs.unity3d.com/6000.0/Documentation/Manual/SL-Offset.html)与[Vulkan深度偏移](https://docs.vulkan.org/spec/latest/chapters/primsrast.html#primsrast-depthbias)给出各自语义。

偏移过大会让本来靠后的物体穿过轮廓，Reversed-Z和不同API也会改变符号与数值条件。调参时保留前后遮挡物，检查本体、壳和遮挡物的深度。裁剪空间Z的数值不能直接当作统一的距离衰减。

#### 模板记录本体覆盖

先让本体在通过深度测试的像素写入保留的模板位，再画壳，只允许该位为零的区域通过。下面是ShaderLab状态示意，假设位`0x10`由描边独占，已在当前相机合适阶段清零，且没有其他通道覆盖它。

```text
// 本体通道
Stencil { Ref 16 ReadMask 16 WriteMask 16 Comp Always Pass Replace }
// 壳通道：读取标记，保留模板内容
Stencil { Ref 16 ReadMask 16 WriteMask 0 Comp NotEqual Pass Keep }
```

多对象共用一位时，本体覆盖会形成联合遮罩。两个对象重叠，内部遮挡线可能被一起排除。要保留对象差异，可逐对象清理与绘制，或者使用对象ID和深度定义所需边界。对象ID占用有限位数，不能只换一个`Ref`值就保证所有遮挡关系正确。

模板分配还要与延迟光照、UI遮罩和其他效果协调，通用比较和写掩码见 [[02_GPU与光栅化管线/模板缓冲、位分配与对象遮罩]]。来源文章的重叠对比是具体场景观察，不能证明一个状态组合适用于所有对象顺序。

### 图元生成的另一条路径

有网格邻接信息时，可以先找满足轮廓条件的边，再为边生成线段或四边形。相邻面的朝向符号不同是候选条件之一，最终仍要处理遮挡和线段连接。几何着色器、离线预处理或Compute可承担生成，选择取决于API、邻接数据和几何放大量。

这条路径能给线段独立宽度、UV和端点属性，同时增加邻接维护、接缝与输出预算问题。阶段机制见 [[02_GPU与光栅化管线/几何着色器、曲面细分与流输出]]，硬件成本按目标平台测量。

## 结构线与表面边缘

### 手绘线、SDF与顶点权重

衣服缝线、发束分界和面部细节可直接由美术指定。线纹理在近景会暴露采样锯齿，远景又受Mip过滤影响。SDF保存到线边界的距离，Shader用阈值控制宽度，再用导数平滑边缘；输入距离的尺度和Mip生成规则需要保持一致。

把SDF或宽度权重存在顶点属性中可以减少纹理依赖，但线条形状受网格分辨率和插值限制。UV岛边界也可以生成线，不过UV接缝未必就是画面需要的结构边。离线生成前先定义线的语义。

### 法线与视线夹角

侧面的法线与视线点积趋近零，可以让这部分表面出现窄色带：

```hlsl
float ndotv = saturate(dot(normalize(normalWS), normalize(viewDirWS)));
float rimMask = 1.0 - smoothstep(rimLow, rimHigh, ndotv);
```

输入是同一世界空间的单位方向，阈值满足`rimLow < rimHigh`。这画的是表面掠射区域：球体可形成边缘带，平面转向侧面时可能整面变色。法线贴图也会改变区域，因此它适合材质边缘效果，需要精确外轮廓时使用几何或遮罩信号。

## 屏幕空间描边

屏幕方法先读场景缓冲，找相邻像素的数据差异，再把边缘遮罩合成到颜色。它能补内部折角，线宽直接跟像素相关，但只能利用缓冲中确实存在的信息。

![屏幕描边的数据依赖](../assets/outline/screen-flow.svg)

图：深度、法线和对象ID各自生成边缘，按Mask控制后合成。图表达数据依赖；实际通道是否合并、资源何时驻留由引擎与API决定。

### 深度不连续

先把设备深度还原为正的视空间距离。比较中心和邻居，使用相对差值降低远近尺度变化：

```hlsl
float OutlineRelativeDepth(float centerDepth, float neighborDepth,
                          float minimumScale)
{
    return abs(neighborDepth - centerDepth)
           / max(min(centerDepth, neighborDepth), minimumScale);
}
```

阈值无单位，`minimumScale`与视空间距离使用相同单位。深度斜面本身也有梯度，这个函数只改善距离缩放，无法独自区分表面倾斜和物体断层。斜面校正、法线或ID组合可以减少地面误判；背景无有效深度时先用覆盖标记处理。

横竖差分容易对方向敏感，可选Sobel等邻域算子。采样距离与线宽相关，轮廓膨胀与边缘检测最好分清：前者扩展已有遮罩，后者寻找不连续。深度约定与重建见 [[02_GPU与光栅化管线/深度缓冲、反向深度与位置重建]]。

### 法线不连续

单位法线点积等于夹角余弦，用`1-dot(N0,N1)`衡量变化。平滑法线会减弱折角，高频法线贴图会引入细碎线。缓冲保存几何法线还是着色法线，决定检测到的是结构还是表面细节。

```hlsl
float OutlineNormalEdge(float3 centerNormal, float3 neighborNormal)
{
    return 1.0 - clamp(dot(normalize(centerNormal), normalize(neighborNormal)),
                       -1.0, 1.0);
}
```

相同方向得到零，反向得到二。解码和空间约定要一致，法线变化阈值通过已知夹角网格校准。边缘处相邻样本可能属于背景，需要先检查覆盖和深度有效性。

### 对象遮罩与ID

单独渲染选中对象为二值遮罩`M`，膨胀后减去原遮罩，得到外侧轮廓：

$$O=\max(\operatorname{dilate}(M)-M,0)$$

模糊遮罩减原遮罩会形成软边，膨胀核则明确控制像素半径。方形核在角点形成方形扩张，圆形核更接近径向线宽。两者成本与形状不同，按轮廓目标选择。

![遮罩膨胀与相减](../assets/outline/mask-dilation.svg)

图：CPU参考算法的11×11二值输入、半径1方形核膨胀及差值。输入为5×5方块，轮廓占24个像素。它是算法结果图，Shader与抗锯齿后的结果仍需独立验证。

多对象共用遮罩时只得到联合边界。需要对象间线条时比较离散ID，并用深度定义遮挡关系。ID使用整数或明确的离散编码和点采样，线性过滤会混合类别。MSAA resolve与TAA历史也要考虑ID不能按普通颜色平均。

被遮挡对象描边需要独立遮罩或Custom Depth，因为场景最近深度没有后方对象的信息。透视线与普通遮挡线使用不同的可见性规则，图注和参数应让读者明确目标。

### 放在时域处理的哪个位置

TAA前绘制可让线条参与历史累积，也可能拖影；TAA后绘制能保留锐利线，却更依赖输入深度、法线是否已对齐。抖动、渲染分辨率和最终显示尺寸的变化会让一像素线跳动。

让边缘输出、运动向量与历史校验使用同一坐标约定。对移动细线、遮挡揭露、相机旋转和动态分辨率分别测试，具体流程见 [[02_GPU与光栅化管线/抗锯齿、TAA与时域超采样]]。深度历史、ID与颜色历史承担不同数据语义。

## 方案选择与工程代价

| 方案 | 擅长的目标 | 主要成本与限制 |
|---|---|---|
| 几何壳 | 模型外轮廓、逐顶点控制 | 额外Draw、顶点、蒙皮和覆盖；开放网格、凹面需处理 |
| 显式边几何 | 线段UV、端点和折角控制 | 邻接数据、连接规则、输出规模和平台支持 |
| 手绘/SDF | 精确的艺术结构线 | 资产制作、UV、距离尺度和过滤 |
| 深度/法线检测 | 场景边界和折角 | 全屏采样、噪声、最近表面信息限制 |
| 遮罩/ID | 选中轮廓、对象边界 | 额外数据通道、离散分类与遮挡定义 |
| 掠射色带 | 材质表面边缘效果 | 受法线和视角影响，轮廓形状有限 |

线宽可以按外部/内部、距离、材质、曲率或艺术权重调整。这些是风格参数，需要参考目标画面校准；等宽轮廓和有粗细变化的线都可能适用。先确定外轮廓，再逐步加入内部线，能避免高频信息淹没主体。

壳描边的成本包括重复绘制、蒙皮、顶点变形、透明裁剪和Submesh。屏幕方案增加纹理读取与中间目标，也可能额外生成ID或遮罩。测量时记录线条覆盖、Pass、尺寸与格式，局部通道成本和整帧成本分别观察。

### 本机参考实验

仓库根目录执行：

```powershell
python 知识库/examples/outline/reference.py --out 知识库/examples/outline/build
dxc -T vs_6_0 -E OutlineVS 知识库/examples/outline/CompileProbe.hlsl -Fo 知识库/examples/outline/build/outline-vs.dxil
dxc -T ps_6_0 -E OutlinePS 知识库/examples/outline/CompileProbe.hlsl -Fo 知识库/examples/outline/build/outline-ps.dxil
```

Python需要3.10以上，仅使用标准库。它生成`mask.pgm`、`outline.pgm`与结果JSON，验证法线顺序、权重、像素尺度、遮罩边界和深度比例。HLSL编译探针使用列向量矩阵约定，只验证API中立函数的编译；数据绑定、渲染目标和绘制状态由实际工程提供。

本轮验证状态与工具版本见下方“证据范围”。读者重复实验时保留自己得到的结果和环境，参考测试不替代目标网格与引擎验证。

### Unity 6 URP接入路线

环境范围为Unity 6000.0、URP17、Universal Renderer，使用[Render Objects Renderer Feature](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/renderer-features/renderer-feature-render-objects.html)。完整Shader见 [StaticHull.shader](../examples/outline/StaticHull.shader)，只使用原法线与对象空间宽度，先验证静态闭合网格。

1. 将Shader复制进测试项目，创建使用该Shader的描边材质。球体与立方体使用普通不透明材质，并放入单独Layer。
2. 在相机使用的Renderer Data中添加Render Objects，事件设为`AfterRenderingOpaques`，筛选该Layer与Opaque。若设置Pass Names，匹配测试本体Shader的LightMode。
3. Override Mode选择Material，指定描边材质。深度和模板覆盖先关闭，让Shader内的`Cull Front`、`ZWrite Off`、`ZTest LEqual`生效。
4. 从小的`_OutlineWidthOS`开始，确认原模型正常绘制，额外通道只输出壳。相机靠近和远离时，像素宽度应变化。
5. 用Frame Debugger定位额外Draw，检查材质、剔除和深度状态。球体通常连续，硬边立方体暴露裂缝；随后接入独立平滑方向再比较。

此路线按官方功能文档组织。`StaticHull.shader`尚未在Unity完整工程中导入编译或运行，目标补丁和URP包版本需记录。多相机、XR、MSAA、蒙皮、负缩放与透明对象属于进一步验证范围，通用图通道接入见 [[13_引擎架构与资源系统/Unity Render Graph与自定义通道]]。

### 故障与回归

| 症状 | 先检查 | 验证或修法 |
|---|---|---|
| 整个物体变成描边色 | 本体Draw、Cull、深度与顺序 | 单独显示本体/壳，确认原深度写入 |
| 硬边裂缝 | 重合顶点方向和焊接归属 | 输出方向RGB，比较组内方向 |
| 动画时轮廓脱离 | 独立方向是否变形、Pass是否共用动画 | 静态姿态与极端关节姿态对照 |
| 远景粗线盖住细物体 | 像素线宽与显示/渲染尺寸 | 加宽度上下限，验证不同render scale |
| 地面满是轮廓 | 深度编码、斜面梯度与阈值 | 分别输出深度、法线、ID检测结果 |
| 对象重叠处线消失 | 联合遮罩、模板位与对象顺序 | 独立ID和深度对照，明确要画的边 |
| TAA拖影或抖动 | 注入阶段、运动向量和历史拒绝 | 固定相机、移动物体、遮挡揭露分别测 |

性能回归保持相机、构建、分辨率与网格一致。分别关闭壳、屏幕检测、内部线和ID生成，确认耗时变化来自实际执行路径。设备、驱动和统计窗口与结果一起保存。
