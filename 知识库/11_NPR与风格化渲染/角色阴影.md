# 角色阴影

刘海投影既要跟随头发，也要保持脸部可读。普通Shadow Map、专用遮罩、屏幕偏移和射线求交保存的信息不同。我们先确定投影对象和消费者，再按角色距离、平台与画面档位选择。

## 角色遮挡与阴影

### 头发投脸阴影

Face SDF 只描述脸部自阴影，不能准确处理刘海。头发投影可以使用：

- 普通 Shadow Map；
- 单独 Hair Shadow Pass，把头发深度/Mask 投到 Face；
- Screen-space Offset Shadow；
- 美术绘制的固定 Hair Shadow Mask。

Shadow Map 物理关系较完整，但 Bias、分辨率和 PCF 会影响细线。Screen-space Offset 便宜且可控，却会随 FOV、头部旋转和遮挡穿帮。

专用 Hair Shadow Pass 可以只让头发写入角色局部 Shadow Mask，再由脸材质采样。需要用 Stencil/ID 防止投到场景或其他角色，并处理透明发片与 Alpha Clip。

#### 深度偏移法

延迟路径下有一种成本很低的做法：在计算面部着色时，把当前像素的屏幕坐标沿光照方向偏移一段，采样偏移处的深度，若该处存在头发（靠材质分类 ID 判断）且深度更近，就判定当前像素处于刘海投影中。

它的本质是在屏幕空间做一次单步的光线步进。前提是能够区分头发与面部——这正是材质分类 ID 或专用 Buffer 的用途。

三个必须处理的问题：偏移量需要随深度缩放，否则远处角色的投影会过大；偏移方向应来自光方向在屏幕空间的投影，而非固定方向；单次采样会产生硬边，需要多次采样或与 SDF 结果混合。

穿帮场景是可预期的：头发被其他物体遮挡时深度信息丢失；侧面视角下屏幕空间偏移与真实几何关系脱节；FOV 变化会改变偏移的视觉尺度。

#### 光追投影

支持硬件光追时，可以从面部像素向光源发射阴影射线，只与头发几何求交。它使用实际头发几何求可见性，减少Shadow Map分辨率和离屏信息缺失的问题；薄发片、Alpha处理、自相交与低样本噪声仍需限定。

代价很直接：需要为角色维护加速结构、每帧更新蒙皮后的几何、承担光追本身的性能与硬件门槛。通常只在高配档位启用，低配回退到深度偏移或 Shadow Map。

#### 方案对照

| 方案 | 准确性 | 成本 | 主要问题 |
|---|---|---|---|
| 普通 Shadow Map | 几何正确 | 中 | Bias 与分辨率影响细发 |
| 专用 Hair Shadow Pass | 几何正确、可控 | 中 | 需要额外 Pass 与分类 |
| 深度偏移 | 近似 | 低 | 视角与遮挡穿帮 |
| 模板偏移 | 近似 | 低 | 同上，且形状受模板精度限制 |
| 美术绘制 Mask | 完全可控 | 极低 | 不随光照变化 |
| 光追 | 几何正确 | 高 | 硬件门槛与加速结构维护 |

选择取决于画面档位与角色重要性。可以按角色重要性与平台预算分档，实际成本和画质在同一场景比较。

### 角色Shadow Map

PCF/PCSS的滤波与半影机制见 [[05_光照阴影与GI/Shadow Map]]。角色页只选择过滤尺度、Bias区域和艺术重映射。

角色 NPR 不一定追求物理软阴影。常用控制：

- 固定或量化 Filter Radius，保持动画片色块；
- 给脸、头发和身体不同 Bias；
- 用 Shadow Ramp 重映射可见性；
- 限制自阴影区域；
- 主光使用高质量阴影，附加光不产生复杂色块。

Bias 过大造成 Peter Panning，过小产生 Acne。Normal Bias 还会让细脸和发片轮廓偏移，必须近距离检查。

## 验证方法

分别显示头发遮罩、角色局部深度与最终阴影，测试侧视、被遮挡头发和FOV变化。通用PCF/PCSS与Bias机制以Shadow Map为主归属，角色页只说明过滤尺度和区域控制。
