# 学习与维护方法

## 定向检索

Obsidian 搜索正式知识时使用：

```text
path:"知识库" 关键词
```

日常阅读从正式知识开始。正文中的相关主题链接用于继续学习。本机维护来源用于核对原始语境、例子和实现细节。

## 怎么读一篇笔记

先找到这项技术解决的问题，再看它如何改变数据或执行流程。遇到公式时，先确认变量代表什么，不需要先背公式。

读完后至少能用自己的话回答：

- 它解决什么问题？
- 核心机制是什么？
- 成本转移到了哪里？
- 哪些条件下会失效？
- 在引擎或帧捕获中能看到什么证据？

这些问题用于检查理解，不需要变成固定的文章章节。

## 怎么补充知识

### 先找到正确归属

不要看到一个新术语就创建文件。先检查它是否属于现有主题中的一个小节。

例如 Anisotropic Filtering 应该进入“纹理采样、过滤、Mipmap 与压缩”，而不是单独建立页面。

### 先修正关系，再增加细节

如果一个概念已经存在，但与上下游技术没有联系，应先补清楚关系。例如讲 PCSS 时，需要先说明 Shadow Map 的深度比较、PCF 过滤和光源尺寸，而不是直接增加采样代码。

### 区分三种内容

- **已核验事实**：规范、官方文档、源码、论文或可靠技术演讲可以支持。
- **解释和推导**：为了帮助理解而重新组织的说明。
- **实践记录**：某个版本、平台或项目中的观察结果。

实践记录不能直接当成所有引擎和硬件都成立的规则。

## 来源优先级

1. 图形 API 规范、引擎官方文档和源码。
2. 论文、SIGGRAPH/GDC 等正式技术演讲。
3. GPU 厂商和平台官方资料。
4. 有完整推导或实验的技术文章。
5. 课程笔记、视频转录和个人总结。

课程笔记适合提供解释线索，但底层细节仍需要更可靠的来源核验。

## 代码示例怎么写

代码用于说明算法的关键数据流。适合加入正文的内容包括空间变换、资源读写、采样循环、索引计算、同步边界和核心公式。窗口创建、资源路径、错误处理等工程样板可以放在来源工程中查阅。

一段示例通常控制在 8–25 行，并满足这些条件：

- 代码块标明 `glsl`、`hlsl`、`cpp`、`csharp` 或其他准确语言；
- 代码前说明输入、输出、坐标空间、资源格式和必要前提；
- 代码中的变量名称与正文公式保持一致；
- 代码后解释执行顺序、成本和可观察的错误现象；
- 示例包含一个可以独立完成的验证方法。

跨 API 的算法优先给出 API 中立伪代码或一个最小 Shader 函数。涉及资源绑定、内存布局和同步语义时，再补充对应 API 或引擎写法。示例只保证表达当前机制，完整工程所需的状态创建和生命周期管理仍由正文说明。

引用外部代码时保留来源名称、章节或源码路径，并确认许可证允许当前使用方式。知识库采用重新组织和改写后的最小示例。代码来自个人实验时，记录运行环境和验证结果。

### 全库示例覆盖检查

每篇适合代码化的正式知识文章至少包含一个关键示例。示例可以是 Shader、C++、C#、Python、命令、配置、数据结构定义或伪代码。导航页、术语表和纯概念索引不强制加入代码。

示例需要交代与理解机制直接相关的前提：

- 输入、输出和数据单位；
- 坐标空间、资源格式或对象生命周期；
- API 状态、同步条件或调用顺序；
- 省略的工程样板和适用边界。

代码后的解释需要沿执行顺序说明关键步骤，并给出至少一种可观察的错误现象或验证方法。示例覆盖检查关注知识文章是否具备连接概念和工程的入口，不以代码块数量衡量文章质量。

## 如何处理不确定内容

没有足够证据时直接标记：

> [!warning] 待补充
> 当前资料不足以确认这一实现是否适用于所有引擎版本或 GPU。

不要用“通常应该”“大概就是”补齐缺失机制。

## 双链怎么使用

Obsidian 仓库根目录为 `知识库/`。双链从编号目录开始书写，例如 `[[06_纹理技术/纹理采样、过滤、Mipmap与压缩]]`。

双链只连接真正有帮助的关系：

- 前置知识；
- 数据或执行依赖；
- 容易混淆的对照技术；
- 后续可以继续深入的主题。

正文已经能自然说明的普通名词不必全部链接。

## 什么时候拆分文章

满足以下情况之一时再考虑拆分：

- 两部分解决的问题完全不同；
- 阅读顺序已经无法自然组织；
- 一部分可以独立维护，并且有大量自己的来源和下游链接；
- 修改一个部分时经常误触另一个部分。

标题层级多、篇幅长并不自动代表必须拆分。

## 模块完成检查

- 是否只写了定义，没有解释机制？
- 是否把性能收益说清楚到 CPU、GPU、带宽、内存或延迟？
- 是否混淆了 API 用法和底层原因？
- 是否存在没有来源的引擎内部结论？
- 是否有可以合并的重复说明？
- 是否可以通过一个小实验、Profiler 或帧捕获验证？
