# 渲染图、依赖编译与资源调度

渲染图（Render Graph，也称 Frame Graph）把一帧表示为通道与资源的依赖关系。输入是每个通道的资源访问声明，输出是可以提交给 GPU 的执行计划。图编译器管理资源分配和同步，通道回调负责具体绘制或计算。

## 从声明到执行

```text
记录通道与逻辑资源
  → 建立读写依赖和资源版本
  → 从可观察输出反向标记有效通道
  → 安排执行顺序与队列
  → 计算资源使用区间和物理分配
  → 生成转换、屏障及跨队列同步
  → 执行回调并提交命令
```

这是典型流程，具体引擎可能合并部分步骤。记录阶段的资源句柄代表逻辑资源，尚不保证已有物理纹理。执行回调时才应使用图提供的资源和命令接口。

## 资源版本和依赖

一个纹理可以经过多次写入。图必须区分初始内容、第一次写后的内容和后续版本，否则无法判断读取依赖哪次写入。实现可以采用显式版本句柄，也可以维护最后写入者与当前读取者集合。

三个基本约束是：写后读等待写入完成；读后写等待之前的读取结束；写后写保持覆盖顺序。读后读通常可以并行，但布局、队列归属或图形 API 的状态限制可能要求额外处理。声明的是实际访问类型和子资源范围，单写一个“使用纹理”不足以生成正确同步。

## 通道剔除

从呈现颜色、导出资源和明确的外部副作用反向追踪依赖，只保留可达通道。例如生成一张从未采样的模糊纹理，没有其他副作用时可整段剔除。

写外部纹理、异步回读和查询统计可能是可观察副作用。应按引擎约定声明，不能仅以“后面没有读者”判断通道必然被剔除。关闭剔除适合诊断，生产路径应表达真实的输出依赖。

## 最小依赖示例

以下为 API 中立伪代码，输入是已有的场景颜色，输出是呈现颜色。资源描述符包含尺寸和格式，访问标记区分采样与颜色写入。

```text
scene = graph.Import(sceneColor)
half = graph.CreateTexture(halfSize, RGBA16F)
blurred = graph.CreateTexture(halfSize, RGBA16F)
output = graph.Import(presentColor)

graph.AddPass("Downsample")
    .Read(scene, Sampled)
    .Write(half, ColorAttachment)
    .Execute(DrawDownsample)
graph.AddPass("Blur")
    .Read(half, Sampled)
    .Write(blurred, ColorAttachment)
    .Execute(DrawBlur)
graph.AddPass("Compose")
    .Read(scene, Sampled)
    .Read(blurred, Sampled)
    .Write(output, ColorAttachment)
    .Execute(DrawCompose)
graph.MarkOutput(output)
graph.CompileAndExecute()
```

删除 `Compose` 对 `blurred` 的读取后，模糊链没有可观察输出，两个通道可以一起消失。重新声明读取后，纹理内容转换和写后读屏障由图恢复。该实验检查声明是否参与依赖编译。

## 生命周期与别名复用

逻辑资源的使用区间从首次有效访问到最后一次访问。两个尺寸和分配约束兼容、使用区间不重叠的资源可能共享物理内存。是否实现真正的堆别名、纹理池复用或其他优化，要看引擎分配器。

异步计算引入部分有序的时间线。图中两个资源的节点编号不同，不足以证明它们在 GPU 上不重叠；分配器必须考虑跨队列依赖。别名切换还可能需要专用屏障或状态初始化。首次读取未初始化内容属于声明错误，应先清除或完整写入。

历史纹理跨帧存在，应作为外部资源导入并维护帧完成条件。把历史伪装成帧内临时资源，会导致重建内容丢失或内存复用冲突。

## 调度与合并

拓扑排序只保证依赖合法，不能保证最快。队列选择、通道合并、内存峰值和同步开销会互相制约。把计算移到异步队列可能增加重叠，也可能增加等待和资源存活时间。

Tile GPU 上，兼容的图形通道可以保留附件在片上。采样邻域、不同尺寸附件、必要的外部副作用等操作可能阻止合并。渲染图提供分析条件，实际合并结果由具体实现与 API 支持决定。

## 引擎对应

Unity 6 URP 在 `RecordRenderGraph` 中记录资源和回调，使用 `TextureHandle`、访问声明及 `RasterGraphContext`。Unreal 使用 `FRDGBuilder`、通道参数结构和 RDG 资源句柄。两者都需要准确描述资源访问；接口细节见独立实现页。

## 验证方法

1. 给测试通道唯一名称，在图查看器和 GPU 捕获中定位输出及消费者。
2. 去掉最终读取，检查无副作用通道是否被剔除。
3. 禁用别名复用，与正常路径比较输出；差异提示初始化或生命周期声明有误。
4. 开关异步计算，检查队列时间线、等待区间和临时内存峰值。
5. 连续运行两个相机、动态分辨率和历史重置场景，确认外部资源描述与帧间状态一致。

记录的指标包括图编译 CPU 时间、GPU 通道时间、同步等待和资源峰值。实际算法、错误格式或过高分辨率仍需要在通道内部优化。
