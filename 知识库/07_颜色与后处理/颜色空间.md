# 颜色空间

sRGB中间灰值不是一半光能。把编码值直接用于光照或混合，会压暗中间结果。颜色空间记录原色、白点和传递函数；采样解码后在线性空间处理，显示时再编码。

## 颜色编码

### 为什么光照要在线性空间计算

现实中的光能量可以线性相加。两盏相同灯一起照射，理想情况下总能量是单盏的两倍。

显示和图片编码通常不是线性的。如果直接在编码值上做光照、插值和混合，会错误地压暗中间值。

典型流程：

```text
sRGB 颜色纹理
  → 采样时解码为 Linear
  → 光照、混合和后处理
  → Tone Mapping
  → 输出编码到显示空间
```

### sRGB 不是单纯 Gamma 2.2

sRGB 使用分段传递函数。低值部分近似线性，其余部分接近幂函数。

从 sRGB 编码值 $C_s$ 解码到线性值 $C_l$ 的常见形式：

$$
C_l=
\begin{cases}
C_s/12.92,&C_s\le0.04045\\
\left(\frac{C_s+0.055}{1.055}\right)^{2.4},&C_s>0.04045
\end{cases}
$$

用 $C^{2.2}$ 是简化近似，不是完整 sRGB 定义。

sRGB 还规定色度原色和白点。讨论广色域、HDR 显示时，不能只看传递函数。

### 线性空间与距离衰减

平方反比衰减描述线性光能随球面面积扩散：

$$
E(r)=\frac{I}{r^2}
$$

它要求灯光强度、BRDF 和输出都在线性空间参与计算。若在 sRGB 编码值上直接计算光照，幂函数会把中间亮度重新压缩，视觉上容易误以为平方反比衰减“太快”，进而用线性衰减补偿。在线性 HDR Buffer 中计算并固定曝光后，物理衰减与材质响应才有可比较的意义。

实时引擎仍会在 $r=0$ 附近加入有限光源半径，并在影响范围边缘使用平滑窗函数。窗函数是性能边界，应保持主要距离段的 $1/r^2$ 关系。验证时固定曝光，在距离 1、2、4 处放置相同漫反射平面；忽略角度后，照度应近似呈 1、1/4、1/16 变化。

### 哪些纹理使用 sRGB

通常按“它是给人看的颜色，还是给 Shader 读取的数据”判断。

#### 常用 sRGB

- Base Color/Albedo；
- UI 彩色图片；
- 手绘颜色和部分 Emissive 颜色。

#### 常用 Linear/Data

- Normal；
- Roughness、Metallic、AO；
- Mask、Height、SDF；
- LUT 和数值查找纹理；
- 深度和运动向量。

不能因为一张贴图看起来是灰色就判断它是 Linear。灰色照片仍是颜色，单通道 Roughness 才是数据。

## 验证方法

0.5的sRGB解码约为0.214，先比较数值再看显示。检查颜色纹理与数据纹理view，防止手动解码和硬件解码叠加。平方反比照度机制以直接光照为主归属，这里只核对计算空间。
