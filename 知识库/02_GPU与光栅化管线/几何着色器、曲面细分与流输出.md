# 几何着色器、曲面细分与流输出

标准光栅管线的几何前端以顶点着色器为中心：每次调用处理一个顶点，输出一个变换后的顶点。这个抽象的优势是并行粒度稳定、顶点复用清晰、硬件容易以高吞吐组织执行。代价是两个明确的缺失：

- 没有**图元级上下文**。顶点着色器不知道相邻顶点是谁，无法回答“这个三角形朝向哪、面积多大”这类问题；
- 没有**可变输出**。输入一个顶点就只能输出一个顶点，无法在 GPU 端生成或删除几何。

两类需求因此无法满足：图元级的几何生成与拓扑改写（把点扩成面片、把线扩成条带、按邻接信息生成轮廓），以及细节随视距自适应（近处要更多三角形，远处不必，且不想离线预存全部细分结果）。

图形 API 提供三类扩展。几何着色器（GS）以图元为输入并生成可变数量的图元。曲面细分由固定硬件生成参数域拓扑，再由着色器求值。流输出将几何阶段结果写入缓冲区，供后续使用。

这三者围绕同一个问题反复尝试：如何让几何前端更灵活，同时不与 GPU 的大规模并行本质冲突。理解它们各自的性能特征，比记住接口写法更重要。

## 几何着色器的编程模型

几何着色器由 Direct3D 10 引入，随后进入 OpenGL 3.2 核心规范。它位于顶点着色器（或曲面细分）之后、光栅化之前，是可选阶段。

与顶点着色器的本质差异有两条：

- **输入单位是图元**。每次调用拿到一个完整图元的顶点数组：三角形 3 个、线段 2 个、点 1 个；带邻接信息时更多；
- **输出数量可变**。一次调用可以输出 0 到 N 个顶点，组成新的图元流。

HLSL 的概念形态：

```hlsl
[maxvertexcount(N)]
void GSMain(triangle VS_OUT input[3], inout TriangleStream<GS_OUT> outStream)
{
    // 可读取 input[0..2]，拥有整个三角形的上下文
    // 按需发射 0..N 个顶点
    outStream.Append(v);
    outStream.RestartStrip();
}
```

GLSL 形态：

```glsl
layout(triangles) in;
layout(triangle_strip, max_vertices = N) out;

void main() {
    gl_Position = f(gl_in[0].gl_Position);
    EmitVertex();
    EndPrimitive();
}
```

几个接口要点：

- `[maxvertexcount(N)]` 声明单次调用输出顶点的最大值，供编译器与硬件按最坏情况预留资源；
- 输出通过流类型表达：`PointStream`、`LineStream`、`TriangleStream`。线条与三角形的输出拓扑只有带（strip）形式；需要列表语义时用 `RestartStrip` 逐段切分。条带末端顶点数不足以构成图元的部分会被丢弃；
- 输出顶点的位置必须已经变换到齐次裁剪空间。顶点属性插值发生在光栅化阶段，几何着色器输出的每个顶点属性就是插值端点；
- 几何着色器中不存在屏幕空间导数。需要采样纹理时只能用显式 mip 级别（如 `SampleLevel`），不能使用依赖隐式 LOD 的采样。

### 图元拓扑

几何着色器的输入前缀必须与输入装配阶段声明的图元拓扑一致，否则顶点对不上。基础拓扑分两类五种：点列表（point list）、线列表（line list）、线条带（line strip）、三角形列表（triangle list）、三角形带（triangle strip）。

列表与带的区别在顶点复用方式。三角形列表每三个顶点组成一个独立三角形；三角形带中每个后续顶点都与前两个顶点组成新三角形，$N$ 个顶点表达 $N-2$ 个三角形，内存与处理都更省。

两个容易忽略的细节：

**绕序**。三角形带中相邻三角形共享边，顶点顺序天然交替，导致奇数位置与偶数位置的三角形绕序相反。GPU 内部会对偶数序三角形的后两个顶点做调换，使所有三角形保持一致的绕序，背面剔除才能正确工作。

**邻接图元**。`lineadj`（4 顶点：线段本体加两端邻点）与 `triangleadj`（6 顶点：三角形本体加三条边的对顶点）只为几何着色器提供邻接信息，邻接顶点不会被绘制——即使管线没有启用几何着色器，邻接顶点也不会出现在画面上。轮廓检测等算法依赖这一输入形态。

## 几何着色器的应用

几何着色器的用法可以统称为**有限放大**：每个输入图元的输出上限可控、放大量不大。

### 广告牌：点扩展为四边形

广告牌要求一个面片始终朝向相机。把每个广告牌存成一个点，几何着色器在 GPU 端把它扩展为两个三角形组成的四边形，CPU 每帧只需提交点列表，不必回写顶点缓冲。

核心是用观察方向构造面片的局部坐标架。下面的圆柱广告牌保持世界上方向，只绕竖直轴转向相机：

```hlsl
[maxvertexcount(4)]
void GS(point VS_IN input[1], inout TriangleStream<GS_OUT> triStream)
{
    float3 up = float3(0, 1, 0);
    float3 look = GetWorldSpaceViewDir(input[0].positionWS);
    look.y = 0.0;
    look = normalize(look);
    float3 right = cross(up, look);

    float2 corners[4] = { float2(-1,-1), float2(1,-1), float2(-1,1), float2(1,1) };
    for (int i = 0; i < 4; ++i) {
        float3 posWS = input[0].positionWS
                     + right * corners[i].x * halfWidth
                     + up * corners[i].y * halfHeight;
        GS_OUT o;
        o.positionCS = TransformWorldToHClip(posWS);
        o.uv = corners[i] * 0.5 + 0.5;
        triStream.Append(o);
    }
}
```

`look.y = 0` 是圆柱与球面广告牌的分界：压平视方向的竖直分量后，`right` 只随水平朝向变化，面片不俯仰。观察方向与世界上方向接近平行时 `look` 退化，需要另行处理。用 `SV_PrimitiveID` 作为索引采样纹理数组，可以让同一批点呈现不同外观。

### 线框渲染：逐片元到边距离

线框效果要求片元知道自己离所在三角形最近边有多远。这个信息无法在顶点着色器产生——顶点不知道自己在三角形里的位置关系。几何着色器可以算出每个顶点到对边的距离，作为属性交给光栅化插值：

```hlsl
[maxvertexcount(3)]
void GS(triangle VS_IN p[3], inout TriangleStream<GS_OUT> triStream)
{
    // 顶点已是裁剪空间坐标：先做透视除法到 NDC，再映射到屏幕像素
    float2 p0 = screenSize * (p[0].positionCS.xy / p[0].positionCS.w * 0.5 + 0.5);
    float2 p1 = screenSize * (p[1].positionCS.xy / p[1].positionCS.w * 0.5 + 0.5);
    float2 p2 = screenSize * (p[2].positionCS.xy / p[2].positionCS.w * 0.5 + 0.5);

    float2 e0 = p2 - p1, e1 = p2 - p0, e2 = p1 - p0;
    float area = abs(e1.x * e2.y - e1.y * e2.x);
    float3 d = float3(area / length(e0), area / length(e1), area / length(e2));
    // 三个顶点分别携带 (d0,0,0) (0,d1,0) (0,0,d2)，光栅化时自动插值
}
```

在屏幕像素空间计算距离，线宽才能以像素为单位稳定控制。片元着色器取三个分量的最小值，经指数衰减得到抗锯齿的线宽，阈值外的片元丢弃。注意这里必须手动做透视除法：几何着色器拿到的 `positionCS` 尚未除以 $w$。

### 法线可视化与调试几何

对每个三角形或每个顶点生成一条短线段表示法线，是检查法线数据的直接手段。线起点取三角形重心或顶点位置，终点沿法线偏移固定长度，用 `LineStream` 输出。这类调试几何放在独立的渲染通道中，配合图层或渲染队列与正常绘制区分。

### 视距驱动的曲线细分

绘制光滑曲线需要把曲线离散成折线。固定段数的两难是：近景段数不足出现折角，远景段数过多浪费几何。几何着色器可以只提交控制点，按视距决定输出段数：

```glsl
layout(lines_adjacency) in;
layout(line_strip, max_vertices = 64) out;

void main() {
    vec3 mid = bezier3(0.5, P0, P1, P2, P3);
    float w = clamp((length(mid) - minDist) / (maxDist - minDist), 0.0, 1.0);
    int segments = int(round(mix(float(maxSeg), float(minSeg), w)));

    for (int i = 0; i <= segments; ++i) {
        gl_Position = proj * vec4(bezier3(float(i) / segments, P0, P1, P2, P3), 1.0);
        EmitVertex();
    }
    EndPrimitive();
}
```

贝塞尔曲线完全由控制点决定，对控制点做仿射变换曲线形状同步保持，因此控制点只需在顶点着色器变换一次，几何着色器直接在变换后的控制点上求值。

这个例子真正的意义是那条更一般的思想：让几何细节跟随视距与投影尺度生成，而不是在资产侧预烘焙所有 LOD。几何着色器不是实现这一思想的高效终局——曲面细分才是为规模化、规则化细分设计的阶段。

### 草地：两个阶段的组合

大规模草地演示常把两个阶段串起来用：曲面细分负责增密（把地面网格细分出大量顶点，每个顶点位置长一根草），几何着色器负责成形（把每个细分出的图元扩展成一根弯曲的草叶）。

一根草叶的生成按执行顺序是若干几何操作的组合：

1. 以基点位移哈希为种子，用轴角公式构造三个旋转矩阵——朝向随机旋转、弯曲随机旋转、风力旋转（风力纹理在域着色器阶段用显式 mip 采样后传递，因为细分与几何阶段都没有屏幕导数）；
2. 由法线、切线、副切线建立切空间到世界的变换，与三个旋转矩阵依次相乘，得到这根草的完整姿态矩阵；
3. 沿高度分若干段，每段输出左右两个顶点形成条带：宽度随高度线性收窄，前向弯曲量按 $t^{curve}$ 增长，幂指数控制弯曲形状；
4. 每个顶点的世界高度钳制不低于地面，防止弯曲穿透地表。

这类组合管线的代价也直接可见：曲面细分的放大作用在顶点阶段，几何着色器的放大作用在图元阶段，两级相乘后三角形数量爆炸，规模一大 GPU 就会跑满。它是教学演示的合理选择，不是生产草地方案——生产环境通常用实例化加预生成叶片，或计算着色器驱动的 GPU-Driven 方案。

## 几何着色器为什么慢

几何着色器在工程上的评价是“灵活但慢”，根源在于可变输出与 GPU 执行组织之间的结构性冲突。

**锁步等待**。同一批线程（Wave）锁步执行，但各线程输出的顶点数不同，整个线程组要等最慢者完成，其余线程的执行资源闲置。

**预留缓冲压力**。`maxvertexcount` 让编译器和硬件按最坏情况为每个线程预留输出存储。预留量乘以并发线程数，总量可能把片上缓冲挤到显存，带来显著带宽压力与延迟，进一步压低并行度。历史上的硬件测试印证了这一分析：32 或 64 宽的 Wave 设计上缓冲压力明显，而支持更窄发射宽度的实现表现相对好。

**后变换缓存失效**。顶点着色器的结果可以按索引复用，避免同一顶点重复变换。几何着色器生成的顶点是全新顶点，没有索引身份，无法进入这套缓存，同样的数据也要重新计算。

**输出上限**。Direct3D 10 规定几何着色器单次调用最多输出 1024 个 32 位标量，足以让它只做小规模几何操作。NVIDIA 早期编程指南给出过更细的量化：单次输出 1 到 20 个标量时接近峰值性能，27 到 40 个时降到峰值的一半左右。

**顺序保证**。图形管线要求输出结果等同于按输入顺序串行执行。并行产出可变数量的图元后，还要花代价把它们重新排成确定顺序。

由此得到使用边界：几何着色器适合整个图元级的任务——轮廓判断、中心计算、少量辅助几何；不适合大规模几何生成。移动端部分平台直接不支持几何着色器。需要大规模生成时，方向是实例化、计算着色器或网格着色器。

## 曲面细分：固定拓扑生成与可编程求值

曲面细分由 Direct3D 11 引入，随后进入 OpenGL 4.0 核心规范。它把“生成多少顶点”与“顶点在哪里”拆开：

- 参数点的生成规则固定，交给固定功能硬件，吞吐高、结果可预测；
- 参数点对应的几何求值保留可编程性。

这是把几何着色器的“可变输出”问题改写为“规则采样”问题。采样点生成足够规则，硬件才能高吞吐；求值仍由着色器完成，灵活性不丢。

### 三段式与命名对应

| Direct3D | OpenGL | 职责 |
|---|---|---|
| Hull Shader（HS） | Tessellation Control Shader（TCS） | 读取 Patch 控制点，输出细分因子与变换后控制点 |
| Tessellator | Tessellation Primitive Generator | 固定功能，按细分因子在参数域生成拓扑与坐标 |
| Domain Shader（DS） | Tessellation Evaluation Shader（TES） | 对每个参数点求值，输出最终顶点 |

Direct3D 的外壳着色器在逻辑上再分两部分：逐控制点阶段（每个控制点并行执行一次）与 Patch 常量阶段（每个 Patch 执行一次，输出细分因子）。OpenGL 的 TCS 把两者合在同一个着色器里，每个输出控制点对应一次调用（`gl_InvocationID` 标识），写共享的 `patch out` 变量时需要注意同步。

### Tessellator 是定点数生成器

Tessellator 是管线中为数不多的固定功能单元。它不执行浮点着色运算，只做定点数的参数点生成与拓扑枚举。其输出不是几何坐标，而是参数域坐标与连接关系：

- 三角域：重心坐标 $(u,v,w)$，满足 $u+v+w=1$；
- 四边域：二维坐标 $(u,v)$，$u,v\in[0,1]$；
- 等值线域：$u$ 表示第几条线，$v$ 表示沿线起点的偏移。

生成规则由图形 API 功能规范逐位定义，因此结果确定、拓扑一致、缓存友好。几何含义全部由域着色器赋予——同一份参数坐标，线性插值得到原三角形，配合位移贴图得到地形，配合曲面求值公式得到光滑曲面。

### Patch 与控制点

启用细分后，输入装配提交的不是三角形而是 Patch：一组控制点构成的参数化曲面片。OpenGL 侧用 `glPatchParameteri(GL_PATCH_VERTICES, n)` 声明每个 Patch 的控制点数，绘制时用 `GL_PATCHES` 拓扑；控制点数量上限由 `GL_MAX_PATCH_VERTICES` 给出，取决于硬件。

要区分两类点：控制点是输入，数量由 API 声明；细分点是 Tessellator 的输出，数量由细分因子决定。域着色器用参数域坐标在控制点之间插值或求值，得到每个细分点的真实位置。

### 细分因子与边缘间距

细分因子分外部与内部两组，有效索引随域类型变化：

| 域类型 | 外部有效索引 | 内部有效索引 |
|---|---|---|
| quads | 4 条边全部 | 2 个方向全部 |
| triangles | 前 3 个（三条边） | 仅第 1 个 |
| isolines | 前 2 个（线数与段数） | 无效 |

边缘间距模式决定细分因子的非整数部分如何处理，三条规则的钳制区间不同：

- `equal_spacing`（Direct3D 对应 integer）：钳制到 $[1, max]$，向上取整，每条边均分为整数段；
- `fractional_even_spacing`：钳制到 $[2, max]$，向上取整到最近的偶数；
- `fractional_odd_spacing`：钳制到 $[1, max-1]$，向上取整到最近的奇数。

后两种模式把小数部分体现为平滑过渡：以 odd、因子 3.5 为例，向上取整到奇数得 5 段，向下取整到奇数得 3——中间 3 段均分，两端各分配 $(3.5-3)/2=0.25$ 段。新边从零宽度平滑生长，细分密度随距离连续变化时不会出现整排顶点突现的跳变。

相邻 Patch 共享边的边细分因子必须完全相同，否则两侧采样点错位、产生裂缝。因子应当由共享边的两个端点唯一决定。

### 三角域的内部细分过程

三角域的细分按固定次序进行，理解这个过程才能解释内部细分因子的作用：

1. 先按内部细分因子生成若干同心三角形环：最外层环的每条边被分成内部因子指定的段数，每向内一层，每边段数减 2，直到段数小于 0；段数恰为 0 时最内层退化为一个顶点；
2. 舍弃最外层环，改用外部细分因子重新细分三条边；
3. 按规则把环与环、环与边界之间的采样点装配成三角形。

这条次序解释了为什么三角域内部只有一个有效因子：同心环结构只有一个自由度。等值线域忽略内部因子，由外部因子的两个分量分别控制线段数量与每条线的分段数。

### Phong 细分

线性插值只能让细分点落在原三角形平面内，几何形状没有变化。Phong 细分沿插值法线把细分点向外偏移，用低模平面逼近圆润表面：

```hlsl
float3 posOS = patch[0].positionOS * bary.x
             + patch[1].positionOS * bary.y
             + patch[2].positionOS * bary.z;
float3 normalOS = normalize(patch[0].normalOS * bary.x
                          + patch[1].normalOS * bary.y
                          + patch[2].normalOS * bary.z);
posOS += normalOS * phongStrength;   // 强度为 0 时退化为线性插值
```

它不需要额外的控制点或曲率数据，适合给低模加圆润感。偏移量与真实曲率无关，强度过大在凹陷区域会产生外翻。

### 距离驱动的细分因子

连续 LOD 要求细分因子随视距变化。边因子应由边的两个端点决定，常见做法取边中点到相机的距离做归一化：

```hlsl
float3 EdgeTessFactors(float3 p0, float3 p1, float3 p2,
                       float3 cameraPosWS, float minDist, float maxDist)
{
    float3 f;
    f.x = saturate(1.0 - (distance(0.5 * (p1 + p2), cameraPosWS) - minDist) / (maxDist - minDist));
    f.y = saturate(1.0 - (distance(0.5 * (p0 + p2), cameraPosWS) - minDist) / (maxDist - minDist));
    f.z = saturate(1.0 - (distance(0.5 * (p0 + p1), cameraPosWS) - minDist) / (maxDist - minDist));
    return f;
}
```

内部因子取三个边因子的平均值，最终写出的每个因子都要 `max(1.0, ...)`——小于 1 的因子在部分实现下行为未定义。`saturate` 同时吸收了 `minDist == maxDist` 时的除零。用边中点而非 Patch 中心或面法线，才能保证共享边两侧的 Patch 算出相同的边因子。

## 流输出：把几何结果存下来

几何阶段的输出默认只能继续进入光栅化。如果想要的只是“处理后的顶点流”——供后续绘制、粒子状态更新或调试——没有流输出时只能绕道渲染到纹理再回读，引入格式编码、精度损失与额外带宽。

流输出（Direct3D 称 Stream Output，OpenGL 称 Transform Feedback）提供直接路径：声明要捕获的输出语义与写入布局，几何阶段结束后顶点属性按序写入缓冲区。

Direct3D 用声明表描述捕获项：

```cpp
D3D11_SO_DECLARATION_ENTRY decl[] = {
    { "SV_POSITION", 0, 0, 4, 0 },   // 语义名, 索引, 起始分量, 分量数, 输出槽
    { "NORMAL",      0, 0, 3, 0 },
    { "TEXCOORD",    0, 0, 2, 0 },
};
```

OpenGL 用 `glTransformFeedbackVaryings` 指定变量名列表，配合 `GL_INTERLEAVED_ATTRIBS`（交错写入同一缓冲）或 `GL_SEPARATE_ATTRIBS`（分缓冲写入）；GLSL 还可以用 `xfb_buffer`、`xfb_offset`、`xfb_stride` 布局限定符直接描述写入布局。

### 顺序约束的代价

流输出的昂贵不在“多写一份”，而在**顺序**。图形 API 功能规范要求：无论内部如何并行调度，最终写出的结果必须等同于按输入顺序串行执行。

一旦引入几何着色器或曲面细分，每个输入图元输出的顶点数可变，并行完成次序不可预测，顺序保证就从免费变成结构性成本：

- **原子计数器**为每次输出分配位置：可行，但所有线程争用同一计数器形成热点；
- **两阶段写入**：先算每个图元的输出大小，再做前缀和求偏移，最后并行写入——高效但复杂，这已经接近“用计算着色器手写几何管线”的形态；
- **粗粒度序列化**：实现简单，吞吐损失明显。

流输出把并行友好的散写问题变成了要求顺序稳定的队列问题，强迫并行机器在某处排队。这也是它看似是通用 GPGPU 的早期入口、却没有成为通用计算主路径的原因——计算着色器从一开始就按显式并行、显式同步组织，不背图形管线的顺序包袱。

流输出的现代角色是保守的：调试与可视化、小规模几何捕获、个别沿用至今的粒子更新。面对通用的生成、压缩、排序需求，实践上转向计算着色器加显式缓冲，顺序与压缩策略自行管理。

## 三者的关系与演进

把三者放在一起，能看到一条清晰的取舍链：

| 机制 | 解决什么 | 结构性约束 |
|---|---|---|
| 几何着色器 | 图元级上下文与可变输出 | 可变输出与锁步并行冲突，吞吐低 |
| 曲面细分 | 规则化的高吞吐几何放大 | 只能生成规则拓扑，不做内容相关改写 |
| 流输出 | 几何结果的存留与复用 | 顺序稳定要求与并行调度冲突 |

几何着色器提供图元级通用改写但慢，曲面细分快但只能做规则放大，流输出能存留结果但被顺序拖住。三者的共同对手是同一个：任何要求“严格保持输入顺序的确定性可变输出”的机制，都会与大规模并行调度发生冲突。

网格着色器将几何前端组织成工作组任务。着色器在平台规定的输出上限内生成顶点和图元，可以结合剔除与数据解码。它提供更灵活的调度，但是否更快取决于工作量、实现与目标硬件。评估新项目时，几何着色器与传统流输出应当作为兼容性选项而不是默认起点。

## 验证方法

- 用帧捕获确认各阶段实际执行顺序：VS → HS → Tessellator → DS → GS → 光栅化 → PS，几何着色器位于细分之后。
- 几何着色器输出先可视化位置，再叠加属性；`maxvertexcount` 改为 1 时画面应退化为逐图元单点，用于确认发射逻辑。
- 故意把输入图元前缀与绘制拓扑写错，确认出现顶点错位——借此验证输入对应关系。
- 开关 fractional 与 integer 模式对比：连续改变细分因子时，integer 模式应有可见跳变。
- 相邻 Patch 接缝处拉近视距检查裂缝；出现裂缝先查共享边因子的计算输入是否一致。
- 距离驱动细分下让相机匀速推进，几何密度应平滑变化；因子小于 1 的区域确认被钳制。
- 检查 GS 输出的统计：每图元平均输出顶点数与 `maxvertexcount` 的预留差距过大说明资源浪费。
- 细分场景统计输出三角形的平均屏幕面积，亚像素三角形过多说明因子上限定高了。
- 流输出结果读回后与光栅化路径的顶点逐一比对，顺序与数值都应一致。
