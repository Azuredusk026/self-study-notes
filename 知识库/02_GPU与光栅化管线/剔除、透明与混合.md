# 剔除、透明与混合

减少不可见工作要尽量发生在昂贵阶段之前。剔除是在提交或光栅化前排除对象和图元；深度测试是在样本阶段拒绝被挡住的片元；透明混合则需要保留并组合多个可见层。

## 背面剔除

封闭网格通常只需要看到朝外的一面。GPU 根据屏幕空间绕序判断三角形正反面，再按 Rasterizer State 剔除 Front 或 Back。

常见问题：

- 负缩放翻转绕序；
- DCC、引擎和 API 的坐标手性不同；
- 法线方向正确不代表三角形绕序正确；
- 双面材质关闭剔除后，片元成本和过度绘制会增加。

## 视锥剔除

CPU 或 GPU 用对象 Bounds 与六个视锥平面测试。完全在任一平面外的对象不可见。

通常先用 Bounding Sphere 或 AABB 做便宜粗测。Bounds 太大会保留很多不可见对象；Bounds 太小会错误剔除动画、粒子或 Shader 位移后的几何。

## 遮挡剔除

视锥内的物体仍可能被墙体和近处物体挡住。遮挡剔除需要根据已有遮挡信息判断 Bounds 是否可能可见。

常见方案：

- 离线 PVS/Portal；
- Hardware Occlusion Query；
- Software Rasterizer；
- 基于上一帧或当前帧 Hi-Z 的 GPU Occlusion Culling。

遮挡判断本身有成本，也会引入延迟和保守误差。小物体、动态遮挡和相机快速移动需要特别处理。

## Alpha Test

Alpha Test/Clip 根据阈值保留或丢弃片元。保留下来的部分仍可以写深度，因此适合树叶、栅栏和硬边镂空。

主要问题：

- `discard/clip` 可能限制 Early-Z；
- 边缘会产生采样锯齿；
- Mipmap 会平均 Alpha，远处覆盖率可能变化；
- 双面叶片容易增加 Overdraw。

Alpha-to-Coverage 可以把 Alpha 转换成 MSAA Coverage，改善边缘，但依赖 MSAA 样本数和平台实现。

## Alpha Blend

普通非预乘 Alpha 的常见公式：

$$
C_{out}=\alpha_sC_s+(1-\alpha_s)C_d
$$

$C_s$ 是源颜色，$C_d$ 是目标颜色。

预乘 Alpha 的源 RGB 已经乘过 Alpha：

$$
C_{out}=C_s+(1-\alpha_s)C_d
$$

预乘表示在纹理过滤、边缘颜色和多次合成时通常更稳定，但资源制作、Shader 输出和 Blend State 必须使用同一约定。

## 为什么透明需要排序

标准 Alpha Blend 不满足交换律。先画 A 再画 B，和先画 B 再画 A 的结果不同。因此透明物体通常从远到近绘制，并开启深度测试、关闭深度写入。

对象级排序不能解决：

- 两个透明网格相交；
- 一个网格内部三角形顺序错误；
- 粒子互相穿插；
- 玻璃需要折射后方画面。

## 常见透明方案

### Sorted Transparency

最常见。成本可控，但排序不可能覆盖所有相交情况。

### Additive

加法混合接近可交换，适合火花和发光粒子，但无法表达正常遮挡和吸收。

### Weighted Blended OIT

用加权累积近似与顺序无关透明。它减少排序问题，但不能精确还原所有层次，颜色和遮挡会有偏差。

### Per-pixel Linked List

保存每像素所有透明片元再排序，结果更准确，但内存、带宽、原子操作和最坏情况都很昂贵。

## 透明性能

透明通常不能利用普通不透明物体的完整深度拒绝。同一区域覆盖很多层时，Pixel Shader 和 Blend 都会重复执行。

优化方向：

- 控制屏幕覆盖面积，而不只是粒子数量；
- 使用紧贴内容的粒子网格；
- 降低透明 Shader 和纹理采样成本；
- 近远景使用不同粒子复杂度；
- 在移动端注意 Blend、带宽和 Tile Memory；
- 用 Overdraw 视图和 GPU Counter 验证。
