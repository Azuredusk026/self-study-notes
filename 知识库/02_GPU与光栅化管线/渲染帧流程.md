# 渲染帧流程

CPU 准备逻辑与资源，GPU 执行队列中的命令，显示系统再呈现图像。这些工作可以跨帧重叠，所以帧率、排队和输入延迟要沿整条时间线理解。

一帧从某次输入与模拟状态出发，经过视图准备、命令执行得到图像，再进入显示队列。模拟步、渲染帧和显示刷新分别计数：一次渲染可以在相邻两次模拟状态之间插值，一份完成的图像也可能等待后续刷新才被扫描输出。下面以常见光栅化路径说明数据关系。

## 专题入口

| 环节 | 输入与输出 | 入口 |
|---|---|---|

| 可见候选筛选 | 当前视图和场景包围体产生可绘制集合；阴影视图另行筛选 | [[02_GPU与光栅化管线/可见性剔除]] |
| 通道与资源组织 | 绘制需求和资源读写关系形成通道依赖、附件与寿命安排 | [[13_渲染架构/Render Graph]]、[[13_渲染架构/Render Pass与附件]] |
| 记录与提交 | 渲染数据、管线状态和资源引用形成命令列表，再提交队列执行 | [[13_渲染架构/Command Buffer与帧提交]] |
| 几何与样本处理 | 顶点经变换、裁剪和光栅化形成覆盖与插值，着色和样本测试决定写入贡献 | [[02_GPU与光栅化管线/光栅化与属性插值]]、[[02_GPU与光栅化管线/光栅化可见性]] |
| 光照与颜色处理 | 路径决定表面与光照求值时机；透明合成和后处理生成待呈现颜色 | [[13_渲染架构/渲染路径与光源组织]]、[[07_颜色与后处理/后处理链]] |

表格描述生产与消费关系。GPU剔除可在命令提交后生成间接绘制参数，光照可由片元或计算着色器执行，异步队列也可并行处理无依赖工作。Forward在几何绘制时完成材质与光照，Deferred先保存表面再照明，具体通道顺序由资源依赖决定。单次绘制内部的图形管线阶段，与一帧由多个通道组成的执行图，分别在这两个尺度上理解。

## 阅读路线

先掌握空间变换与 GPU 执行，再沿命令记录、几何覆盖、附件写入和显示呈现阅读。各阶段的开始与结束需要结合队列依赖理解；CPU 记录完一帧后，GPU 可能仍在处理此前提交的工作。

追踪一帧时同时记录模拟步编号、渲染帧ID、提交完成值和呈现图像身份。CPU处理帧N+1时GPU可以执行帧N，显示系统再扫描更早的图像；稳定吞吐受关键路径与等待限制，输入到显示的延迟则要沿同一份输入追到对应图像。把CPU与GPU耗时简单相加，无法同时解释这两个指标。

诊断卡顿时，从帧时间线定位等待，再回到对应环节。Present 附近的等待可能涉及限帧、显示同步或 GPU 积压，具体判断见显示呈现与帧瓶颈诊断。
