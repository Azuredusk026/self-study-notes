# 深度缓冲、反向深度与位置重建

深度缓冲保存投影后的可见性比较值。位置重建需要知道投影、深度范围和反向深度约定，不能直接把缓冲值作为世界距离。

## 深度值不是线性距离

透视投影需要把较多精度分配给近处，因此常规深度缓冲通常与视空间距离非线性对应。用它直接做世界距离会出错，需要通过投影参数重建。

深度精度受 Near Plane 影响很大。Near 设得过近，会浪费大量可用精度。

### 伪深度的来历

透视投影把视锥内的点压到标准立方体。屏幕位置由相似三角形直接给出，但两个视空间深度不同的点可能投影到同一屏幕位置，因此需要保留一个可比较的深度量。

为了让深度表达式与 $x'$、$y'$ 形式一致、便于用齐次坐标和矩阵统一表示，深度取以 $z$ 为分母的线性分式：

$$
z'=\frac{az+b}{z}
$$

以 Direct3D 约定为例，近裁剪面 $z=N$ 映射到 0，远裁剪面 $z=F$ 映射到 1。代入两个边界条件解得：

$$
a=\frac{F}{F-N},\qquad b=\frac{-FN}{F-N}
$$

深度非线性来自 $z'=a+b/z$。对 $z$ 求导得到 $\lvert dz'/dz\rvert=\lvert b\rvert/z^2$：距离越远，同样的世界空间深度差对应的缓冲值差越小。固定精度缓冲因此更难区分远处表面。横向投影缩小和深度量化是两类问题，深度误差应由投影公式与存储格式计算。

OpenGL 传统约定把 NDC 深度映射到 $[-1,1]$，Direct3D 映射到 $[0,1]$。重建深度和写投影矩阵时必须确认当前 API 与引擎的约定。

### Reversed-Z 为什么有效

浮点数在 0 附近的可表示值远比在 1 附近密集。常规映射把远处放在接近 1 的区间，恰好落在浮点精度最稀疏的地方，非线性压缩与浮点分布的稀疏区叠加，远处 Z-Fighting 因此格外严重。

Reversed-Z 把近平面映射到 1、远平面映射到 0。远处落进浮点密集区，两种非线性相互抵消，深度精度在整个范围内分布得更均匀。配合浮点深度格式时收益最大；配合定点格式（如 D24）时浮点分布的优势不存在，收益有限。

启用时必须同步四处：投影矩阵、深度 Clear Value（清成 0 而非 1）、深度比较函数（Less 改为 Greater）、以及所有手工重建深度的代码。只把采样结果做 `1-z` 是错误的。

### 缓解深度冲突

- 收窄 Near 与 Far 的比值。Near 的影响远大于 Far，把 Near 从 0.01 提到 0.1 的收益通常比压缩 Far 大得多；
- 避免共面或极近的几何，这是美术侧能解决的绝大部分情况；
- 使用 Polygon Offset / Depth Bias 给特定图元一个可控偏移；
- 启用 Reversed-Z 配合浮点深度。

## 深度缓冲与深度纹理

这是两个容易混淆的概念，服务于不同使用者。

**深度缓冲**由 GPU 与窗口系统管理，用于可见性判定与 Early-Z。它随管线自动写入，开发者只控制 Depth Write 与比较函数。

**深度纹理**强调资源供着色器读取的用途。许多 API 允许同一深度资源创建采样视图，但需要支持的格式、创建标志、布局与访问状态。引擎也可能选择深度拷贝或独立预通道，尤其涉及 MSAA、相机堆栈和时机约束时。是否需要拷贝以目标管线实际路径为准。

两者的写入条件也不同。关闭 Depth Write 的对象不写深度缓冲，但它是否出现在深度纹理里，取决于深度纹理由哪条路径生成，而不取决于该对象的 Depth Write 状态。

生成深度纹理的常见路径：

- **Shader Replacement**：用替换着色器把符合条件的对象重画一遍。兼容性最好，代价是不透明物体的 Draw Call 翻倍；
- **深度拷贝**：从已渲染的深度附件拷出。不增加 Draw Call，但要求硬件支持深度拷贝，且 MSAA 情况下需要额外解析；
- **延迟渲染直接复用**：GBuffer 阶段已经写好深度，无需额外操作。

Unity URP 提供 `CanCopyDepth` 一类的运行时判断，在不支持拷贝或开启 MSAA 时回退到独立的 Depth Prepass。具体行为随 URP 版本变化，需要在目标版本的 Frame Debugger 中确认。

## 从深度重建位置

屏幕空间效果经常需要由深度反推世界位置。两条常用路径：

**逆变换法**：由屏幕 UV 与深度组装 NDC 坐标，乘以逆 View-Projection 矩阵，再做齐次除法。

$$
\mathbf{p}_{world}=\frac{M_{VP}^{-1}\,\mathbf{p}_{ndc}}{w}
$$

**射线插值法**：预先计算相机到远平面四角的射线，在屏幕上插值得到当前像素的视线方向，再按线性深度沿射线前进。省去逐像素矩阵乘法，但要求插值的是视空间线性深度，不是原始深度值。

两条路径的前提不同，必须逐项核对：NDC 的 Y 方向、深度区间是 $[0,1]$ 还是 $[-1,1]$、是否启用 Reversed-Z、UV 原点在左上还是左下。任何一项与平台约定不符，结果都会整体偏移或翻转。

### 由深度重建世界位置

输入是屏幕 UV 与深度纹理采样值，输出世界空间位置。以 Direct3D 风格的 $[0,1]$ 深度区间为例：

```hlsl
float3 ReconstructWorldPos(float2 uv, float rawDepth)
{
    float2 ndcXY = uv * 2.0 - 1.0;
#if UNITY_UV_STARTS_AT_TOP
    ndcXY.y = -ndcXY.y;
#endif
    float4 ndc = float4(ndcXY, rawDepth, 1.0);
    float4 world = mul(_InvViewProjMatrix, ndc);
    return world.xyz / world.w;
}
```

`rawDepth` 必须是未经线性化的原始深度，与写入时的约定一致；若已调用过线性化函数，再走逆 VP 矩阵会得到错误结果。启用 Reversed-Z 时投影矩阵已包含反转，此处不需额外处理。

验证方法是把重建结果对 1 米取模输出为颜色，画面应出现贴合场景表面的规则网格。网格在斜面上扭曲说明透视除法有误；随相机移动而滑动说明用错了矩阵或深度约定。

### Reversed-Z

Reversed-Z 让近处映射到较大深度，远处映射到较小深度，并把比较从 Less 改为 Greater。配合浮点深度，它可以利用浮点数在 0 附近更密集的表示，改善远距离精度。

它不是简单把深度贴图做 `1-z`。投影矩阵、Clear Value、比较函数和深度重建都要一致。

## Depth Test 和 Depth Write

Depth Test 判断新样本能否通过。Depth Write 决定通过后是否更新深度。两者独立。

常见情况：

- 不透明物体：测试开，写入开；
- 半透明物体：测试开，写入通常关；
- 天空：常在背景深度位置绘制；
- UI 或叠加效果：根据需求关闭测试或使用特殊比较。

## 验证方法

- 对近、中、远三个距离做投影与重建往返。
- 开关反向深度时同步检查清除值和比较函数。
- 将重建位置按世界距离画条纹，确认条纹贴合场景。
