# 虚拟内存

申请很大地址区间，不一定立刻占用同样多物理内存。虚拟内存把地址与物理页分开，首次访问可能触发缺页，随机工作集又会增加TLB开销。Reserve、Commit和驻留要分别观测。

## 虚拟内存、页表与 TLB

每个进程看到连续的 Virtual Address Space。Page Table 把 Virtual Page 映射到 Physical Page，并记录读写执行权限。不同进程可以把同一物理页映射到不同地址，用于共享库、共享内存和 Copy-on-write。

TLB 缓存最近使用的地址翻译。工作集跨越大量 Page 或访问模式随机时，TLB Miss 增加，硬件需要查询多级页表。Huge Page 可以减少页表层级和 TLB 压力，但分配、碎片和平台权限更复杂。

访问尚未建立有效映射的页面会触发 Page Fault。Minor Fault 可能只需建立已有物理页映射；Major Fault 可能要从磁盘读取，延迟高得多。首次触碰新提交内存、内存映射文件和换页都可能产生 Page Fault。

Reserve 通常只占用地址范围，Commit 才承诺可用存储，实际物理页还可能在首次访问时分配。引擎分配器可以先申请大块虚拟地址，再按 Page 提交和回收，减少频繁进入内核。

## Stack、Heap 与内存映射

线程 Stack 保存调用帧、局部变量和返回信息，容量有限，并按 Page 逐步增长。深递归、大型局部数组和无限调用链会造成 Stack Overflow。

语言运行库的 Heap Allocator 在操作系统提供的大块 Virtual Memory 上管理小对象。`new`/`malloc` 不一定每次直接调用系统；分配器会维护 Size Class、Free List、Arena 或 Thread Cache。多线程高频分配还要处理锁竞争和跨线程释放。

Memory-mapped File 把文件区间映射到虚拟地址。读取由 Page Fault 按需触发，操作系统 Page Cache 可以与普通文件 IO 共享数据。它适合随机访问大型文件，但仍要处理映射生命周期、文件截断、错误页和显式刷盘语义。

## 按页提交

平台中立伪代码保留地址区间，再为所需页提交存储；具体OS接口与权限由后端实现。

```text
range = ReserveVirtualAddress(capacity)
CommitPages(range, requiredBytes)
TouchCommittedPagesIfLatencyRequires()
DecommitUnusedPagesAfterReadersFinish()
ReleaseRange()
```

## 验证方法

比较地址保留、提交量与驻留集，冷访问记录缺页，热访问记录TLB与缓存。测试文件截断、映射失效和跨页范围；Huge Page的收益由实际工作集验证。
