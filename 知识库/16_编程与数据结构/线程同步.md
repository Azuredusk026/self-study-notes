# 线程同步

消费者醒来，队列仍可能为空，因为通知不是对状态的永久承诺。线程同步先保护共享谓词，再使用锁、条件变量或原子发布建立访问关系。原子更新不自动保护整个对象寿命。

## 锁与等待原语

Mutex 提供互斥所有权，未获得锁的线程通常进入等待。递归互斥锁允许同一线程重复获取，但容易掩盖职责和调用层级问题。读写锁允许多个读者或一个写者，只有读多写少且临界区足够大时才可能受益。

信号量保存可用许可数量，适合限制并发资源或通知多个工作项。条件变量让线程在等待状态时睡眠。共享状态在锁保护下更新，再通知等待者。线程醒来后需要重新检查条件，因为可能发生伪唤醒，也可能有其他线程先消费了数据。

自旋锁在短时间内循环尝试，不进入睡眠。它只适合临界区极短、锁持有者很快会运行的场景。锁持有期间做 IO、等待另一个锁或被操作系统抢占，会让 自旋浪费CPU时间。

## 原子操作与内存顺序

原子读改写保证多个线程对同一原子对象的更新不会丢失。原子性不自动保证一组普通内存操作的整体事务，也不解决对象生命周期。

编译器和 CPU 可以在不改变单线程结果的前提下重排内存访问。取得/释放建立跨线程的先行发生关系：发布线程先写数据，再用释放发布标志；消费线程用取得读到标志后，才能可靠观察此前的数据写入。顺序一致性提供更直观的全局顺序，约束通常更强。

无锁表示系统整体能持续推进，不代表每个线程都不会饥饿，也不代表一定比互斥锁快。无锁结构还要处理 ABA、内存回收、伪共享和复杂验证。

## 数据竞争与死锁

在C++线程模型中，两个可能并发的操作访问同一内存位置，至少一个写入、至少一个是非原子操作，且两者之间没有先行发生关系时，构成数据竞争并导致未定义行为。对象寿命的开始或结束与重叠存储的访问也可能形成冲突。只在调试时“看起来结果正确”不能证明线程安全。

经典死锁需要四个条件同时成立：互斥、持有并等待、不可抢占、循环等待。常见预防方式是统一锁顺序、缩小锁范围、一次获取整组锁、避免持锁调用未知代码，并在调试构建记录锁依赖图。

活锁中线程持续响应对方却没有实际进展；饥饿表示某个线程长期得不到资源。公平锁、退避和任务优先级可以缓解，但也会改变吞吐和延迟。

## 条件变量的谓词等待

生产者修改队列和停止标记时持有同一互斥锁，消费者用谓词处理虚假唤醒：

```cpp
std::unique_lock lock(queueMutex);
queueReady.wait(lock, [&] { return stopping || !jobs.empty(); });

if (stopping && jobs.empty())
    return;

Job job = std::move(jobs.front());
jobs.pop_front();
lock.unlock();
job.Run();
```

等待会原子地释放锁并休眠，唤醒后重新获得锁再检查谓词。任务执行放在解锁之后，避免一个长任务阻塞所有生产者和消费者。若停止标记在另一把锁下修改，可能丢失唤醒或形成数据竞争；压力测试应覆盖空队列停止、多生产者和连续虚假通知。

## 并发错误定位

先列出共享数据的写入者与读者，再把锁、消息队列或原子发布点画到时间线上。两个线程各自运行正常，不说明交错后也正常。调试器、线程检测工具和压力测试分别提供现场、候选竞争与复现线索；证明访问顺序还要回到语言内存模型。

## 通知、发布与回收

生产者先在队列锁内加入任务，解锁后通知。消费者若先检查到空，在 `wait` 中释放锁并等待；若生产者先入队，消费者拿到锁后直接看到非空。正确性依赖共享谓词与同一把锁，通知只促使重新检查，不能作为“必有一个任务”的计数。

原子发布的典型顺序是先写普通数据，再以release写标志；消费者用acquire读到对应标志后，才读取数据。若消费者只执行一次acquire却读到旧值，它没有取得那次发布。数据被消费后如何再次写入还需另一个交接协议，单个ready布尔值不能自动支持无界多轮复用。

回收也属于同步。一个线程确认指针非空后，另一个线程仍可能删除对象；原子指针只保证指针值读写完整。锁、引用所有权或专门的延迟回收机制必须让实际访问期间对象保持存活。

## 验证方法

空队列停止、虚假通知、多生产者与取消分别压测。记录锁图和等待，使用竞态工具检查普通访问；取得必须读到对应释放发布值，不能靠两个关键字建立任意同步。
