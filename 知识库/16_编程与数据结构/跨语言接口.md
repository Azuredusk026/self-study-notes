# 跨语言接口

一侧分配内存，另一侧用不同运行库释放，接口即使能链接也会崩溃。跨语言通信先固定字节表示、版本、所有权和错误传播，再选择C ABI、绑定库、协议或CLI。

## 互操作边界

### 跨语言边界

常见方式：

- C#通过P/Invoke调用暴露C ABI的原生动态库；
- C++/CLI 连接 .NET 与 Native，仅适合支持平台；
- pybind11或CPython扩展将C++接口暴露给Python；
- Socket/HTTP/gRPC 把进程隔离；
- CLI + JSON/Protobuf/文件交换；
- 宿主内嵌解释器执行脚本。

边界设计要明确所有权、线程、编码、错误、取消和版本。高频小调用应合并为批量，避免序列化/互操作成为瓶颈。

### 错误转换

C++ 异常、C# 异常和 Python 异常不应未经转换跨 ABI/进程边界。

在边界捕获并转成稳定结果：

- Status/错误码；
- 简短用户消息；
- 详细栈/Native 错误；
- 操作/资产ID；
- 可重试与否。

不要用异常表示普通验证 Failure，也不要吞掉异常后返回空数据，让下游继续生成错误资产。

### 配置与路径

使用结构化配置和 `Path` API，不手工拼接分隔符。区分：

- 项目相对资产路径；
- 本机绝对路径；
- URI/Depot Path；
- Case-sensitive 规范路径；
- 显示路径。

Windows 开发环境可能掩盖大小写错误，Linux CI/目标平台会失败。路径规范化不等于全部转小写，权威大小写应来自资产数据库或版本库。

## 批量调用契约

这是接口伪代码，长度、编码与版本先校验，返回状态和可解释错误。缓冲由调用者提供或由配套释放函数管理。

```text
request = {version, operationId, itemCount, encodedItems}
result = ExecuteBatch(request)
validate result.version, count and status
release result using the matching owner API
```

## 字节与缓冲所有权

一个可跨模块的字符串接口可表示为UTF-8字节指针和字节长度。长度计字节，不能把中文字符个数当缓冲大小；嵌入零字节是否允许也写入契约。接收侧在调用结束前复制需要长期保存的数据，或明确取得独占所有权。

调用方提供输出缓冲时，接口返回实际所需字节数和状态：容量不足只报告所需大小，调用方扩容后重试。若结果会变化，两次调用可能得到不同长度，因此接口应固定请求对应的结果版本，或允许重复扩容但设上限。由被调用方分配时，则配套导出同模块的释放函数。

异步接口另带请求ID与完成回调。取消只改变请求状态，回调对象和缓冲活到最终完成通知；卸载插件前先停止新请求，等待完成，再释放回调与模块。ABI稳定解决二进制调用，不能替代这份寿命约定。

## 验证方法

测试零长度、非法编码、超时、取消和版本冲突。异常在语言边界转换成稳定错误，不把C++异常穿过不兼容ABI。小调用合批后比较序列化与实际处理成本。


## 实现与证据

正文描述C ABI与进程协议的接口契约，未编译双语言绑定。验证应覆盖UTF-8多字节、容量不足、取消和模块卸载，而不只检查链接成功。
