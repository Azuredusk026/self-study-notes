# 操作系统、进程与并发基础

操作系统负责隔离程序、调度 CPU、管理虚拟内存、文件、设备和权限。游戏引擎看到的线程、内存页、文件句柄和网络 Socket，最终都通过系统调用落到这些机制上。

## 用户态、内核态与系统调用

普通代码运行在 User Mode，不能直接修改页表、操作设备或访问其他进程内存。需要文件、网络、线程和虚拟内存服务时，通过 System Call 进入 Kernel Mode。内核验证参数和权限，执行操作后返回用户态。

一次系统调用不等于一定发生线程切换，但进入内核、检查参数和处理设备会产生开销。高频小 IO、频繁创建线程和反复申请小块虚拟内存应通过批处理、缓存和用户态分配器减少系统调用次数。

Handle/File Descriptor 是进程访问内核对象的间接标识。它需要明确关闭，复制和跨进程继承也受权限控制。句柄泄漏会逐渐耗尽进程或系统资源，不能只用普通堆内存分析工具定位。

## 进程与线程

Process 拥有独立虚拟地址空间、Handle Table、安全上下文和一组线程。进程隔离让一个工具崩溃时不直接破坏另一个进程的内存，但进程间传递数据需要 IPC 和序列化。

Thread 是 CPU 调度的基本执行单元。一个进程内线程共享代码、Heap、全局数据和多数 Handle，每个线程拥有自己的 Register、Stack、Thread-local Storage 和调度状态。共享地址空间让通信便宜，也使数据竞争成为主要风险。

Coroutine、Fiber 和语言级 Task 是用户态调度抽象。它们可以在等待时主动让出执行权，但最终仍运行在一个或多个操作系统线程上。异步函数没有自动获得并行能力，CPU 密集任务只有被调度到其他可运行线程才可能并行。

## 调度与上下文切换

Scheduler 根据线程状态、优先级、时间片和 CPU 亲和性选择运行者。线程可能处于 Running、Ready、Blocked 或 Sleeping 等状态。等待 Mutex、IO、Event 时进入阻塞，CPU 可以运行其他线程。

Context Switch 需要保存当前线程 Register 和执行位置，恢复另一个线程，并可能扰动 Cache、TLB 和分支预测。切换成本与平台和工作集有关，不能只用固定纳秒数描述。

线程数超过硬件并发度并不一定更快。大量短任务适合复用线程池，由 Job System 控制粒度和依赖。实时线程可以提高优先级，但必须避免锁、分配和不可控 IO，否则高优先级阻塞会影响整个系统。

## 虚拟内存、页表与 TLB

每个进程看到连续的 Virtual Address Space。Page Table 把 Virtual Page 映射到 Physical Page，并记录读写执行权限。不同进程可以把同一物理页映射到不同地址，用于共享库、共享内存和 Copy-on-write。

TLB 缓存最近使用的地址翻译。工作集跨越大量 Page 或访问模式随机时，TLB Miss 增加，硬件需要查询多级页表。Huge Page 可以减少页表层级和 TLB 压力，但分配、碎片和平台权限更复杂。

访问尚未建立有效映射的页面会触发 Page Fault。Minor Fault 可能只需建立已有物理页映射；Major Fault 可能要从磁盘读取，延迟高得多。首次触碰新提交内存、内存映射文件和换页都可能产生 Page Fault。

Reserve 通常只占用地址范围，Commit 才承诺可用存储，实际物理页还可能在首次访问时分配。引擎分配器可以先申请大块虚拟地址，再按 Page 提交和回收，减少频繁进入内核。

## Stack、Heap 与内存映射

线程 Stack 保存调用帧、局部变量和返回信息，容量有限，并按 Page 逐步增长。深递归、大型局部数组和无限调用链会造成 Stack Overflow。

语言运行库的 Heap Allocator 在操作系统提供的大块 Virtual Memory 上管理小对象。`new`/`malloc` 不一定每次直接调用系统；分配器会维护 Size Class、Free List、Arena 或 Thread Cache。多线程高频分配还要处理锁竞争和跨线程释放。

Memory-mapped File 把文件区间映射到虚拟地址。读取由 Page Fault 按需触发，操作系统 Page Cache 可以与普通文件 IO 共享数据。它适合随机访问大型文件，但仍要处理映射生命周期、文件截断、错误页和显式刷盘语义。

## 锁与等待原语

Mutex 提供互斥所有权，未获得锁的线程通常进入等待。Recursive Mutex 允许同一线程重复获取，但容易掩盖职责和调用层级问题。Read-write Lock 允许多个 Reader 或一个 Writer，只有读多写少且临界区足够大时才可能受益。

Semaphore 保存可用许可数量，适合限制并发资源或通知多个工作项。Condition Variable 让线程在条件不满足时睡眠，并在状态变化后被唤醒；等待必须放在循环中重新检查 Predicate，因为可能发生 Spurious Wakeup 或条件被其他线程先消费。

Spin Lock 在短时间内循环尝试，不进入睡眠。它只适合临界区极短、锁持有者很快会运行的场景。锁持有期间做 IO、等待另一个锁或被操作系统抢占，会让 Spin 浪费 CPU。

## 原子操作与内存顺序

Atomic Read-modify-write 保证多个线程对同一原子对象的更新不会丢失。原子性不自动保证一组普通内存操作的整体事务，也不解决对象生命周期。

编译器和 CPU 可以在不改变单线程结果的前提下重排内存访问。Acquire/Release 建立跨线程的 Happens-before 关系：发布线程先写数据，再用 Release 发布标志；消费线程用 Acquire 读到标志后，才能可靠观察此前的数据写入。Sequential Consistency 提供更直观的全局顺序，约束通常更强。

Lock-free 表示系统整体能持续推进，不代表每个线程都不会饥饿，也不代表一定比 Mutex 快。无锁结构还要处理 ABA、内存回收、伪共享和复杂验证。

## 数据竞争与死锁

两个线程并发访问同一内存位置，其中至少一个写入，且没有同步关系时形成 Data Race。C++ 中这通常是未定义行为。只在调试时“看起来结果正确”不能证明线程安全。

经典死锁需要四个条件同时成立：互斥、持有并等待、不可抢占、循环等待。常见预防方式是统一锁顺序、缩小锁范围、一次获取整组锁、避免持锁调用未知代码，并在调试构建记录 Lock Graph。

Livelock 中线程持续响应对方却没有实际进展；Starvation 表示某个线程长期得不到资源。公平锁、退避和任务优先级可以缓解，但也会改变吞吐和延迟。

## 进程间通信

常见 IPC 包括 Pipe、Socket、Shared Memory、Named Pipe、Message Queue 和子进程标准输入输出。

- Pipe 和 Socket 边界清楚，容易隔离崩溃，代价是复制、协议和序列化；
- Shared Memory 适合大数据交换，但同步、所有权和版本必须由双方约定；
- 启动 CLI 子进程适合 DCC 与资产工具，输入输出应有 Schema、退出码、超时和取消；
- RPC 建立在传输和序列化之上，仍要处理超时、重复与进程失效。

跨进程不能传普通指针。即使两个进程映射同一物理内存，虚拟地址也可能不同，应使用 Offset、Index 或稳定 ID。

## 文件系统与 IO

文件系统按路径解析目录项，再通过文件元数据定位数据块。Page Cache 会缓存最近读写的数据，因此一次读很快可能只是命中缓存。性能测试要区分冷缓存、热缓存、顺序读、随机读和存储设备队列深度。

Buffered IO 经过系统缓存，Direct IO 绕过部分缓存并要求更严格的对齐和块大小。Asynchronous IO 让线程提交请求后继续工作，完成事件由系统通知；它适合资产流送，但仍需要请求合并、优先级、取消和目标 Buffer 生命周期管理。

原子替换常先写临时文件、Flush 并关闭，再 Rename/Replace 正式路径。`Flush` 的语义受系统和设备缓存影响，需要持久化保证时应使用平台明确提供的同步接口。

## 时间与计时器

Wall Clock 表示日历时间，可能因系统校时、时区或用户修改发生跳变。测量持续时间和驱动游戏循环应使用 Monotonic Clock。

Sleep 只保证线程在指定时间前通常不会恢复，不保证精确唤醒。调度粒度、系统负载和省电策略都会产生误差。固定 Tick 应使用累计器和真实单调时间计算，不要依赖每次 Sleep 恰好一个帧间隔。

## 调试与验证

- 用线程时间线区分 Running、Ready 和 Blocked，定位锁等待与过度切换。
- 记录 Page Fault、Working Set、Commit Size、Handle Count 和 IO 延迟。
- 使用 Thread Sanitizer 或平台竞态工具检查数据竞争。
- 对锁顺序、取消、进程退出和异常路径做压力测试。
- 对文件流送分别测冷缓存、热缓存和限速设备。
- 用 Monotonic Clock 测时，并记录线程与 CPU Core。

### 条件变量的谓词等待

生产者修改队列和停止标记时持有同一互斥锁，消费者用谓词处理虚假唤醒：

```cpp
std::unique_lock lock(queueMutex);
queueReady.wait(lock, [&] { return stopping || !jobs.empty(); });

if (stopping && jobs.empty())
    return;

Job job = std::move(jobs.front());
jobs.pop_front();
lock.unlock();
job.Run();
```

等待会原子地释放锁并休眠，唤醒后重新获得锁再检查谓词。任务执行放在解锁之后，避免一个长任务阻塞所有生产者和消费者。若停止标记在另一把锁下修改，可能丢失唤醒或形成数据竞争；压力测试应覆盖空队列停止、多生产者和连续虚假通知。
