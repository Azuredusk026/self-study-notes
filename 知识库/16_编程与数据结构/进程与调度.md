# 进程与调度

后台任务可以不阻塞界面，却未必同时占用多个核心。进程提供地址与故障隔离，线程由OS调度，协程与Task再在其上组织工作。系统调用、等待和切换各自影响延迟。

## 用户态、内核态与系统调用

普通代码运行在 User Mode，不能直接修改页表、操作设备或访问其他进程内存。需要文件、网络、线程和虚拟内存服务时，通过 System Call 进入 Kernel Mode。内核验证参数和权限，执行操作后返回用户态。

一次系统调用不等于一定发生线程切换，但进入内核、检查参数和处理设备会产生开销。高频小 IO、频繁创建线程和反复申请小块虚拟内存应通过批处理、缓存和用户态分配器减少系统调用次数。

Handle/File Descriptor 是进程访问内核对象的间接标识。它需要明确关闭，复制和跨进程继承也受权限控制。句柄泄漏会逐渐耗尽进程或系统资源，不能只用普通堆内存分析工具定位。

## 进程与线程

Process 拥有独立虚拟地址空间、Handle Table、安全上下文和一组线程。进程隔离让一个工具崩溃时不直接破坏另一个进程的内存，但进程间传递数据需要 IPC 和序列化。

Thread 是 CPU 调度的基本执行单元。一个进程内线程共享代码、Heap、全局数据和多数 Handle，每个线程拥有自己的 Register、Stack、Thread-local Storage 和调度状态。共享地址空间让通信便宜，也使数据竞争成为主要风险。

Coroutine、Fiber 和语言级 Task 是用户态调度抽象。它们可以在等待时主动让出执行权，但最终仍运行在一个或多个操作系统线程上。异步函数没有自动获得并行能力，CPU 密集任务只有被调度到其他可运行线程才可能并行。

## 调度与上下文切换

Scheduler 根据线程状态、优先级、时间片和 CPU 亲和性选择运行者。线程可能处于 Running、Ready、Blocked 或 Sleeping 等状态。等待 Mutex、IO、Event 时进入阻塞，CPU 可以运行其他线程。

Context Switch 需要保存当前线程 Register 和执行位置，恢复另一个线程，并可能扰动 Cache、TLB 和分支预测。切换成本与平台和工作集有关，不能只用固定纳秒数描述。

线程数超过硬件并发度并不一定更快。大量短任务适合复用线程池，由 Job System 控制粒度和依赖。实时线程可以提高优先级，但必须避免锁、分配和不可控 IO，否则高优先级阻塞会影响整个系统。

## 进程间通信

常见 IPC 包括 Pipe、Socket、Shared Memory、Named Pipe、Message Queue 和子进程标准输入输出。

- Pipe 和 Socket 边界清楚，容易隔离崩溃，代价是复制、协议和序列化；
- Shared Memory 适合大数据交换，但同步、所有权和版本必须由双方约定；
- 启动 CLI 子进程适合 DCC 与资产工具，输入输出应有 Schema、退出码、超时和取消；
- RPC 建立在传输和序列化之上，仍要处理超时、重复与进程失效。

跨进程不能传普通指针。即使两个进程映射同一物理内存，虚拟地址也可能不同，应使用 Offset、Index 或稳定 ID。

## 时间与计时器

Wall Clock 表示日历时间，可能因系统校时、时区或用户修改发生跳变。测量持续时间和驱动游戏循环应使用 Monotonic Clock。

Sleep 只保证线程在指定时间前通常不会恢复，不保证精确唤醒。调度粒度、系统负载和省电策略都会产生误差。固定 Tick 应使用累计器和真实单调时间计算，不要依赖每次 Sleep 恰好一个帧间隔。

## 工具进程协议

伪代码输入结构化任务，标准输出返回结构化结果，退出码与超时独立记录。

```text

wait until completion or deadline

```

## 验证方法

记录Running、Ready与Blocked时间，模拟子进程退出、超时及巨大输出。传输使用偏移、ID或序列化，进程间不传普通指针。测时使用单调时钟。
