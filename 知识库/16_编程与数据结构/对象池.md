# 对象池

弹丸反复创建销毁，可以改成租用已有实例，但上一轮速度、任务和事件必须先清理。对象池管理的是取得与释放契约，槽位复用之前还要确认旧使用者退出。

## 对象复用

对象池复用已经创建的对象，减少反复 Instantiate/Destroy、注册、分配和 GC。适合生命周期短、频繁出现、结构相同的对象，例如弹丸、命中特效和部分 UI Item。

典型状态：

```text
Inactive -> Acquire -> Active -> Release -> Inactive
```

对象池不应只调用 `SetActive`。需要定义重置契约：

- 变换、速度、动画、粒子；
- 事件订阅、协程/Task；
- MaterialPropertyBlock 和临时引用；
- 物理状态、拖尾历史；
- 玩法所有者、计时器、伤害状态。

漏重置会让上一任对象状态污染下一次使用。

## 容量与驻留成本

- 预热增加加载时间和初始内存；
- 过大池长期保留 Native/Managed/GPU 资源；
- Active/Inactive 切换仍可能触发生命周期和子系统成本；
- 对象结构/Prefab 更新后池中旧实例可能不兼容；
- 对象池隐藏真实所有权，产生未归还或重复归还；
- 低频对象池化只增加复杂度。

容量策略可设置初始容量、上限、溢出：超过上限时拒绝、临时创建或回收最旧对象。选择要符合玩法，不应静默抢走仍在使用的对象。

## 租用与生命周期回调

Unity对脚本实例只调用一次 `Awake`。实例化后对象在层级中处于激活状态时会触发它；实例化非激活对象时，调用可延后到首次激活。此后的启用和禁用按组件及对象状态触发 `OnEnable/OnDisable`，不会重复执行 `Awake`。若业务把每次使用初始化放在 `Awake`，对象池后就会出错。

建议定义显式 `OnAcquire(context)` / `OnRelease()`，让每次租用状态可测试。引擎生命周期只负责底层接入。

## 槽位复用条件

槽位回到空闲表以后，新对象可能马上占用同一地址。若旧任务仍保存裸指针，它看到的就会是另一个对象。带 generation 的句柄能拒绝陈旧引用，完成值与任务依赖则保证实际使用已经结束；对象池同时需要这两种约束，清空字段只是最后一步。

## 租用状态机

伪代码以generation区分每次租用，借用者同时验证句柄代数。

```text
Acquire: pop free slot; increment generation; Reset(context); mark Active
Release: reject stale generation or duplicate release
         cancel callbacks; wait owned users; reset; mark Free
```

## 释放中的任务竞争

一次租用可用 `(slot,generation)` 标识。假设槽位7的第12代弹丸结束，槽位随后发给第13代；旧命中回调带第12代句柄，查询时发现代数不同，便拒绝修改新弹丸。但代数检查必须与实际访问处于同一保护范围，否则检查后槽位仍可能被并发回收。

释放流程先把对象标记为停止接收任务，再取消定时器与订阅，等待已开始的使用者结束，清除运动与表现状态，最后放回空闲表。对象只是不可见时仍可能有GPU或任务访问，因此“禁用”不等于可以覆盖数据。

容量可按最大同时活跃数量加余量估计，预热只减少首次创建成本。记录活跃峰值、空闲驻留和溢出次数；若对象大部分时间闲置且保留大量贴图引用，池会把临时峰值变成长驻内存。对象池的收益由完整租还周期测量，不能只比较一次new与一次取槽。

## 验证方法

测试重复释放、陈旧句柄、容量耗尽与场景切换，观察事件和轨迹是否残留。比较预热、稳态分配和长期驻留，只有高频重复工作才可能抵消池管理成本。
