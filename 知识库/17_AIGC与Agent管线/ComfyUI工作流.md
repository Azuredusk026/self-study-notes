# ComfyUI工作流

节点图能连通，只证明接口类型可接，不能证明模型和潜变量语义匹配。ComfyUI工作流把模型、节点版本、参数与输入一起固定，再由队列保存执行和产物状态。失败恢复依赖这份记录。

## 可复现执行

### 基础图

典型文生图：

```text
Checkpoint Loader
  -> Model -----------------> Sampler
  -> Text Encoder -> Positive/Negative Condition -> Sampler
  -> VAE -----------------------------------------> Decode

Empty Latent -> Sampler -> Denoised Latent -> VAE Decode -> Save
```

检查点加载器可能同时返回模型、文本编码器和 VAE。工作流也可显式替换 VAE、加载多个 LoRA 或使用不同文本编码器。

线连通只表示类型兼容，不表示语义正确。错误 VAE、控制模型、潜变量格式或分辨率仍可能产出图像。

### 工作流与依赖

正式工作流至少记录：

- 工作流 ID/版本；
- ComfyUI提交或发布版本；
- 自定义节点包与提交版本；
- 模型/VAE/LoRA/ControlNet 文件哈希；
- 默认参数与允许覆盖范围；
- 输入/输出结构约束；
- 示例输入和基准输出；
- GPU/精度与已知兼容性；
- 负责人、审核与变更记录。

只保存截图无法重建节点、控件和连接。只保存 JSON 但不保存依赖版本，也可能因节点升级改变结果。

### 模型与路径

不要让工作流依赖某台电脑的绝对路径。使用受控模型登记库、逻辑 ID 和配置映射到本地缓存。

启动时校验需要的模型哈希。名称相同但内容不同的文件不能视为同一依赖。

模型下载与许可应由独立步骤处理，生成工作进程只读取批准登记库。不要让自定义节点在执行中任意联网下载未知文件。

### 参数接口

将常调参数集中为输入节点或 API 结构约束：

- 提示词/负面提示词；
- 种子；
- 宽度、高度与批量大小；
- 步数/CFG/采样器/调度器；
- 去噪强度；
- 控制/IP-Adapter/LoRA 权重；
- 遮罩、参考图与输出格式。

节点内部散落的无说明常量很难审查。参数要有单位、范围和默认值，非法组合在排队前拒绝。

### 队列与批处理

ComfyUI Server 可通过 API 提交工作流和读取历史/输出。生产调度还需要外围任务状态：

```text
Pending -> Validating -> Queued -> Running
        -> Succeeded / Failed / Cancelled
```

任务记录工作流哈希、输入哈希、工作进程、GPU、开始结束时间和输出。相同任务是否复用缓存由管线明确决定，不能只依赖节点内部缓存。

批量应限制并发、VRAM 和磁盘。OOM 后无限重试会持续挤占工作进程；可以降低批量/分辨率或转到更大 GPU，但必须记录已改变参数。

### 自定义节点风险

自定义节点本质是可执行代码。风险包括：

- 任意文件/网络访问；
- 依赖冲突和安装脚本；
- 更新后 API/结果变化；
- 无人维护或许可不清；
- Pickle/模型加载安全；
- 隐式修改全局环境。

生产环境使用白名单、固定提交版本、隔离环境和代码审查。升级先跑基准工作流，不在工作日直接拉最新版本。

### 输出与元数据

输出文件名应来自任务/资产ID，不以提示词直接拼接路径。提示词可能包含非法字符、隐私内容或过长文本。

伴随清单保存：

- 完整工作流/参数；
- 模型/节点哈希；
- 种子与输入文件哈希；
- 输出哈希、分辨率、颜色空间；
- 父任务与派生变体；
- 审核状态和后处理记录。

图片元数据可作为方便入口，但发布系统不应只依赖可能被编辑软件清除的嵌入字段。

## 失败恢复

- 保存每帧任务/条件/种子/模型/输出；
- 独立逐帧工作流按帧重试；含跨帧状态或联合去噪的工作流，按可恢复的片段或检查点重跑；
- OOM 可切工作进程或降安全参数，并标记变更；
- 输出写暂存，整段验证后发布；
- 自定义节点异常保留输入和栈；
- 关键帧人工批准后锁定，传播任务不得静默覆盖。

## 提交、完成与产物确认

自托管服务的 `/prompt` 接收API格式的执行图，校验成功后返回 `prompt_id` 和队列信息。编辑器保存的可视化工作流JSON还包含布局等信息，自动提交时确认导出的是API执行格式。节点ID作为键，输入引用由上游节点ID和输出槽连接，不能只按截图顺序重建。

```text
job = persist(workflowHash, inputHash, requestedParameters)
reply = POST /prompt with API graph
persist job -> reply.prompt_id
observe /ws and query /history/{prompt_id}
validate expected output nodes, files and hashes
mark job completed after output validation
```

这是自托管HTTP接口流程，认证、地址和请求库由部署补齐。收到提交成功只说明已排队，WebSocket断开也不说明执行失败；恢复后用已保存的prompt_id查历史。提交响应丢失而未取得ID时，不能盲目认定任务未执行；外围调度器需做操作登记与产物对账，避免重复生成和重复发布。

取消请求同样要等待执行终态，再清理该任务临时文件。历史列表有输出记录以后，还要核对文件存在、尺寸与哈希；缺失任一预期输出的任务保持失败或待修复，不能以“部分图片可打开”作为整组完成。

## 验证方法

固定模型和节点hash跑基准工作流，比较输出与环境。测试缺模型、OOM、部分输出和重试，参数降级形成新的变体。视频一致性属于独立问题，单帧种子不保证跨帧身份。


## 实现与证据

2026-10-22核读自托管路由文档的/prompt、/history与/ws；没有连接本机ComfyUI实例或运行生成任务。具体节点与模型兼容性由锁定提交的工作流验证。
