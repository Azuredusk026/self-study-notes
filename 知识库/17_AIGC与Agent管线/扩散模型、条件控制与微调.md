# 扩散模型、条件控制与微调

图像扩散工作流可以理解为：从噪声状态开始，在文本、结构图或参考图条件下逐步预测更干净的表示，最后解码成图像。模型、条件、Sampler 和数据版本共同决定结果。

## Forward Diffusion

训练时逐步向真实样本 $x_0$ 加高斯噪声。常见闭式形式：

$$
x_t=\sqrt{\bar\alpha_t}x_0+\sqrt{1-\bar\alpha_t}\epsilon,
\qquad \epsilon\sim\mathcal N(0,I)
$$

$\bar\alpha_t$ 由 Noise Schedule 决定。$t$ 越大，原始信号越弱，最终接近纯噪声。

模型学习在给定 $x_t$、时间 $t$ 和条件 $c$ 时预测 Noise、Clean Sample 或 Velocity。具体 Parameterization 取决于模型训练，Sampler 必须匹配。

## Reverse Process

生成从随机噪声 $x_T$ 开始，反复调用去噪网络估计下一状态，直到得到 $x_0$。

这不是简单“每一步减一点噪声”。Sampler/Scheduler 根据模型预测、Noise Schedule 和随机项离散求解对应 SDE/ODE。不同算法在步数、随机性、稳定性和细节上有取舍。

同一 Prompt 只改 Sampler 或 Step，路径就会变化。比较参数时应固定 Model、VAE、Condition、Seed、Resolution 和其他设置。

## Latent Diffusion

像素空间高分辨率去噪很贵。Latent Diffusion 使用 VAE：

```text
Image -> VAE Encoder -> Latent
Latent -> Diffusion Denoise
Latent -> VAE Decoder -> Image
```

Latent 是压缩特征，不是普通 RGBA Texture。它的通道和数值语义由 VAE 训练决定。

更换 VAE 可能改变颜色、对比、细节和伪影。使用与基础模型不兼容的 VAE，结果即使能解码也可能异常。

## U-Net 与其他去噪网络

经典 Stable Diffusion 使用 U-Net：下采样提取多尺度语义，中间处理全局特征，上采样恢复空间细节，并通过 Skip Connection 保留局部信息。

Text/Image Condition 常通过 Cross-attention 注入。Time Embedding 告诉网络当前噪声级别。

现代模型也可能使用 Diffusion Transformer 等架构。U-Net 是常见实现，不是扩散模型定义本身。工作流节点和 LoRA 必须匹配具体架构。

## 文本条件与 CLIP

Text Encoder 把 Token 序列编码为 Embedding。CLIP 系列常用于文本-图像语义对齐，但不同模型使用的 Encoder、Tokenizer 和最大长度可能不同。

Prompt 不会按自然语言逐条执行。词是否有效取决于训练语料、Tokenizer、位置、权重和条件注入方式。

长 Prompt 可能被截断或分段。堆叠同义词不一定加强控制，反而会稀释关键条件。先用结构化短 Prompt 建基线，再逐项增加条件更容易定位影响。

## Classifier-Free Guidance

Classifier-Free Guidance（CFG）组合有条件与无条件预测：

$$
\epsilon_{cfg}=\epsilon_{uncond}+s(\epsilon_{cond}-\epsilon_{uncond})
$$

$s$ 是 CFG Scale。值升高会加强条件方向，但不是质量滑杆。过高可能产生过饱和、硬边、纹理破碎和构图僵化。

Negative Prompt 通常进入 Unconditional/Negative Condition。它改变去噪方向，不能保证逻辑上的“禁止”。过长负面词也可能压制正常细节。

合适 CFG 与模型、Sampler、Step、Prompt 和 LoRA 共同相关。

## Seed 与可复现性

Seed 初始化随机噪声。固定 Seed 有助于比较单变量，但不保证跨环境逐像素相同：

- Model/VAE/LoRA Hash；
- Sampler/Scheduler 实现；
- Framework/CUDA/Kernel；
- 精度、优化和硬件；
- Custom Node Version；
- Batch 顺序。

生产记录应保存完整 Workflow 和依赖 Hash，不只保存 Seed。

## Text-to-Image、Img2Img 与 Inpainting

Text-to-Image 从纯噪声生成，构图自由度最大。

Img2Img 先把输入图编码为 Latent，在相应时间点加噪后继续去噪。Denoise Strength 越高，原图结构保留通常越少，但映射并非所有 Sampler 都完全一致。

Inpainting 用 Mask 指定重绘区域。质量取决于：

- Mask 语义与是否反转；
- Feather/Padding；
- 重绘区域是否包含足够上下文；
- 原图/Latent Noise；
- Denoise Strength；
- 模型是否专门训练 Inpaint。

Mask 太贴边会让新旧内容无法融合；范围过大则改变不应修改的区域。

## ControlNet

ControlNet 为预训练扩散模型增加可训练控制分支，把 Edge、Depth、Normal、Pose、Segmentation 等结构信号注入去噪网络。

常见工作流：

```text
Reference Image
 -> Preprocessor
 -> Control Map
 -> Matching ControlNet
 -> Denoising Network
```

Preprocessor 输出必须与 ControlNet 训练类型匹配。Canny Map 接到 Depth Control 模型，节点仍可能运行，但条件语义错误。

控制参数包括 Weight、Start/End Step 和 Resolution。强度过高会把预处理噪声和错误结构一起锁死；过低则约束不足。

Normal/Depth 预处理本身可能有尺度、坐标和遮挡错误。ControlNet 只遵循输入，不会自动修复错误几何。

## IP-Adapter

IP-Adapter 把参考图编码为 Image Embedding，通过额外 Attention/Condition 影响生成。它适合传递角色、对象、构图或风格语义。

与 ControlNet 的典型分工：

- ControlNet 偏空间结构；
- IP-Adapter 偏参考图语义/外观；
- Text Prompt 提供可编辑意图；
- Mask 决定影响区域。

多种条件叠加会竞争。应逐一启用并记录 Weight，不要直接把 Text、多个 ControlNet、IP-Adapter 和 LoRA 全开后凭感觉调参。

参考图来源和使用授权必须进入记录。技术上可提取特征不等于项目有权使用。

## LoRA

Low-Rank Adaptation（LoRA）把权重增量近似为低秩分解：

$$
W'=W+\lambda BA
$$

$A/B$ 的秩远小于原矩阵维度，训练和文件规模较小。基础模型权重保持不变，生成时加载增量并设置强度 $\lambda$。

LoRA 可学习角色、服装、材质、物体或风格，但结果受数据和 Caption 强烈影响。它不能弥补来源混乱、构图单一和错误标注。

## LoRA 数据

先定义目标概念和非目标因素。数据应：

- 有明确授权和来源；
- 覆盖希望泛化的视角、光照和背景；
- 避免所有图片同一姿势/构图；
- 去除水印、重复、低质量和错误样本；
- 记录 Crop/Resize/Caption 处理；
- 划分训练与固定验证集。

若所有角色图都在白背景，LoRA 可能把白背景当概念一部分。若 Caption 没区分服装和角色，特征也会纠缠。

## Caption 与 Tag

Caption 描述图像内容与可变因素；Trigger Word 指向目标概念。是否标注某个特征取决于希望模型把它当可控变量还是概念固有部分。

自动 Caption 可生成初稿，但要人工检查身份、颜色、数量和构图。错误 Caption 会稳定地教给模型错误关系。

Tag 顺序、Shuffle、Dropout 和自然语言/标签风格与训练脚本相关，应锁定配置并做对照实验。

## 训练与过拟合

关键变量：Base Model、Network Rank/Alpha、Learning Rate、Batch、Optimizer、Resolution/Bucket、Epoch/Step、Text Encoder 是否训练。

过拟合表现：

- 构图和背景重复；
- Prompt 难以改变姿势/服装；
- 训练图细节被直接复现；
- 高权重才像，降低权重就失去概念；
- 与其他 LoRA/Control 组合崩坏。

不能只看训练 Loss。用固定 Prompt Matrix 比较不同 Checkpoint 和 Weight，检查相似度、可控性、泛化和副作用。

## 资产化

模型与适配器应像资产管理：

- Model ID、文件 Hash、License/Source；
- Compatible Base/Architecture；
- Training Dataset Manifest；
- Config、Script/Library Version；
- Trigger/Recommended Weight；
- Validation Grid；
- Known Failure/Forbidden Use；
- Owner、Review、Retire State。

来源不明的 Model/LoRA 不进入正式生产。文件名写“final_v2”无法替代版本和血缘。

## 推理精度与显存

显存主要由 Model Weight、Activation/Attention、Latent、Control 分支和 Batch 占用。提高分辨率会放大空间特征，Attention 的成本还可能增长更快。

常见手段：

- FP16/BF16 权重与计算；
- Attention Slicing/Tiling；
- VAE Tiled Encode/Decode；
- Model/Layer CPU Offload；
- Quantization；
- 降低 Batch 或分段处理；
- 缓存重复 Text/Image Encoding。

这些方法可能改变速度、精度和确定性。Quantization/低精度对颜色、细节或特定硬件 Kernel 的影响要用同一验证集检查。CPU Offload 节省 VRAM，却增加 PCIe 传输和延迟。

OOM 不应自动把分辨率不断降低后仍标记为同一结果。任何参数或精度降级都要进入 Job Manifest，并使用新的 Variation ID。

## 基线评估

模型评估不能只挑最好看的图。建立 Prompt Matrix，覆盖：

- 角色/物体身份；
- 正侧背与远近景；
- 不同光照、背景、材质；
- 手部、文字、重复结构等高风险内容；
- 与 ControlNet/IP-Adapter/多个 LoRA 的组合；
- 项目禁止内容和来源风险。

保存全部 Seed，而不是只保存成功样本。统计失败类型、人工选择率和精修时间，才能判断新 Model/LoRA 是否真的提高生产效率。

自动指标可衡量图文、参考相似度或结构误差，但不能独立决定资产质量。最终评估同时看 Prompt 可控性、跨 Seed 稳定性、与管线兼容、许可和人工返工。

## 数据与隐私

训练、参考图和 Prompt 可能包含未公开角色、项目截图或个人数据。外部 API 前应经过数据分类和批准，明确服务是否保存输入、用于训练、部署区域和删除策略。

日志与样例图同样需要访问控制。为了复现保存完整 Prompt，不代表它可以进入公开报告。

## 验证方法

- 固定 Seed 做 Prompt/CFG/Step/Sampler 单变量网格。
- 输出 Control Map，检查坐标、范围和预处理错误。
- 分别关闭 ControlNet、IP-Adapter、LoRA，确认每个条件贡献。
- 用未见视角、背景、材质和组合 Prompt 测 LoRA 泛化。
- 检查 VAE 色彩、手部/文字/结构伪影和高分辨率放大。
- 保存 Workflow JSON、Model Hash、输入、输出和环境清单。
