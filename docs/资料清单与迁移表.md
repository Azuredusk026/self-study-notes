# 资料清单与迁移表说明

完整迁移台账保存在 `docs/manifests/source-inventory.tsv`。TSV 适合脚本更新，也可以直接用表格软件查看。

## 字段

| 字段 | 含义 |
|---|---|
| `source_path` | 相对 Vault 根目录的来源路径 |
| `file_type` | 文件扩展名 |
| `bytes` | 文件大小 |
| `sha256` | 内容哈希，用于判断完全重复和追踪来源变化 |
| `title` | Markdown/TXT 中识别到的首个 H1 |
| `target_domain` | 初步归属的正式知识领域 |
| `migration_status` | 当前处理状态 |
| `target_article` | 实际吸收内容的正式文章，迁移时填写 |
| `notes` | 冲突、取舍和来源关系 |

## 终态定义

| 状态 | 含义 |
|---|---|
| `已迁移` | 有价值内容已经去重并进入正式文章 |
| `已筛选迁移` | 只吸收了与 TA 直接相关的部分，其余仍留在来源中 |
| `已拆分迁移` | 多主题来源已经按主题拆分吸收 |
| `重复来源已覆盖` | 原始转录或重复稿已经由整理稿和正式文章覆盖 |
| `保留归档` | 来源有保存价值，但不进入正式 TA 导航 |
| `保留治理` | Git、规则等仍在使用的治理文件 |
| `已退役` | 旧规则、模板、索引或脚本已经删除，Git 和台账可恢复 |
| `排除` | 没有有效内容，不纳入知识库 |

## 使用规则

新增或更新来源时：

1. 阅读来源及其配套原稿、课件或整理稿。
2. 将有价值内容融入正式主题，而不是原样复制。
3. 在 `target_article` 中记录实际文章路径。
4. 使用上表中的终态记录处理结果。
5. 在 `notes` 中记录重要取舍、冲突和待核验点。

来源只有在状态已经终结后才能删除或移动。运行 `scripts/validate-vault.ps1` 可以检查非终态和已经退役但仍存在的路径。
