# 资料清单与迁移表说明

完整迁移台账保存在 `docs/manifests/source-inventory.tsv`。TSV 适合脚本更新，也可以直接用表格软件查看。

## 字段

| 字段 | 含义 |
|---|---|
| `source_path` | 相对 Vault 根目录的来源路径 |
| `file_type` | 文件扩展名 |
| `bytes` | 文件大小 |
| `sha256` | 内容哈希，用于判断完全重复和追踪来源变化 |
| `title` | Markdown/TXT 中识别到的首个 H1 |
| `target_domain` | 初步归属的正式知识领域 |
| `migration_status` | 当前处理状态 |
| `target_article` | 实际吸收内容的正式文章，迁移时填写 |
| `notes` | 冲突、取舍和来源关系 |

## 状态定义

| 状态 | 含义 |
|---|---|
| `待迁移` | 主题明确，需要吸收到正式文章 |
| `待拆分迁移` | 一个来源覆盖多个正式主题，需要按章节拆分 |
| `待筛选` | 只有部分内容与 TA 有关，需要人工判断 |
| `重复来源，待核对` | 通常是原始转录，需要与整理稿交叉核验 |
| `仅提取 TA 相关内容` | 主体属于相邻专业，只迁移直接相关段落 |
| `仅归档` | 有保留价值，但不进入 TA 正式导航 |
| `待退役` | 旧索引、模板或流程文件，完成迁移后删除 |
| `待删除` | 当前没有有效内容，最终审核时确认删除 |
| `保留` | 项目治理或仍在使用的文件 |

## 使用规则

迁移某个来源时：

1. 阅读来源及其配套原稿、课件或整理稿。
2. 将有价值内容融入正式主题，而不是原样复制。
3. 在 `target_article` 中记录实际文章路径。
4. 将状态更新为 `已迁移`、`已核对重复`、`已归档` 或 `已排除`。
5. 在 `notes` 中记录重要取舍、冲突和待核验点。

旧文件只有在状态已经终结后才能删除或移动。最终验收时不允许存在没有解释的 `待迁移`。
